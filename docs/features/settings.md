# Feature: Settings

- Status: `implemented`

## Problem

The host keeps one configuration for every Project: the providers it may call, the default execution new Threads start on, the turn limit, the reader's profile, the auto-archive policy and the credentials they name. The reader needs one place to edit it that does not depend on an open Project or Thread, that never loses a change, and in which other bundles can add the sections they own. A provider must also be configurable from the workspace window's `/projects` dashboard, without opening a second window.

## Decisions

- There is no Save button for the configuration. A valid change sends itself once typing settles, at once on a field blur, and before the window closes. A draft the window's own validation refuses is never sent; the window says why instead.
- Each section is a child route of `/settings`, at `/settings/<id>`. The bare `/settings` redirects to the last section that window showed, or to `/settings/providers` when it has shown none. The provider page is state of the page, not a route.
- `core.open-settings/v1` without a `path` focuses an open settings window and leaves it on its section; it opens a window only when none is open.
- A section's nav entry is a `settings-link` item of `settings.sections` with the props `{ label, path, icon?, description? }`; `icon` names one of a fixed set of icons the `settings` bundle draws: `user`, `sun-moon`, `server`, `zap`, `wrench`, `git-branch`, `key-round` and `messages-square`.
- The heading, its icon and the breadcrumb of the section on screen are those of the `settings.sections` link whose `path` is the current route, so a section another bundle adds is named by its own label and icon.
- A section another bundle draws edits the configuration through `settings.config/v1`, so it shares the window's one draft, its debounce, its flush and its save messages. `setDraft` writes at once, so two writes in a row compose; before the configuration has loaded, `draft()` is `undefined` and `setDraft` is ignored.
- The profile's name and time zone are never taken from the host's operating system, because the host can be remote: the window never fills them in, and the host's own time zone applies only while `profile.timezone` is absent.
- Settings offers Appearance only when the app answers `doric.appearance/v1`. The theme is the app's local preference, not part of the host configuration.
- `settings.models/v1` holds every rule the conversation footer's execution picker shows; the [`chat`](../../bundles/desktop/chat/README.md) bundle, which draws the picker, applies none of its own.
- The provider page names no provider kind. A field that a kind draws its own way is an item of `settings.provider.field`, drawn in the field's place.

## Current behavior and contracts

### The bundles

- The [`settings`](../../bundles/desktop/settings/README.md) bundle, a client-only desktop bundle, draws the settings window, its built-in sections, the provider page and the dashboard's Providers group. It provides `settings.config/v1` 1.1.0 and `settings.models/v1` 1.0.0, both client contracts, and requires `host-config/v1@^1.2.0`, `secrets/v1`, `models/v1` and `tools/v1` among others; `core.open-settings/v1` and `workspace.dashboard/v1` are optional ([manifest.json](../../bundles/desktop/settings/manifest.json)).
- The [`host-config`](../../bundles/foundation/host-config/README.md) bundle owns the configuration and serves `host-config/v1`: `current()` answers the configuration with its `revision` and `updatedAt`, and `replace(input)` validates a whole new configuration, builds its providers, and stores it only when all of that succeeds ([bundles/foundation/host-config/src/host/config/service.ts](../../bundles/foundation/host-config/src/host/config/service.ts)).
- The [`core`](../../bundles/foundation/core/README.md) bundle registers `core.open-settings/v1`, which opens the window ([bundles/foundation/core/src/desktop/commands.ts](../../bundles/foundation/core/src/desktop/commands.ts)).
- The window reaches every host contract through one adapter, which also checks each answer's shape ([src/client/api/settings-api.ts](../../bundles/desktop/settings/src/client/api/settings-api.ts)).

### Opening the window

- Two entries open the window, each a `<settings-entry-icon>` item that runs `core.open-settings/v1` with `defaultPath: '/settings'`: "Settings" in the [`account`](../../bundles/desktop/account/README.md) bundle's `account.menu`, and "All settings" in the [`workspace`](../../bundles/desktop/workspace/README.md) bundle's `workspace.dashboard.footer`. Without `account` or `workspace`, the matching entry is not drawn ([src/client/index.ts](../../bundles/desktop/settings/src/client/index.ts)).
- `core.open-settings/v1` takes `{ path?, defaultPath? }`. Without `path`, it focuses the open settings window, or opens one at `defaultPath`; with `path`, it focuses the window and navigates it there, or opens one there. With neither, and no window open, it fails with `invalid_input` ([bundles/foundation/core/src/desktop/commands.ts](../../bundles/foundation/core/src/desktop/commands.ts)).
- The command opens the window through `doric.windows/v1` under the key `settings`, so there is one settings window at a time. The desktop app creates it as a native `BrowserWindow` of its own ([bundles/foundation/core/src/desktop/commands.ts](../../bundles/foundation/core/src/desktop/commands.ts), [app/desktop/doric/src/platform/windows/native-windows.ts](../../app/desktop/doric/src/platform/windows/native-windows.ts)).
- `settings` registers the route `/settings` with `<settings-page>`, the window's one React root. It holds no conversation, sidebar or Thread, names the document "Doric Settings", and mounts its own toaster ([src/client/index.ts](../../bundles/desktop/settings/src/client/index.ts), [src/client/views/settings-page.tsx](../../bundles/desktop/settings/src/client/views/settings-page.tsx)).

- Another bundle adds a section the same way: a child route of `/settings` and a `settings-link` item in `settings.sections` with its label, path, icon and description. - Selecting a section, or the one already showing, closes an open provider page ([src/client/views/settings-view.tsx](../../bundles/desktop/settings/src/client/views/settings-view.tsx)).

### Search

- The nav has a search field ("Search settings sections"). It keeps the links whose label or description contains the query, case-insensitively and anywhere in the text; a query of blank space keeps every link. Typing "turns" finds Execution and "time zone" finds Profile, through their descriptions ([src/client/domain/settings-search.ts](../../bundles/desktop/settings/src/client/domain/settings-search.ts), [src/client/domain/sections.ts](../../bundles/desktop/settings/src/client/domain/sections.ts)).
- The query narrows the nav only: the section on screen stays, and while it is filtered out the nav shows no active row. When no link matches, the nav reads "No sections match" ([src/client/views/settings-view.tsx](../../bundles/desktop/settings/src/client/views/settings-view.tsx), [src/client/components/templates/settings-surface.tsx](../../bundles/desktop/settings/src/client/components/templates/settings-surface.tsx)).

### Autosave

- The window loads the configuration through `host-config/v1.current()` into one draft that every section edits, and reads it again whenever the window regains focus, so a draft does not write back over a change saved from the workspace window. When a read answers a configuration other than the one held, it replaces both the stored copy and the draft, so an edit not yet sent, such as one the window's validation refuses, is dropped ([src/client/hooks/use-config.ts](../../bundles/desktop/settings/src/client/hooks/use-config.ts)).
- A change that differs from the stored configuration and that the window's own validation accepts is sent 500 ms after the last edit. A blur of any field in the content area sends it at once, and so does the window's close: the page registers a handler of the window's `onFlushHook`, and the close waits for that save for up to 1,500 ms, the platform's flush deadline ([src/client/hooks/use-config.ts](../../bundles/desktop/settings/src/client/hooks/use-config.ts), [src/client/hooks/use-config-autosave.ts](../../bundles/desktop/settings/src/client/hooks/use-config-autosave.ts), [src/client/views/settings-view.tsx](../../bundles/desktop/settings/src/client/views/settings-view.tsx), [app/desktop/doric/src/platform/windows/close.ts](../../app/desktop/doric/src/platform/windows/close.ts)).
- The window's own validation requires at least one provider; provider ids of 1 to 128 characters, unique; for each provider, a kind the host lists and every field that kind declares, with valid values; an execution provider that exists; a model of 1 to 512 characters; an effort when the model lists efforts, and only one of the known efforts; a turn limit that is an integer of 1 or more; a tool result limit that is empty or an integer of 1 or more; a context-compaction policy, when present, within its ranges (pressure 50 to 95 percent, a tail of 1 or more messages, a summary of 200 or more characters, a budget of 1,000 or more characters); and a valid profile. While the draft breaks one, the section shows "This change cannot be saved yet" with the first reason, and nothing is sent: a tool result limit of 0 blocks every save, though a save never sends that value ([src/client/domain/config.ts](../../bundles/desktop/settings/src/client/domain/config.ts), [src/client/views/settings-view.tsx](../../bundles/desktop/settings/src/client/views/settings-view.tsx)).
- The host checks more than the window does before it stores a configuration: that every credential it names is stored with the right kind, that every loaded tool's required fields resolve, and that its providers can be built. A draft the window accepts can still be refused there ([bundles/foundation/host-config/src/host/config/service.ts](../../bundles/foundation/host-config/src/host/config/service.ts)).
- A save sends the draft through `host-config/v1.replace`, which replaces the whole configuration. The window sends the providers, the execution model, the turn limit, `gitCredentialId`, `githubCredentialId`, `profile` and `threads`. It does not send the Tools section's values, `execution.maxToolResultChars` or `execution.contextCompaction`, so a save stores none of them ([src/client/api/settings-api.ts](../../bundles/desktop/settings/src/client/api/settings-api.ts), [bundles/foundation/host-config/src/host/config/service.ts](../../bundles/foundation/host-config/src/host/config/service.ts)).
- An accepted save replaces the stored copy with the host's answer, and the draft too when it did not change meanwhile. A toast "Settings saved." (id `config-save`) announces each new revision the window holds, after dismissing a failure toast: a save of its own, and also a newer revision a reread on focus brings, saved elsewhere. The first load announces nothing ([src/client/hooks/use-config.ts](../../bundles/desktop/settings/src/client/hooks/use-config.ts), [src/client/hooks/use-config-autosave.ts](../../bundles/desktop/settings/src/client/hooks/use-config-autosave.ts)).
- A refused save keeps the draft and shows an error toast (id `config-save-failed`), titled "Settings not saved" unless the error's code has a title of its own, with the error's message. An `invalid` answer carries the host's message; a `rejected` one, a configuration the host could not activate, reads "The Doric configuration could not be activated."; a host out of reach reads "Doric backend is unavailable." ([src/client/hooks/use-config-autosave.ts](../../bundles/desktop/settings/src/client/hooks/use-config-autosave.ts), [src/client/domain/error-catalog.ts](../../bundles/desktop/settings/src/client/domain/error-catalog.ts), [src/client/api/settings-api.ts](../../bundles/desktop/settings/src/client/api/settings-api.ts)).
- The content footer reads `Revision <n> · Updated <local time>` of the last stored configuration, followed by the save state: "Saving…" while a save is in flight or waiting on the debounce, "Saved" once the draft matches the stored copy, "Not saved" after a refusal. The nav's footer shows the save state alone ([src/client/views/settings-view.tsx](../../bundles/desktop/settings/src/client/views/settings-view.tsx)).
- A section another bundle draws reads and writes the same draft through `settings.config/v1`: `draft()`, `setDraft(update)` and `subscribe(listener)`, client-only and local ([src/contracts/config.ts](../../bundles/desktop/settings/src/contracts/config.ts), [src/client/services/settings-config.ts](../../bundles/desktop/settings/src/client/services/settings-config.ts)).

### When a change applies

- The [`default`](../../bundles/runtime/default/README.md) agent reads `host-config/v1.current()` at the start of every run, so the next prompt of any Project, including one already running, uses the stored providers, the credentials they name, the turn limit and the profile ([bundles/runtime/default/src/host/executor.ts](../../bundles/runtime/default/src/host/executor.ts)).
- The [`runtime`](../../bundles/runtime/runtime/README.md) reads `gitCredentialId` and `githubCredentialId` again before it accepts a prompt, retries one or resumes a Thread's queue, and applies the Git identity and the GitHub token to the Project's sandbox when they differ from what the sandbox last received, so a change reaches a running Project's next prompt too ([bundles/runtime/runtime/src/host/domain/service.ts](../../bundles/runtime/runtime/src/host/domain/service.ts)).
- The execution model, effort and provider chosen in Execution are the workspace default, which the [`runtime`](../../bundles/runtime/runtime/README.md) applies. A new top-level Thread copies it when it is created; a Thread with no stored provider runs on the default's provider at each run, and a Thread with its own stored execution keeps it. The [per-Thread model](per-thread-model.md) describes those rules ([bundles/runtime/runtime/src/contracts/execution.ts](../../bundles/runtime/runtime/src/contracts/execution.ts)).
- The runtime reads `threads.autoArchive` on every archive sweep ([bundles/runtime/runtime/src/host/domain/service.ts](../../bundles/runtime/runtime/src/host/domain/service.ts)).

### Profile

- The Name field and the Time zone combobox edit the optional `profile` ([src/client/components/organisms/settings-profile.tsx](../../bundles/desktop/settings/src/client/components/organisms/settings-profile.tsx)).
- `profile` is strict, with two optional keys. `name` is trimmed and must then be 1 to 100 UTF-16 code units on one line. `timezone` is an IANA zone the host's `Intl` accepts, stored as chosen; an absent `timezone` means the host's own zone ([bundles/foundation/host-config/src/host/config/schema.ts](../../bundles/foundation/host-config/src/host/config/schema.ts)).
- The combobox lists every zone the window's `Intl` supports, UTC, and the stored zone, sorted, after "Host time zone", which removes `profile.timezone`. Clearing a field removes its key, and clearing both removes `profile`; the draft never holds an empty `profile` ([src/client/domain/config.ts](../../bundles/desktop/settings/src/client/domain/config.ts)).
- The [`default`](../../bundles/runtime/default/README.md) bundle gives them to its prompts as the variables `user.name`, present only when a name is set, and `timezone`, the profile's zone or else the host's ([bundles/runtime/default/src/host/prompts/variables.ts](../../bundles/runtime/default/src/host/prompts/variables.ts)).

### Appearance

- The section exists only while the app provides `doric.appearance/v1`: its route and link are registered when a provider appears and removed when it goes ([src/client/appearance-section.ts](../../bundles/desktop/settings/src/client/appearance-section.ts)).
- It draws three tiles, "Dark (default)", "Light" and "System" (the macOS appearance), as one radio group that the arrow keys move along. It reads the theme each time it mounts and writes a choice through `doric.appearance/v1.set`; the tiles are disabled while a read or a write is pending, and the selection moves only once the app has saved it. A failure reads "Could not read the appearance." or "Could not save the appearance. Try again." The theme is not part of the configuration draft and is not autosaved with it ([src/client/components/organisms/settings-appearance.tsx](../../bundles/desktop/settings/src/client/components/organisms/settings-appearance.tsx), [src/client/components/molecules/theme-option.tsx](../../bundles/desktop/settings/src/client/components/molecules/theme-option.tsx)).

### Providers and the provider page

- Providers lists the configured providers as a table (Name, Kind, Address, Models) that sorts, filters by name and pages. Nothing is edited in the table: a row's action opens its provider page or removes it, and "Add provider" opens a page for a new one ([src/client/components/organisms/settings-providers.tsx](../../bundles/desktop/settings/src/client/components/organisms/settings-providers.tsx)).
- The provider page opens one level under Providers. The window's breadcrumb reads `Settings › Providers › <provider>`, or `… › Add provider`, and the heading "Edit provider" or "Add provider". The Providers crumb and the "Back" control close the page and return to the table ([src/client/views/settings-view.tsx](../../bundles/desktop/settings/src/client/views/settings-view.tsx), [src/client/components/templates/settings-window.tsx](../../bundles/desktop/settings/src/client/components/templates/settings-window.tsx)).
- The page has no save of its own: each change is written into the window's draft, and autosaved with it, as soon as the provider is one the host would accept. A provider draft that is not yet valid stays on the page only: it never reaches the window's draft, does not keep the rest of the window from saving, and is lost when the page closes ([src/client/hooks/use-provider-page.ts](../../bundles/desktop/settings/src/client/hooks/use-provider-page.ts), [src/client/components/organisms/settings-provider.tsx](../../bundles/desktop/settings/src/client/components/organisms/settings-provider.tsx)).
- The form is the kind's: the window learns the provider kinds, their fields and their models from `models/v1`, so a kind the host adds is configurable with no change to `settings`. A field of kind `secret` names a stored `API_TOKEN` credential instead of holding a value ([src/client/api/settings-api.ts](../../bundles/desktop/settings/src/client/api/settings-api.ts), [src/client/components/organisms/settings-provider.tsx](../../bundles/desktop/settings/src/client/components/organisms/settings-provider.tsx)).
- How the page edits a provider's models depends on its kind. A kind whose model list is its catalog (`modelsFromCatalog`, the Claude kind) shows that list read-only, with a reload, once the provider can authenticate, and writes every listed model with its efforts into the draft. A kind that declares a models URL offers the models its endpoint lists to choose from, with the efforts the catalog gives each one. Any other kind that keeps models edits them as rows, one per model, each with its own name and the reasoning efforts it accepts as toggles ([src/client/components/organisms/settings-provider.tsx](../../bundles/desktop/settings/src/client/components/organisms/settings-provider.tsx), [src/client/components/organisms/provider-catalog-models.tsx](../../bundles/desktop/settings/src/client/components/organisms/provider-catalog-models.tsx), [src/client/components/organisms/provider-model-picker.tsx](../../bundles/desktop/settings/src/client/components/organisms/provider-model-picker.tsx), [src/client/components/molecules/provider-models-editor.tsx](../../bundles/desktop/settings/src/client/components/molecules/provider-models-editor.tsx), [src/client/domain/config.ts](../../bundles/desktop/settings/src/client/domain/config.ts)).
- Another bundle may draw one field of one kind's form through the slot `settings.provider.field` (`SETTINGS_PROVIDER_FIELD`): its item's props name the `kind` and the `field`, `settings` sets the element's `view` (`kind`, `field`, the value, the label of the credential it names, and a `problem`), and takes its answer from the DOM event `settings-provider-field`. With two items for one kind and field, the first by `order` is drawn. The [`claude-login`](../../bundles/features/claude-login/README.md) bundle draws the Claude sign-in this way ([src/contracts/slots.ts](../../bundles/desktop/settings/src/contracts/slots.ts), [bundles/features/claude-login/src/client/index.ts](../../bundles/features/claude-login/src/client/index.ts)).
- A failed read of the provider kinds shows an error notice with Retry in the Providers section ([src/client/views/settings-view.tsx](../../bundles/desktop/settings/src/client/views/settings-view.tsx)).

### The dashboard's Providers group

- In the workspace window's `/projects` dashboard, `settings` adds the Providers group to `workspace.dashboard.nav` (order 100) and the provider page to `workspace.dashboard.page` under the id `settings.provider` ([src/client/index.ts](../../bundles/desktop/settings/src/client/index.ts), [src/client/elements.ts](../../bundles/desktop/settings/src/client/elements.ts)).
- The group lists one row per configured provider, by its mark and name, and a "+" that adds a provider. A row or the "+" opens the provider page in the dashboard's main area through `workspace.dashboard/v1.show`, only while that contract is available ([src/client/views/dashboard-providers.tsx](../../bundles/desktop/settings/src/client/views/dashboard-providers.tsx), [src/client/components/organisms/dashboard-providers.tsx](../../bundles/desktop/settings/src/client/components/organisms/dashboard-providers.tsx), [src/client/api/settings-api.ts](../../bundles/desktop/settings/src/client/api/settings-api.ts)).
- A failed read of the provider kinds, or else of the stored credentials, shows a compact error notice with Retry after the group's rows ([src/client/components/organisms/dashboard-providers.tsx](../../bundles/desktop/settings/src/client/components/organisms/dashboard-providers.tsx), [src/client/views/dashboard-providers.tsx](../../bundles/desktop/settings/src/client/views/dashboard-providers.tsx)).
- The dashboard's page draws the same provider form, titled by the provider's mark and name ("Add provider" for a new one). For a kind whose descriptor names an `https:` site it adds a control that opens the site in the system browser; a failure to open it is an error toast (id `provider-open-site`) ([src/client/components/organisms/dashboard-provider-page.tsx](../../bundles/desktop/settings/src/client/components/organisms/dashboard-provider-page.tsx)).
- The group keeps its own draft of the configuration and autosaves it as the settings window does: 500 ms after typing, on a field blur, through the window's `onFlushHook` on close, and when the group leaves the dashboard. The dashboard showing another page closes the provider page ([src/client/views/dashboard-providers.tsx](../../bundles/desktop/settings/src/client/views/dashboard-providers.tsx)).

### Execution

- Execution edits the workspace default: the provider, chosen among the configured ones; the model, chosen among the provider's models, or typed when the provider lists none; and the reasoning effort, chosen among the efforts the model lists other than `none` ([src/client/components/organisms/settings-execution.tsx](../../bundles/desktop/settings/src/client/components/organisms/settings-execution.tsx)).
- Choosing another provider or model sets the effort to the one that model starts at. A model that lists no effort offers none ("Not offered by this model") and the default then carries no effort, so a prompt sends no reasoning. When the window loads a default whose effort is absent or `none` on a model that offers another, the draft starts at that model's start effort. That draft differs from the stored configuration, so opening the window writes it 500 ms later, with no edit, and toasts "Settings saved." ([src/client/hooks/use-config.ts](../../bundles/desktop/settings/src/client/hooks/use-config.ts), [src/client/domain/config.ts](../../bundles/desktop/settings/src/client/domain/config.ts)).
- The Turn limit field sets `execution.maxTurns`. The "Tool result limit" field edits `execution.maxToolResultChars` in the draft, which a save does not send; a value that is not an integer of 1 or more still blocks every save ([src/client/components/organisms/settings-execution.tsx](../../bundles/desktop/settings/src/client/components/organisms/settings-execution.tsx), [src/client/api/settings-api.ts](../../bundles/desktop/settings/src/client/api/settings-api.ts)).
- The conversation footer's execution picker, which edits one Thread's execution, is drawn by the [`chat`](../../bundles/desktop/chat/README.md) bundle from `settings.models/v1`, which `settings` serves from the stored configuration; the [per-Thread model](per-thread-model.md) describes it ([src/client/services/settings-models.ts](../../bundles/desktop/settings/src/client/services/settings-models.ts)).

### Threads

- Threads holds the Auto-archive group: the switch "Archive finished agent threads" (on by default) and "Archive inactive main threads after" 1 day, 7 days (the default), 30 days or Never. A change stores both keys of `threads.autoArchive` ([src/client/components/organisms/settings-threads.tsx](../../bundles/desktop/settings/src/client/components/organisms/settings-threads.tsx), [src/client/domain/config.ts](../../bundles/desktop/settings/src/client/domain/config.ts)). The [thread archive](thread-archive.md) describes what the runtime does with them.

### Tools

- Tools draws one group per tool of the `tools/v1` catalog that declares fields: an `enum` field as a picker of its options, any other as a text field, each showing the draft's value or else the field's default. A tool with no field has no group; with none at all the section reads "No tool declares configuration yet." A failed read of the catalog shows an error notice with Retry ([src/client/components/organisms/settings-tools.tsx](../../bundles/desktop/settings/src/client/components/organisms/settings-tools.tsx)).
- The values edited here stay in the draft: a save does not send them ([src/client/api/settings-api.ts](../../bundles/desktop/settings/src/client/api/settings-api.ts)).

### Credentials

- Credentials edits the host's credential store through `secrets/v1`, not through the configuration draft. It lists only the kinds the window manages, `API_TOKEN`, `USERNAME_PASSWORD` and `GIT`, as a table, and adds or edits one credential in a dialog whose "Add credential" or "Save credential" button writes it ([src/client/components/organisms/settings-credentials.tsx](../../bundles/desktop/settings/src/client/components/organisms/settings-credentials.tsx), [src/client/domain/config.ts](../../bundles/desktop/settings/src/client/domain/config.ts)).
- A secret is write-only: the host answers whether one is stored and never its value, so an edit opens with the secret empty, and an empty secret keeps what is stored. A refused add or edit is shown in the dialog, which stays open; a refused removal is an error toast (id `credentials-write-failed`), and each success dismisses it before its own toast (id `credentials-write`) ([src/client/components/organisms/settings-credentials.tsx](../../bundles/desktop/settings/src/client/components/organisms/settings-credentials.tsx)).
