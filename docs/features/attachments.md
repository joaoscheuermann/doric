# Feature: Attachments

- Status: `implemented`

## Problem

A reader wants to show the agent a screenshot, and a tool wants to hand the model an image it found. The model must receive the image itself, while prompts, queued inputs, edits, events, tool results and the stored history stay text that every part of the system already stores, redacts, compacts and draws. An image must be readable only in the Project that holds it, must go when the Thread or Project that holds it is deleted, and must not reach a model whose provider's catalog says it reads no images.

## Decisions

- The host's Socket.IO message limit is a constant of the host's own, `SOCKET_MAX_HTTP_BUFFER_BYTES`, 8,039,084 bytes: the base64 size of the largest attachment (6,990,508 bytes for 5 MiB) plus 1,048,576 bytes for the envelope around it. The host imports no bundle to size it; a host test imports the runtime's `ATTACHMENT_MAX_BYTES` and fails when the constant is smaller than that attachment as base64 plus 1,048,576 bytes ([app/backend/doric-host/src/lib/socket-buffer.ts](../../app/backend/doric-host/src/lib/socket-buffer.ts), [app/backend/doric-host/tests/socket-buffer.test.ts](../../app/backend/doric-host/tests/socket-buffer.test.ts)).

## Current behavior and contracts

### Units

- The `runtime` bundle owns attachments: it provides `runtime.attachments/v1` 1.0.0, keeps the `runtime.attachment/v1` records, and exports the reference line's format and helpers from its contracts module ([manifest.json](../../bundles/runtime/runtime/manifest.json), [src/contracts/attachments.ts](../../bundles/runtime/runtime/src/contracts/attachments.ts)). Its [README](../../bundles/runtime/runtime/README.md) holds the full contract.
- The `core` bundle provides `storage/v1` 1.1.0, whose `putBlob`, `getBlob` and `deleteBlob` keep the bytes, and forwards them to `storage.backend/v1`, which the `postgres` bundle provides at 1.1.0 ([bundles/foundation/core/manifest.json](../../bundles/foundation/core/manifest.json), [bundles/foundation/core/src/host/storage/facade.ts](../../bundles/foundation/core/src/host/storage/facade.ts), [bundles/foundation/postgres/manifest.json](../../bundles/foundation/postgres/manifest.json), [bundles/foundation/postgres/src/host/storage/blobs.ts](../../bundles/foundation/postgres/src/host/storage/blobs.ts)). See the READMEs of [`core`](../../bundles/foundation/core/README.md) and [`postgres`](../../bundles/foundation/postgres/README.md).
- The `default` bundle's executor turns reference lines into images in the requests a model reads ([src/host/attachments.ts](../../bundles/runtime/default/src/host/attachments.ts), [README](../../bundles/runtime/default/README.md)). The `llms` package sends the images in each provider's format ([README](../../packages/llms/README.md)).
- The `chat` bundle requires `runtime.attachments/v1` and attaches and draws images in the window ([manifest.json](../../bundles/desktop/chat/manifest.json), [src/client/api/attachments-api.ts](../../bundles/desktop/chat/src/client/api/attachments-api.ts), [README](../../bundles/desktop/chat/README.md)).
- The tools `view-image` of the `files` bundle and the MCP tools of the `mcp` bundle attach the images they return ([bundles/features/files/src/host/tools/view-image.ts](../../bundles/features/files/src/host/tools/view-image.ts), [bundles/features/mcp/src/host/tools.ts](../../bundles/features/mcp/src/host/tools.ts); READMEs of [`files`](../../bundles/features/files/README.md) and [`mcp`](../../bundles/features/mcp/README.md)).
- The host sizes its Socket.IO messages for one attachment ([app/backend/doric-host/src/lib/socket-buffer.ts](../../app/backend/doric-host/src/lib/socket-buffer.ts), [README](../../app/backend/doric-host/README.md)).

### The reference line

- Text names an attachment with the Markdown image line `![<name>](doric-attachment:sha256-<64 hex>)`. The id `sha256-<hex>` is the blob's hash `sha256:<hex>` spelled for a URL ([src/contracts/attachments.ts](../../bundles/runtime/runtime/src/contracts/attachments.ts)).
- `attachmentReference(name, id)` writes the line. Its name has line breaks turned into spaces, brackets removed, is trimmed and cut to 200 characters, and is `image` when nothing is left ([src/contracts/attachments.ts](../../bundles/runtime/runtime/src/contracts/attachments.ts)).
- `attachmentReferences(text)` finds every reference in a text, wherever it stands; `attachmentLine(line)` answers the reference only when the trimmed line holds nothing else; `withAttachmentPlaceholders(text)` writes each reference as `[<name>]` ([src/contracts/attachments.ts](../../bundles/runtime/runtime/src/contracts/attachments.ts)).
- Because an image is a line of text, prompts, queued inputs, edits, steers, events, tool results and the stored history carry no image bytes ([src/contracts/attachments.ts](../../bundles/runtime/runtime/src/contracts/attachments.ts), [bundles/runtime/default/src/host/attachments.ts](../../bundles/runtime/default/src/host/attachments.ts)).

### Keeping an image

- An attachment is one content-addressed `storage/v1` blob plus one `runtime.attachment/v1` record per Thread that attached it. The record holds `{ projectId, threadId, id, name, mediaType, size, createdAt }` under the key `<threadId>:<id>`, with the indexes `byProject` (`projectId`, `id`), `byThread` (`threadId`) and `byBlob` (`id`) ([src/contracts/storage.ts](../../bundles/runtime/runtime/src/contracts/storage.ts), [src/host/store/attachments.ts](../../bundles/runtime/runtime/src/host/store/attachments.ts)).
- `runtime.attachments/v1` has two methods, both reachable from the desktop. Its scope keys are `projectId`, `threadId` and `promptId` ([src/host/services/attachments.ts](../../bundles/runtime/runtime/src/host/services/attachments.ts), [manifest.json](../../bundles/runtime/runtime/manifest.json)).

| Method                    | Behavior                                                                                                                                                                                                                                                                                                                                                                                                                    |
| ------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `attach({ name, bytes })` | Keeps base64 `bytes` for the Thread of `call.scope.threadId` and answers `{ id, name, mediaType, size }`. Without a Thread scope it refuses with `invalid_input` (`runtime.attachments/v1.attach needs a Thread scope.`); an unknown Thread is `not_found`. Attaching the same bytes again answers the same id; in the same Thread it rewrites that Thread's one record for the bytes, with the new `name` and `createdAt`. |
| `read({ id })`            | Answers `{ id, name, mediaType, size, bytes }` for the Project of `call.scope.threadId`, else `call.scope.projectId`, or `undefined` when the id is not `sha256-<64 hex>`, when that Project holds no record of the id, or when the blob is gone. An unknown Thread is `not_found`. With neither scope it refuses with `invalid_input` (`runtime.attachments/v1 needs a Project or Thread scope.`).                         |

- An attach refuses with `invalid_input` bytes that are empty (`The attachment is empty.`), larger than 5 MiB (`ATTACHMENT_MAX_BYTES`; `The attachment is larger than 5 MiB.`), or not a PNG, JPEG, WebP or GIF (`The attachment is not a PNG, JPEG, WebP or GIF image.`). The media type is read from the bytes' signature, never from the name ([src/host/store/attachments.ts](../../bundles/runtime/runtime/src/host/store/attachments.ts), [src/contracts/attachments.ts](../../bundles/runtime/runtime/src/contracts/attachments.ts)).
- Every Thread of a Project reads the images any of its Threads attached, so a reader's image and an image a tool attached in a delegated Thread are read alike. A reference line written in another Project reads as nothing ([src/host/services/attachments.ts](../../bundles/runtime/runtime/src/host/services/attachments.ts), [src/host/store/attachments.ts](../../bundles/runtime/runtime/src/host/store/attachments.ts)).

### Deleting

- Deleting a Thread with its subtree, or a Project, deletes its attachment records in the same commit that deletes its documents, histories and event streams ([src/host/store/threads.ts](../../bundles/runtime/runtime/src/host/store/threads.ts), [src/host/store/projects.ts](../../bundles/runtime/runtime/src/host/store/projects.ts)).
- After that commit, each blob those records named and no record in any Project names any more is deleted through `storage/v1.deleteBlob`. A failure there leaves the blob behind, unreadable since no record names it, and does not fail the delete ([src/host/store/attachments.ts](../../bundles/runtime/runtime/src/host/store/attachments.ts)).
- The runtime runs an attach and a collection of the same blob one at a time in its process, so a collection never deletes the bytes of a record being written ([src/host/store/attachments.ts](../../bundles/runtime/runtime/src/host/store/attachments.ts)).

### Sending images to the model

- The runner hands each prompt's session `attachment(id)`, which reads through the attachment store for the Thread's Project (`PromptSession.attachment`, `executor/v1`) ([src/host/domain/runner.ts](../../bundles/runtime/runtime/src/host/domain/runner.ts), [src/contracts/executor.ts](../../bundles/runtime/runtime/src/contracts/executor.ts)).
- Each run of the default executor (`executor/v1` 1.5.0, provided by `default`) asks `models/v1.inputModalities` (`models/v1` 1.2.0; `core` provides 1.4.0) what its model reads ([bundles/runtime/default/manifest.json](../../bundles/runtime/default/manifest.json), [bundles/runtime/default/src/host/executor.ts](../../bundles/runtime/default/src/host/executor.ts), [packages/bundle/src/contracts/basic/models.ts](../../packages/bundle/src/contracts/basic/models.ts), [bundles/foundation/core/manifest.json](../../bundles/foundation/core/manifest.json)).
- `core` answers from the model's entry in the cached catalog of exactly one candidate provider: a configured provider whose kind reports `catalogCapacity`, and that is the requested provider or, without one, lists the model. It answers `undefined` when no such provider or more than one exists, when its catalog does not list the model, when the entry lists no modalities, or when the lookup fails ([bundles/foundation/core/src/host/models/capacity.ts](../../bundles/foundation/core/src/host/models/capacity.ts)).
- The `claude` and `openrouter` kinds report `catalogCapacity`; the `openai` and `codex` kinds do not, so their models always answer `undefined` ([bundles/providers/claude/src/host/kind.ts](../../bundles/providers/claude/src/host/kind.ts), [bundles/providers/openrouter/src/host/kind.ts](../../bundles/providers/openrouter/src/host/kind.ts), [bundles/providers/openai/src/host/kind.ts](../../bundles/providers/openai/src/host/kind.ts), [bundles/providers/codex/src/host/kind.ts](../../bundles/providers/codex/src/host/kind.ts)).
- A model whose answer is `undefined` is treated as reading everything: it is offered every tool and sent every image ([bundles/runtime/default/src/host/executor.ts](../../bundles/runtime/default/src/host/executor.ts)).
- A tool declares what its results hand the model besides text in `resultModalities` (`tools/v1` 1.4.0), such as `image` for `view-image`. The field is carried across processes, so a tool registered from another process declares it too ([packages/bundle/src/contracts/basic/tools.ts](../../packages/bundle/src/contracts/basic/tools.ts), [packages/bundle/src/runtime/envelope/values.ts](../../packages/bundle/src/runtime/envelope/values.ts), [bundles/features/files/src/host/tools/view-image.ts](../../bundles/features/files/src/host/tools/view-image.ts)).
- The executor leaves out every tool whose declared result modalities the model does not read. A tool that declares none stays offered ([bundles/runtime/default/src/host/executor.ts](../../bundles/runtime/default/src/host/executor.ts)).
- Only the request a model reads changes; the stored history stays text. In each user or tool message whose content is text, every reference the Project holds becomes a text part ending in `[Image: <name>]`, where `<name>` is the name the attachment's record keeps, followed by an image part `data:<mediaType>;base64,<bytes>`, in the reference's place among the words. A reference the Project does not hold stays text ([bundles/runtime/default/src/host/attachments.ts](../../bundles/runtime/default/src/host/attachments.ts)).
- For a model that reads no images, nothing is read and every reference becomes `[Image: <name> (not shown: this model does not read images)]`, where `<name>` is the reference's alt text ([bundles/runtime/default/src/host/attachments.ts](../../bundles/runtime/default/src/host/attachments.ts)).
- A run reads each attachment once, however many requests carry it ([bundles/runtime/default/src/host/attachments.ts](../../bundles/runtime/default/src/host/attachments.ts)).
- Automatic and manual compaction (`compactThread`) read the history through the unwrapped language model, so a summary is written from the reference lines as text and never carries image bytes ([bundles/runtime/default/src/host/executor.ts](../../bundles/runtime/default/src/host/executor.ts), [bundles/runtime/default/src/host/compact.ts](../../bundles/runtime/default/src/host/compact.ts)).
- Each provider sends the image parts in its own format ([packages/llms/src/lib/providers/openai/body.ts](../../packages/llms/src/lib/providers/openai/body.ts), [packages/llms/src/lib/providers/codex.ts](../../packages/llms/src/lib/providers/codex.ts), [packages/llms/src/lib/providers/openrouter/body.ts](../../packages/llms/src/lib/providers/openrouter/body.ts), [packages/llms/src/lib/providers/claude/body.ts](../../packages/llms/src/lib/providers/claude/body.ts)):
  - OpenAI and Codex send `input_image` parts beside `input_text` parts, in a user turn and in a `function_call_output`; a tool result without images stays a plain string.
  - OpenRouter sends a user turn's images as `image_url` parts. Tool messages stay text; after a run of tool messages it sends one user message with the images those calls returned, each set introduced by ``The tool call `<id>` returned these images:``.
  - Claude sends `image` blocks with a base64 source, in a user turn and inside a `tool_result`.

### Tools that return images

- `view-image` reads a file from the sandbox, attaches it in the calling Thread, and answers the reference line; a file that is not an accepted image is refused by the attach, and that refusal is what the model reads ([bundles/features/files/src/host/tools/view-image.ts](../../bundles/features/files/src/host/tools/view-image.ts)).
- An MCP tool result's image block of an accepted type is attached as `image.<subtype>` and becomes its reference line. A block of another type becomes `[An image (<type>) the conversation cannot show.]`, and a block the Project refuses to keep becomes `[An image (<type>) the Project refused to keep.]`. MCP tools declare no `resultModalities`, so they stay offered to a model that reads no images, and their images reach it as the not-shown note ([bundles/features/mcp/src/host/tools.ts](../../bundles/features/mcp/src/host/tools.ts)).

### In the window

- The composer attaches each image file the reader pastes into the prompt or drops on it, in order, through `runtime.attachments/v1.attach` in the conversation's Thread, and only then writes its reference line, on a line of its own at the caret, or at the end of the prompt when the caret has left it ([src/client/components/organisms/conversation/plugins/attach-images.tsx](../../bundles/desktop/chat/src/client/components/organisms/conversation/plugins/attach-images.tsx)).
- A file larger than 5 MiB is refused in the window before it is sent, with `invalid_input` and `The image is larger than 5 MiB.`; a host refusal keeps the code `invalid_input` and the host's sentence ([src/client/api/attachments-api.ts](../../bundles/desktop/chat/src/client/api/attachments-api.ts)).
- A failed attach shows a toast for that file. Its title comes from the first error level whose code has a catalog entry: an `invalid_input` refusal, the window's or the host's, is titled "Request refused" with the refusal's sentence as its explanation, and an unknown Thread (`not_found`) "Not found". A failure with no such code, such as `internal`, is titled "Image not attached" (`attach_failed`) ([src/client/components/organisms/conversation/plugins/attach-images.tsx](../../bundles/desktop/chat/src/client/components/organisms/conversation/plugins/attach-images.tsx), [packages/desktop/src/error-copy.ts](../../packages/desktop/src/error-copy.ts), [src/client/domain/error-catalog.ts](../../bundles/desktop/chat/src/client/domain/error-catalog.ts)).
- The prompt holds the image as a node whose text is the reference line, so the prompt sends, drafts and edits the line as text; text loaded back into the prompt turns each line that is only a reference into the image again ([src/client/components/organisms/conversation/nodes/attachment-image-node.tsx](../../bundles/desktop/chat/src/client/components/organisms/conversation/nodes/attachment-image-node.tsx)).
- The prompt, every turn and a tool result that is only a reference line draw it as the image, as wide as the column at most. The image is read through `runtime.attachments/v1.read` in the conversation's Thread and kept once per attachment as a `data:` URL; one the Project does not hold, or that cannot be read, shows `[<name>]`. A reference with words around it on its line is drawn as text, and one inside a code fence as code ([src/client/components/molecules/attachment-image.tsx](../../bundles/desktop/chat/src/client/components/molecules/attachment-image.tsx), [src/client/domain/markdown.ts](../../bundles/desktop/chat/src/client/domain/markdown.ts), [src/client/components/organisms/conversation/nodes/markdown-blocks.ts](../../bundles/desktop/chat/src/client/components/organisms/conversation/nodes/markdown-blocks.ts), [src/client/components/molecules/tool-item.tsx](../../bundles/desktop/chat/src/client/components/molecules/tool-item.tsx)).
- Queue rows show each reference of a reader's prompt as `[<name>]` and other sources' text as is; the queued-prompt block shows every item's references as `[<name>]`; the queue edit header shows the edited prompt's references as `[<name>]` ([src/client/domain/queue.ts](../../bundles/desktop/chat/src/client/domain/queue.ts), [src/client/components/organisms/conversation/nodes/queued-turn-node.tsx](../../bundles/desktop/chat/src/client/components/organisms/conversation/nodes/queued-turn-node.tsx), [src/client/components/organisms/conversation/plugins/edit-queue-prompt.tsx](../../bundles/desktop/chat/src/client/components/organisms/conversation/plugins/edit-queue-prompt.tsx)).

### Message size

- A desktop call carries an attachment whole, base64 in its envelope, over the host's `/doric/bridge` Socket.IO namespace. The host's Socket.IO server accepts messages of up to `SOCKET_MAX_HTTP_BUFFER_BYTES`, 8,039,084 bytes ([app/backend/doric-host/src/lib/socket-buffer.ts](../../app/backend/doric-host/src/lib/socket-buffer.ts), [app/backend/doric-host/tests/socket-buffer.test.ts](../../app/backend/doric-host/tests/socket-buffer.test.ts), [app/backend/doric-host/src/index.ts](../../app/backend/doric-host/src/index.ts), [app/backend/doric-host/src/lib/bridge/socket.ts](../../app/backend/doric-host/src/lib/bridge/socket.ts)).
