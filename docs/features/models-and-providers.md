# Feature: Models and providers

- Status: `implemented`

## Problem

The agent calls language models through providers of several kinds: an OpenAI Responses endpoint, OpenRouter, a Claude Code subscription login and the ChatGPT Codex backend. Each kind needs other values to reach its endpoint, knows its models in another way and asks for reasoning in another way. The user needs one place to set which providers the host may call, which models each offers and what a new Thread runs on, without the window carrying a list of kinds or models of its own. Each provider kind is a bundle of its own, and a credential must never leave the host's credential store.

## Decisions

- `models.provider/v1` is a contract of cardinality `many`: every provider kind is one record of it, and a bundle that provides it is one kind. The `openai`, `openrouter`, `codex` and `claude` bundles each provide one record and require only `log/v1`; the secret of a provider reaches them from the core, through `catalog({ secret })` and `create({ secret })`, never from `secrets/v1` of their own. None of them has a `contracts` module.
- The core provides `models/v1` over the records it sees. It reads each record's descriptor once, when the record appears, and keeps it in the record's registration place. `kinds()` lists the advertised kinds in registration order; `kind(id)` finds any registered kind, `codex` included. A removed record drops the providers it built, and the next `resolve` builds them again from the active configuration.
- The core reads no product configuration. `prepare` sets the active providers instead: a stored snapshot (`{ configuration, revision, updatedAt }`) becomes the active set; a configuration without a `revision` is a candidate, built before it is stored, which the next stored snapshot adopts without building them again when its providers are in exactly the same form; otherwise the snapshot's providers are built again (see [The configured providers](#the-configured-providers)). `host-config` calls `prepare(current)` at startup and, on a replacement, `prepare(filled)` before the store write and `prepare(snapshot)` after it. A failed write changes nothing, and a running prompt keeps the instance it resolved.
- `create` receives the values without the `secret` fields and a `secret` callback that reads `secrets/v1.resolve` in the core, `''` when no credential is stored. The provider awaits it before every request, so a rotated credential reaches the next request of a provider built before the rotation.
- `models/v1.catalog` resolves the credential of the kind's first `secret` field and calls the record's `catalog`. A kind no record provides answers `absent`. The `openrouter` bundle answers `failed` without logging; `models/v1` logs `Model catalog could not be read` with `{ kind }` alone.
- `POST /providers/models` applies the strict input `{ kind, configuration }` and the field rule of a stored provider to the descriptor `models/v1.kind(id)` gives, internal kinds included. An unknown kind or a refused field answers `422 invalid_provider` without reading the catalog; a catalog `failed` or `absent` answers `502`.
- `catalogCapacity()` is required of every `models.provider/v1` record; the core treats a failing call as `false`. `models/v1.contextWindow` considers the providers of the active configuration whose kind reports `catalogCapacity()` and that are the `providerId` or, without one, list the model. With exactly one candidate it reads that cached provider's `models()` and answers a finite capacity above 0, else nothing, and it never throws.
- `host-config` validates a configuration's kinds and fields synchronously against the kind catalog of `packages/llms` (`providerKind`).
- The provider owns its icons. `models.provider/v1.icons` answers, for a provider's values and some model names, the provider's own icon and each model's icon, by name. The provider receives the values and the model names, never a secret, and choosing icons does no I/O.
- Icons are named from one set in `packages/llms`: LobeHub's mono icons from `@lobehub/icons-static-svg` 1.102.0 (MIT), kept as a TypeScript module with the source, the hashes and the edits `packages/llms/PROVENANCE.md` records. The provider chooses names and the core turns them into SVG; a name the core does not know is no icon. Each kind's rule is in its `kind.ts`, and the two model rules a kind may call, by OpenRouter lab and by model name, read one family table in `packages/llms`.
- The core applies the fallback, once for every kind: a model without an icon wears its provider's own icon. A record whose `icons` rejects, does not answer within 1000 ms, or answers out of shape has no icon for that request, and the rest of the answer does not fail with it.
- `models/v1.icons` is one batched method exposed to the desktop. A request names a configured provider by id or a draft by kind and values, and the answer carries icon names and, once each, the SVG of every name it uses.
- The kinds choose these icons: `claude`, Claude for every model and as its own; `codex`, OpenAI for every model and as its own; `openai` on OpenAI's own endpoint, OpenAI for every model and as its own; `openai` on another endpoint, the family the model's name says and no icon of its own; `openrouter`, the lab the model id's prefix names (`anthropic/` Claude, `openai/` OpenAI, `google/gemma` Gemma, other `google/` Gemini, `deepseek/` DeepSeek, `qwen/` Qwen, `meta-llama/` Meta) and OpenRouter as its own. The name rule matches every family of the set: Claude, Gemini, Gemma, OpenAI (`gpt`), DeepSeek, Qwen and Meta (`llama`).
- A provider without an own icon shows lucide's `ServerIcon` on the provider pages; the window has no endpoint rule of its own.

## Current behavior and contracts

### The bundles

- The [`core`](../../bundles/foundation/core/README.md) bundle provides `models/v1` 1.4.0 over every `models.provider/v1` record ([manifest.json](../../bundles/foundation/core/manifest.json), [src/host/models/index.ts](../../bundles/foundation/core/src/host/models/index.ts)). Both contracts are defined in `bundle/contracts` ([packages/bundle/src/contracts/basic/models.ts](../../packages/bundle/src/contracts/basic/models.ts)).
- The [`openai`](../../bundles/providers/openai/README.md), [`openrouter`](../../bundles/providers/openrouter/README.md), [`codex`](../../bundles/providers/codex/README.md) and [`claude`](../../bundles/providers/claude/README.md) bundles, version 1.2.0, each provide one `models.provider/v1` 1.3.0 record and require `log/v1`. Each kind is a `KindDefinition`: its descriptor, whether it is advertised, whether its catalog reports capacity, how a provider is built, how its catalog is read and which icons it chooses ([bundles/providers/openai/manifest.json](../../bundles/providers/openai/manifest.json), [bundles/providers/openai/src/host/provider.ts](../../bundles/providers/openai/src/host/provider.ts)).
- The host enables `openai`, `openrouter`, `codex` and `claude`, in that order ([app/backend/doric-host/composition.json](../../app/backend/doric-host/composition.json)).
- The [`host-config`](../../bundles/foundation/host-config/README.md) bundle stores the configuration, fills it from the catalogs and activates its providers ([bundles/foundation/host-config/src/host/config/service.ts](../../bundles/foundation/host-config/src/host/config/service.ts)). The [`transport`](../../bundles/foundation/transport/README.md) bundle serves `/config` and `/providers` over them ([bundles/foundation/transport/src/host/app.ts](../../bundles/foundation/transport/src/host/app.ts)).
- The [`settings`](../../bundles/desktop/settings/README.md) bundle draws the provider pages and the default execution; [Settings](settings.md) describes the window.
- The providers themselves are the factories of `packages/llms` ([packages/llms/README.md](../../packages/llms/README.md)).

### Provider kinds

- A kind's descriptor (`ModelKindDescriptor`) has an `id`, a `label`, a `description`, its `fields`, the `lists` it keeps (`models`, `reasonings`), an optional `modelsFromCatalog` and an optional `https:` `site`. A field (`ModelField`) has a `key`, a `label`, a `kind` (`text`, `url`, `number`, `enum`, `secret`), `required`, and optional `description`, `placeholder`, `options` and `advanced` ([packages/bundle/src/contracts/basic/models.ts](../../packages/bundle/src/contracts/basic/models.ts)).
- Each kind is the descriptor its bundle reports; `host-config` also checks a stored provider against the kind catalog of `packages/llms` (see [The configured providers](#the-configured-providers)).
- A `secret` field's value is the id of a stored `API_TOKEN` credential, never the secret ([bundles/foundation/host-config/src/host/config/schema.ts](../../bundles/foundation/host-config/src/host/config/schema.ts), [bundles/foundation/host-config/src/host/config/service.ts](../../bundles/foundation/host-config/src/host/config/service.ts)); [Credentials](credentials.md) describes the store.
- Every kind has an `endpoint` field (`url`, optional, `advanced`) whose placeholder is the factory's own base URL, and a `token` field (`secret`) ([bundles/providers/openai/src/host/provider.ts](../../bundles/providers/openai/src/host/provider.ts)).

| Kind         | Advertised | Lists                  | Catalog                                                         | Other fields                                                |
| ------------ | ---------- | ---------------------- | --------------------------------------------------------------- | ----------------------------------------------------------- |
| `openai`     | yes        | `models`, `reasonings` | none                                                            | `token` optional                                            |
| `openrouter` | yes        | `models`, `reasonings` | the models URL; reports capacity                                | `maxStructuredOutputRepairs`, `modelsUrl` (both `advanced`) |
| `codex`      | no         | none                   | none                                                            | `chatGptAccountId`, `fedramp` (`true` or `false`)           |
| `claude`     | yes        | `models`, `reasonings` | Anthropic's `/v1/models`; `modelsFromCatalog`; reports capacity | none                                                        |

`maxStructuredOutputRepairs` must be a non-negative safe integer; any other value fails the provider's build, so `PUT /config` answers `503 configuration_rejected` ([packages/llms/src/lib/providers/openrouter.ts](../../packages/llms/src/lib/providers/openrouter.ts), [bundles/foundation/transport/src/host/routes/config.ts](../../bundles/foundation/transport/src/host/routes/config.ts)).

Sources: [openai/src/host/kind.ts](../../bundles/providers/openai/src/host/kind.ts), [openrouter/src/host/kind.ts](../../bundles/providers/openrouter/src/host/kind.ts), [codex/src/host/kind.ts](../../bundles/providers/codex/src/host/kind.ts), [claude/src/host/kind.ts](../../bundles/providers/claude/src/host/kind.ts).

- `GET /providers/kinds` answers `{ kinds }`, the advertised kinds `models/v1.kinds()` lists: `openai`, `openrouter` and `claude`. `codex` is not listed, but `models/v1.kind('codex')` describes it, so a configured `codex` provider is built and runs ([bundles/foundation/transport/src/host/routes/providers.ts](../../bundles/foundation/transport/src/host/routes/providers.ts), [bundles/foundation/core/src/host/models/index.ts](../../bundles/foundation/core/src/host/models/index.ts), [bundles/foundation/core/src/host/models/registry.ts](../../bundles/foundation/core/src/host/models/registry.ts)).
- A record whose descriptor cannot be read is left out of every list ([bundles/foundation/core/src/host/models/registry.ts](../../bundles/foundation/core/src/host/models/registry.ts)).
- The window learns the kinds, their fields and their models from `models/v1`, which it reaches through the desktop bridge, so it carries no list of kinds of its own ([bundles/desktop/settings/src/client/api/settings-api.ts](../../bundles/desktop/settings/src/client/api/settings-api.ts)).

### The configured providers

- `host-config` takes a whole configuration through `host-config/v1.replace`, which `PUT /config` calls; `GET /config` answers the stored snapshot. An invalid configuration answers `422 invalid_config`, one that cannot be activated `503 configuration_rejected` ([bundles/foundation/transport/src/host/routes/config.ts](../../bundles/foundation/transport/src/host/routes/config.ts)).
- A configuration lists at least one provider. A configured provider is `{ id, kind, configuration, models? }`. Its `id` is 1 to 128 characters and unique. Its `configuration` holds exactly the fields its kind declares: every required value present and not empty, no undeclared key, an optional value absent rather than empty, a `url` starting with `http://` or `https://`, a `number` that is finite, an `enum` among its `options`, a `secret` that is a UUID ([bundles/foundation/host-config/src/host/config/schema.ts](../../bundles/foundation/host-config/src/host/config/schema.ts)).
- A provider carries `models` exactly when its kind keeps `models`, possibly empty. A model is `{ name, reasonings?, defaultEffort?, mandatory? }`, its name 1 to 512 characters and not repeated. It carries `reasonings` exactly when the kind keeps `reasonings`; `defaultEffort` must be one of its `reasonings`. A kind that keeps no `reasonings` carries the name alone ([bundles/foundation/host-config/src/host/config/schema.ts](../../bundles/foundation/host-config/src/host/config/schema.ts)).
- A provider's kind must be one the kind catalog of `packages/llms` lists (`providerKind`); any other fails validation (`Unknown provider kind`), and `PUT /config` answers `422 invalid_config` with `The Doric configuration is invalid.` A kind that a provider bundle adds is therefore stored only when `packages/llms/src/lib/providers/kinds.ts` also lists it ([bundles/foundation/host-config/src/host/config/schema.ts](../../bundles/foundation/host-config/src/host/config/schema.ts), [packages/llms/src/lib/providers/kinds.ts](../../packages/llms/src/lib/providers/kinds.ts)).
- An effort is one of `none`, `minimal`, `low`, `medium`, `high`, `xhigh` and `max` ([packages/llms/src/lib/types/provider.ts](../../packages/llms/src/lib/types/provider.ts)).
- A replacement runs in request order: the credential rule (every `secret` value names an `API_TOKEN` credential), the catalog fill, the tool-field rule, the candidate providers (`models/v1.prepare`), the store write, and the activation of the stored revision. A failure after the caller-input rules keeps the active configuration ([bundles/foundation/host-config/src/host/config/service.ts](../../bundles/foundation/host-config/src/host/config/service.ts)). The core builds each provider through its kind's `create`, one at a time in configuration order, and a running prompt keeps the provider it resolved ([bundles/foundation/core/src/host/models/providers.ts](../../bundles/foundation/core/src/host/models/providers.ts)).
- The store writes and answers providers in id order, each with its non-secret values in jsonb key order and its credential last ([bundles/foundation/host-config/src/host/config/store.ts](../../bundles/foundation/host-config/src/host/config/store.ts)). The core adopts the candidate it built only when the stored snapshot's providers are in that same form; otherwise it builds them again from the snapshot, so a replacement whose providers are not in that form, such as one that appends a provider whose id sorts before an existing one, builds them twice ([bundles/foundation/core/src/host/models/providers.ts](../../bundles/foundation/core/src/host/models/providers.ts)).
- At startup `host-config` activates the stored configuration's providers ([bundles/foundation/host-config/src/host/configuration.ts](../../bundles/foundation/host-config/src/host/configuration.ts)).
- The `openai` kind's provider reports the configured provider's id as its identity (`{ id, name }`, both the provider's id), so no kind asks for an identity as a field ([bundles/providers/openai/src/host/provider.ts](../../bundles/providers/openai/src/host/provider.ts), [bundles/providers/openai/src/host/kind.ts](../../bundles/providers/openai/src/host/kind.ts)).

### Model catalogs

- `models/v1.catalog({ kind, configuration })` answers `{ status: 'read', models }`, `{ status: 'absent' }` or `{ status: 'failed' }`. A catalog model is `{ id, name?, reasonings, parameters, defaultEffort?, mandatory }` ([packages/bundle/src/contracts/basic/models.ts](../../packages/bundle/src/contracts/basic/models.ts), [bundles/foundation/core/src/host/models/index.ts](../../bundles/foundation/core/src/host/models/index.ts)).
- `POST /providers/models` with `{ kind, configuration }` answers `{ models }`, the same catalog, for a surface that holds a draft; a catalog that answers `failed` or `absent` is `502 model_catalog_unreadable` ([bundles/foundation/transport/src/host/routes/providers.ts](../../bundles/foundation/transport/src/host/routes/providers.ts)).
- The `openrouter` catalog is its models URL: `modelsUrl` when set, else `<endpoint>/models`, else `https://openrouter.ai/api/v1/models`, below the default endpoint. It sends the secret as a `Bearer` token when there is one. Configuration and execution read the same URL ([bundles/providers/openrouter/src/host/catalog.ts](../../bundles/providers/openrouter/src/host/catalog.ts), [bundles/providers/openrouter/src/host/kind.ts](../../bundles/providers/openrouter/src/host/kind.ts)).
- The `claude` catalog is Anthropic's `/v1/models`, read through the provider itself with the same headers and endpoint a request uses; it is `absent` without a stored login. Each listed model takes the efforts its `capabilities.effort` marks supported, or, when the listing carries no capabilities, the ones its id names, and a default effort: `medium` on Opus and Haiku 5.5 and later, `high` elsewhere, when the model lists it, else its strongest listed effort, and none when it lists no effort ([bundles/providers/claude/src/host/kind.ts](../../bundles/providers/claude/src/host/kind.ts), [packages/llms/src/lib/providers/claude/models.ts](../../packages/llms/src/lib/providers/claude/models.ts)). [Provider sign-in](provider-sign-in.md) describes the login.
- `openai` and `codex` have no catalog and answer `absent` ([bundles/providers/openai/src/host/provider.ts](../../bundles/providers/openai/src/host/provider.ts)).

### The catalog fill

- On every replacement `host-config` reads each provider's catalog through `models/v1.catalog` and writes what it says into the configuration it stores ([bundles/foundation/host-config/src/host/config/service.ts](../../bundles/foundation/host-config/src/host/config/service.ts), [bundles/foundation/core/src/host/models/catalog.ts](../../bundles/foundation/core/src/host/models/catalog.ts)):
  - A provider that lists models gets, for each one, the efforts, the default effort and the `mandatory` flag its catalog entry gives; a model the catalog does not name gets no efforts. A provider that lists no models is not read.
  - A provider whose kind sets `modelsFromCatalog` (`claude`) is read even with no models, and its list becomes every model the catalog lists, in the catalog's order, each with its efforts and default.
  - A catalog that cannot be read leaves that provider exactly as it was. A kind with no catalog (`openai`) keeps the efforts the operator gave each model.
- The fill then resolves the default execution, `models.execution` (`{ providerId, model, effort? }`) ([bundles/foundation/core/src/host/models/catalog.ts](../../bundles/foundation/core/src/host/models/catalog.ts)):
  - A model that lists efforts keeps the effort the profile names, `none` included. A profile that names none takes the model's catalog default when it is one of its efforts, else its first effort other than `none`.
  - A model that lists no effort leaves the profile with no effort, so no request carries reasoning for it.
  - A provider whose kind keeps no `reasonings`, or a model the provider does not list, leaves the profile as it is.
- The `execution.providerId` must name a configured provider ([bundles/foundation/host-config/src/host/config/schema.ts](../../bundles/foundation/host-config/src/host/config/schema.ts)). A new top-level Thread copies the default execution; [Per-Thread model](per-thread-model.md) describes a Thread's own choice and the footer picker ([bundles/runtime/runtime/src/contracts/execution.ts](../../bundles/runtime/runtime/src/contracts/execution.ts)).

### On the provider page

- The page chooses the kind with a searchable combobox, and changing the kind starts the form over. Fields marked `advanced` wait under "Advanced settings" after the others ([bundles/desktop/settings/src/client/components/organisms/settings-provider.tsx](../../bundles/desktop/settings/src/client/components/organisms/settings-provider.tsx)).
- For a kind that declares `modelsUrl`, the page reads the draft's catalog through `models/v1.catalog` and draws it as a table that sorts, filters and pages, with a tick per model, a column per parameter the catalog advertises, the efforts each model names and a menu of visible columns. A model the provider lists that the catalog does not is drawn too, marked "Not in the catalog", and one can be added by name. The efforts are the catalog's, not edited by hand ([bundles/desktop/settings/src/client/components/molecules/provider-models-table.tsx](../../bundles/desktop/settings/src/client/components/molecules/provider-models-table.tsx), [bundles/desktop/settings/src/client/components/organisms/provider-model-picker.tsx](../../bundles/desktop/settings/src/client/components/organisms/provider-model-picker.tsx), [bundles/desktop/settings/src/client/domain/config.ts](../../bundles/desktop/settings/src/client/domain/config.ts), [bundles/desktop/settings/src/client/hooks/use-provider-catalog.ts](../../bundles/desktop/settings/src/client/hooks/use-provider-catalog.ts)).
- For a `modelsFromCatalog` kind the page offers no choice: before a credential is named it reads "The models this provider serves appear here once it is signed in; none is added by hand."; after, it reads the catalog, writes every listed model with its efforts and default into the draft, and shows the list read-only with "Reload models" ([bundles/desktop/settings/src/client/components/organisms/provider-catalog-models.tsx](../../bundles/desktop/settings/src/client/components/organisms/provider-catalog-models.tsx)).
- The Execution section starts a chosen model at its catalog default when that is not `none`, else its first effort other than `none`, and never leaves a model that offers reasoning at `none` ([bundles/desktop/settings/src/client/domain/config.ts](../../bundles/desktop/settings/src/client/domain/config.ts), [bundles/runtime/runtime/src/contracts/execution.ts](../../bundles/runtime/runtime/src/contracts/execution.ts)). [Settings](settings.md) describes the rest of the page and the section.

### Capacity and input modalities

- `models/v1.contextWindow({ providerId?, model })` and `models/v1.inputModalities({ providerId?, model })` read the catalog of the one candidate provider through the cached provider, which is built again only when its record was replaced. The candidates are the active configuration's providers whose kind reports `catalogCapacity()` (`openrouter`, `claude`) and that are `providerId` or, without one, list the model ([bundles/foundation/core/src/host/models/capacity.ts](../../bundles/foundation/core/src/host/models/capacity.ts), [bundles/foundation/core/src/host/models/registry.ts](../../bundles/foundation/core/src/host/models/registry.ts)).
- OpenRouter reports a model's `context_length` and `architecture.input_modalities`; Claude reports `max_input_tokens` and reads `capabilities.image_input` ([packages/llms/src/lib/providers/openrouter/models.ts](../../packages/llms/src/lib/providers/openrouter/models.ts), [packages/llms/src/lib/providers/claude.ts](../../packages/llms/src/lib/providers/claude.ts)). [Usage](usage.md) uses the capacity and [Attachments](attachments.md) the modalities.

### Requests

- The run's provider is `models/v1.resolve({ providerId, model, effort? })`, the active set's built provider; with no active set, a provider id the set does not hold, or a rebuild that fails, it throws `Configured provider is unavailable.` ([bundles/foundation/core/src/host/models/index.ts](../../bundles/foundation/core/src/host/models/index.ts), [bundles/foundation/core/src/host/models/providers.ts](../../bundles/foundation/core/src/host/models/providers.ts)).
- A request's top-level `effort` takes precedence over `flags.reasoning.effort` ([packages/llms/src/lib/providers/common.ts](../../packages/llms/src/lib/providers/common.ts)). OpenAI and Codex send it as `reasoning.effort`, and so does OpenRouter; with no effort and no reasoning flag they send no reasoning ([packages/llms/src/lib/providers/openai/body.ts](../../packages/llms/src/lib/providers/openai/body.ts), [packages/llms/src/lib/providers/codex.ts](../../packages/llms/src/lib/providers/codex.ts), [packages/llms/src/lib/providers/openrouter/body.ts](../../packages/llms/src/lib/providers/openrouter/body.ts)).
- Claude sends it as `output_config.effort`: `none` and `minimal` as `low`, a level the model lacks as `high` when the model has it, else as its strongest level, and nothing for a model that takes no effort (Haiku 4.5, Sonnet 4.5 and older) ([packages/llms/src/lib/providers/claude/models.ts](../../packages/llms/src/lib/providers/claude/models.ts), [packages/llms/src/lib/providers/claude/body.ts](../../packages/llms/src/lib/providers/claude/body.ts)).
- OpenAI and OpenRouter send a tool's `inputSchema` as the function's `parameters`, strict only when the tool asks for it and the schema is strict-compatible, and on OpenRouter only when the model's curated profile allows strict tools. Claude sends it as `input_schema`, never strict ([packages/llms/src/lib/providers/openai/body.ts](../../packages/llms/src/lib/providers/openai/body.ts), [packages/llms/src/lib/providers/openrouter/body.ts](../../packages/llms/src/lib/providers/openrouter/body.ts), [packages/llms/src/lib/providers/claude/body.ts](../../packages/llms/src/lib/providers/claude/body.ts)).
- Replay items are kept by provider: Claude tags its own, and the others replay only untagged items, so a history that switched providers replays only what the current one produced ([packages/llms/src/lib/providers/common.ts](../../packages/llms/src/lib/providers/common.ts), [packages/llms/src/lib/providers/claude/body.ts](../../packages/llms/src/lib/providers/claude/body.ts)).

### OpenAI

- `openai` talks to any endpoint that answers the OpenAI Responses API. Without a token it sends no auth header, which a compatible local endpoint may accept ([bundles/providers/openai/src/host/kind.ts](../../bundles/providers/openai/src/host/kind.ts), [packages/llms/src/lib/providers/openai.ts](../../packages/llms/src/lib/providers/openai.ts)).

### OpenRouter

- `openrouter` uses OpenRouter Chat Completions with curated profiles for OpenAI, Anthropic, Gemini, Gemma, DeepSeek, Kimi, Mistral, Qwen, Llama, xAI, GLM, Cohere and MiniMax ([packages/llms/src/lib/providers/openrouter/profiles.ts](../../packages/llms/src/lib/providers/openrouter/profiles.ts)).
- A built provider's `models()`, its model validation and its requests share one live catalog: fresh for 15 minutes, one refresh at a time with a 5-second timeout, the last good catalog kept when a refresh fails, and 30 seconds before a failed refresh is tried again. Each caller may cancel its own wait without cancelling the refresh ([packages/llms/src/lib/providers/openrouter/catalog.ts](../../packages/llms/src/lib/providers/openrouter/catalog.ts), [packages/llms/src/lib/providers/openrouter.ts](../../packages/llms/src/lib/providers/openrouter.ts)). `models/v1.catalog` does not use that cache: it reads the models URL on every call ([bundles/providers/openrouter/src/host/catalog.ts](../../bundles/providers/openrouter/src/host/catalog.ts)).
- The catalog states a model's capabilities: a request with tools or a schema reads the model's advertised parameters, and a model the endpoint does not list advertises none, so its tool request fails. The curated profile says what a catalog cannot: whether a tool schema may be strict, how much reasoning detail replays, and which labs cannot combine forced tool choice with reasoning. When the catalog cannot be read and none is cached, the curated profile decides whether the model takes tools and forced tool choice, and a schema is sent as a prompt ([packages/llms/src/lib/providers/openrouter/prepare.ts](../../packages/llms/src/lib/providers/openrouter/prepare.ts), [packages/llms/src/lib/providers/openrouter/catalog.ts](../../packages/llms/src/lib/providers/openrouter/catalog.ts)).
- It sends `parallel_tool_calls` only when the model advertises it. A request for sequential tool calls with tools also carries a system instruction to call at most one tool per response ([packages/llms/src/lib/providers/openrouter/prepare.ts](../../packages/llms/src/lib/providers/openrouter/prepare.ts)). It keeps `reasoning_details` for replay ([packages/llms/src/lib/providers/openrouter/body.ts](../../packages/llms/src/lib/providers/openrouter/body.ts)).
- A tool-free schema uses the model's JSON Schema output, else JSON object mode, else a schema prompt, and is validated locally with up to `maxStructuredOutputRepairs` corrections, two by default. Tools and a direct schema together are refused (`unsupported_structured_tools`) ([packages/llms/src/lib/providers/openrouter/prepare.ts](../../packages/llms/src/lib/providers/openrouter/prepare.ts), [packages/llms/src/lib/providers/openrouter.ts](../../packages/llms/src/lib/providers/openrouter.ts)).

### Claude

- `claude` sends Anthropic Messages with the Claude Code OAuth beta headers and the Claude Code user agent. The stored value goes as it is when it names its `Bearer` scheme, as `x-api-key` when it is a Console key (`sk-ant-api…`), and under `Bearer` otherwise ([packages/llms/src/lib/providers/claude.ts](../../packages/llms/src/lib/providers/claude.ts)).
- It keeps thinking on only on models that think by default, replays its own signed thinking blocks, marks the system prompt and the conversation for prompt caching, never sends `temperature`, and refuses embeddings and reranking ([packages/llms/src/lib/providers/claude/body.ts](../../packages/llms/src/lib/providers/claude/body.ts), [packages/llms/src/lib/providers/claude.ts](../../packages/llms/src/lib/providers/claude.ts)).
- A stream that ends without `message_stop` is a retryable `incomplete_stream` error. A refusal keeps no text, calls or replay. A tool block that a `max_tokens` stop cut off is never a call. A refused request's error carries Anthropic's own message, with `retryAfterMs` and `requestId` when the response names them ([packages/llms/src/lib/providers/claude.ts](../../packages/llms/src/lib/providers/claude.ts), [packages/llms/src/lib/providers/claude/parse.ts](../../packages/llms/src/lib/providers/claude/parse.ts)).

### Codex

- `codex` sends the stored authorization value to ChatGPT's Codex backend, the `chatGptAccountId` value, when set, as `ChatGPT-Account-ID` (the header's only source), and `fedramp: 'true'` as `X-OpenAI-Fedramp`; it never sends `temperature` ([packages/llms/src/lib/providers/codex.ts](../../packages/llms/src/lib/providers/codex.ts), [bundles/providers/codex/src/host/kind.ts](../../bundles/providers/codex/src/host/kind.ts)).

### Credentials

- `openai` may leave `token` out; `openrouter`, `claude` and `codex` require it. The core passes `''` when no credential is stored. An empty value fails an `openrouter` or `claude` request with `auth_missing`; `codex` sends the request without an auth header ([bundles/providers/openai/src/host/kind.ts](../../bundles/providers/openai/src/host/kind.ts), [bundles/foundation/core/src/host/models/index.ts](../../bundles/foundation/core/src/host/models/index.ts), [packages/llms/src/lib/providers/auth.ts](../../packages/llms/src/lib/providers/auth.ts), [packages/llms/src/lib/providers/openrouter/auth.ts](../../packages/llms/src/lib/providers/openrouter/auth.ts), [packages/llms/src/lib/providers/claude.ts](../../packages/llms/src/lib/providers/claude.ts), [packages/llms/src/lib/providers/codex.ts](../../packages/llms/src/lib/providers/codex.ts)).
- The configuration stores credential ids only. The core resolves a secret when a catalog is read and before each request, and its log of a failed catalog read names only the kind. The provider logs carry counts, model ids, finish reasons and token usage, not request or response bodies ([bundles/foundation/host-config/src/host/config/schema.ts](../../bundles/foundation/host-config/src/host/config/schema.ts), [bundles/foundation/core/src/host/models/index.ts](../../bundles/foundation/core/src/host/models/index.ts), [packages/llms/src/lib/providers/logging.ts](../../packages/llms/src/lib/providers/logging.ts)).

### Icons

- `models/v1.icons({ requests })` takes up to 64 requests, each `{ providerId, models }` or `{ kind, configuration, models }` with up to 1,000 names of up to 512 characters. It answers `{ svgs, answers }`: one `{ provider?, models }` per request, in order, and the SVG of each name used, at most 16,384 characters ([packages/bundle/src/contracts/basic/models.ts](../../packages/bundle/src/contracts/basic/models.ts)).
- The core asks the kind's record within 1000 ms. A request whose provider or kind is unknown, or whose record fails, is late or answers another number of models, answers no provider icon and `null` per model. It reads no secret and builds no provider ([bundles/foundation/core/src/host/models/icons.ts](../../bundles/foundation/core/src/host/models/icons.ts)).
- The set holds Claude, DeepSeek, Gemini, Gemma, Meta, OpenAI, OpenRouter and Qwen ([packages/llms/src/lib/icons/lobehub.ts](../../packages/llms/src/lib/icons/lobehub.ts), [packages/llms/src/lib/icons/index.ts](../../packages/llms/src/lib/icons/index.ts)).
- The window draws an SVG as a CSS mask of a `data:` URL, in the text color, never inserted into the document ([packages/desktop/src/svg-mask.ts](../../packages/desktop/src/svg-mask.ts)). The settings surfaces ask about drafts by kind and values; a provider with no own icon shows `ServerIcon` ([bundles/desktop/settings/src/client/domain/model-icons.ts](../../bundles/desktop/settings/src/client/domain/model-icons.ts), [bundles/desktop/settings/src/client/components/molecules/provider-icon.tsx](../../bundles/desktop/settings/src/client/components/molecules/provider-icon.tsx)). The [`chat`](../../bundles/desktop/chat/README.md) bundle asks by provider id for the model that answered a turn ([bundles/desktop/chat/src/client/api/model-icons.ts](../../bundles/desktop/chat/src/client/api/model-icons.ts)); [Conversation](conversation.md) describes the mark.

### Message-carried configuration

- The `config` package validates an agent configuration carried in message metadata, with a provider `baseUrl` and a model `effort` of the same seven values, with `reasoning` as another name for it; a model whose `effort` and `reasoning` differ is refused. No bundle or app of the host imports it ([packages/config/src/lib/config.ts](../../packages/config/src/lib/config.ts), [packages/config/README.md](../../packages/config/README.md)).
