# Feature: Delegation

- Status: `implemented`

## Problem

A large task is easier to finish when an agent can split it: hand a self-contained part to another agent, keep working while that part runs, and collect its result when it ends. The parts must run in parallel without one conversation absorbing the others, each part must be visible to the reader as a conversation of its own, and the agent that delegated must learn how each part ended without polling for it. In the conversation, the reader must tell another agent's instruction or result apart from their own prompts and reach the conversation it came from.

## Decisions

- A delegated part is a child Thread: a normal Thread of the same Project, with its parent's id as `parentThreadId` and `origin: 'agent'`. A child working for its parent is a subagent; it is no other kind of runtime, and the reader opens and reads it like any conversation.
- The `threads` bundle owns the delegation tools and skills. Its host part reaches the runtime only through `runtime.threads/v1`, scoped to the prompt each tool call runs under, and imports no host internals. Its client part reads a sender's name and Project from the optional `runtime.records/v1`.
- Every delegation control acts only on a direct child of the calling prompt's Thread, in the same Project, and only while that prompt is bound. A child gets its own history, never a copy of its parent's.
- A child's result reaches its parent by itself. The runtime delivers it the way the parent's state allows: into the prompt the parent is running, as a steer taken in at the next safe point (after the tool batch in flight, or before the final answer would end the turn); into the queue of an idle, stopping or paused parent; and never into a closing or terminal parent, which is not reopened.
- Only work the parent handed down reports back. A prompt keeps its source when the reader retries or continues it, so it reports to the parent again; a prompt whose source is not the parent never produces a result for the parent.
- The child's result text is redacted with the runtime's redaction list before it enters the parent's input.
- A spawn may name an agent, a model and an effort. The runtime stores them in the child's document as a snapshot taken at the spawn. A model or an effort the spawn does not name comes from the parent; an agent never does.
- The runtime, not the tool, checks a spawn's model and effort, before it creates anything. `thread-spawn` reads no configuration and no model list.
- An agent's instructions are stored with the child and never shown: the public Thread record carries the agent's name and source only. The runner reads the instructions from the stored document on every run.
- A delegated input is drawn as a block of its own, never as the reader's prompt. Chat owns the block type `chat.delegated-input/v1` and draws it itself; a bundle that registers a renderer for it draws it instead. The `threads` bundle registers one.
- An instruction from a parent starts open and a result starts closed; the reader's choice then stands.
- The reader does not write to an agent Thread: the runtime refuses the reader's prompt, steer and rewind, and the edit and removal of its queued input. In the window, the reader may watch it, pause it, continue a paused prompt, retry its last prompt, archive, restore and pin it, and delete it once it is archived.

## Current behavior and contracts

### The bundles

- [`threads`](../../bundles/features/threads/README.md) has a host part, which registers the eight delegation tools, and a client part, which draws delegated inputs and `thread-spawn` calls in the conversation. It requires `tools/v1`, `runtime.threads/v1`, `ui/v1` and `navigation/v1`, and may use `default.agents/v1`, `chat.views/v1` and `runtime.records/v1` ([manifest.json](../../bundles/features/threads/manifest.json), [src/host/part.ts](../../bundles/features/threads/src/host/part.ts), [src/client/index.ts](../../bundles/features/threads/src/client/index.ts)).
- [`runtime`](../../bundles/runtime/runtime/README.md) provides `runtime.threads/v1`, whose `RuntimeThreadControls` are the controls a running prompt has over its direct children; it creates children, runs them and delivers their results ([bundles/runtime/runtime/src/contracts/threads.ts](../../bundles/runtime/runtime/src/contracts/threads.ts), [bundles/runtime/runtime/src/host/domain/runner.ts](../../bundles/runtime/runtime/src/host/domain/runner.ts)).
- [`chat`](../../bundles/desktop/chat/README.md) draws the conversation, owns the block type `chat.delegated-input/v1` and the element `<chat-readonly-markdown>` ([bundles/desktop/chat/src/contracts/index.ts](../../bundles/desktop/chat/src/contracts/index.ts), [bundles/desktop/chat/src/client/index.ts](../../bundles/desktop/chat/src/client/index.ts)).
- The agents a spawn may name are defined by [`default`](../../bundles/runtime/default/README.md) through `default.agents/v1`; [Default agent](default-agent.md) describes them.

### The delegation tools

- The bundle registers eight tools as always available, at the model-visible orders 1000 to 1650: `thread-spawn` (1000), `thread-list` (1100), `thread-get` (1200), `thread-events` (1300), `thread-send` (1400), `thread-interrupt` (1500), `thread-terminate` (1600) and `thread-restart` (1650) ([src/host/part.ts](../../bundles/features/threads/src/host/part.ts)).
- Each tool calls `runtime.threads/v1` bound to its call's scope, and answers the result serialized as JSON; `thread-interrupt` answers the bare result ([src/host/threads.ts](../../bundles/features/threads/src/host/threads.ts), [src/host/tools/thread-interrupt.ts](../../bundles/features/threads/src/host/tools/thread-interrupt.ts)).

| Tool               | Input                                         | Behavior                                                                                                                                                                                                                                                                                                                                                                                           |
| ------------------ | --------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `thread-spawn`     | `{ prompt, title?, agent?, model?, effort? }` | Creates a child and queues `prompt` in it; answers `{ threadId, promptId }` at once ([src/host/tools/thread-spawn.ts](../../bundles/features/threads/src/host/tools/thread-spawn.ts)).                                                                                                                                                                                                             |
| `thread-list`      | `{ limit?, cursor? }`                         | A page of the direct children and their states; `limit` 1 to 100, default 50 ([src/host/tools/thread-list.ts](../../bundles/features/threads/src/host/tools/thread-list.ts)).                                                                                                                                                                                                                      |
| `thread-get`       | `{ threadId }`                                | The child's record and, once a prompt has finished, the result of its last finished prompt ([src/host/tools/thread-get.ts](../../bundles/features/threads/src/host/tools/thread-get.ts)).                                                                                                                                                                                                          |
| `thread-events`    | `{ threadId, afterSequence?, limit? }`        | A page of the child's events after an exclusive sequence, default 0; `limit` 1 to 50, default 20. Each event is digested to its sequence, type, prompt and a summary: its `text` or `delta`, else its JSON, cut to 400 characters and `…`. The page carries `nextSequence` when there is more ([src/host/tools/thread-events.ts](../../bundles/features/threads/src/host/tools/thread-events.ts)). |
| `thread-send`      | `{ threadId, prompt }`                        | Queues a follow-up in the child, without interrupting it, and answers the runtime's result; see the [runtime README](../../bundles/runtime/runtime/README.md) ([src/host/tools/thread-send.ts](../../bundles/features/threads/src/host/tools/thread-send.ts)).                                                                                                                                     |
| `thread-restart`   | `{ threadId, prompt? }`                       | Reopens a child whose Thread failed and queues `prompt`, or the last prompt the child accepted, and answers the runtime's result; see the [runtime README](../../bundles/runtime/runtime/README.md) ([src/host/tools/thread-restart.ts](../../bundles/features/threads/src/host/tools/thread-restart.ts)).                                                                                         |
| `thread-interrupt` | `{ threadId, promptId }`                      | Cancels that active prompt of the child; its queue, descendants and conversation stay. Answers the runtime's result; see the [runtime README](../../bundles/runtime/runtime/README.md) ([src/host/tools/thread-interrupt.ts](../../bundles/features/threads/src/host/tools/thread-interrupt.ts)).                                                                                                  |
| `thread-terminate` | `{ threadId }`                                | Closes the child and its descendants, cancelling active and queued work; history and the Project's sandbox stay ([src/host/tools/thread-terminate.ts](../../bundles/features/threads/src/host/tools/thread-terminate.ts)).                                                                                                                                                                         |

- Every input is strict: an unknown key fails the call. A `prompt` or `title` that is empty or only whitespace fails it too, `thread-restart`'s optional `prompt` included ([src/host/tools/thread-spawn.ts](../../bundles/features/threads/src/host/tools/thread-spawn.ts), [src/host/tools/thread-send.ts](../../bundles/features/threads/src/host/tools/thread-send.ts), [src/host/tools/thread-restart.ts](../../bundles/features/threads/src/host/tools/thread-restart.ts)).
- The runtime checks every control against the calling prompt: once that prompt's binding has ended, a control rejects with `Thread control is no longer active.`, and a Thread that is not a direct child of the caller in the same Project rejects with `Thread is not a direct child.` ([bundles/runtime/runtime/src/host/domain/runner.ts](../../bundles/runtime/runtime/src/host/domain/runner.ts), [bundles/runtime/runtime/src/contracts/threads.ts](../../bundles/runtime/runtime/src/contracts/threads.ts)).
- `thread-spawn`, `thread-send` and `thread-restart` queue their prompt with the source `{ kind: 'parent', threadId, promptId }`, naming the parent Thread and the calling prompt. The reader's retry queues the child's last prompt again with that prompt's own source, and continue resumes the same prompt, so a retried or continued prompt of the parent reports to the parent again, with its original `requestPromptId` ([bundles/runtime/runtime/src/host/domain/runner.ts](../../bundles/runtime/runtime/src/host/domain/runner.ts), [bundles/runtime/runtime/src/host/domain/service.ts](../../bundles/runtime/runtime/src/host/domain/service.ts)).

### The skills

- The bundle ships three skills: `thread-delegation` (order 3100, always available) delegates self-contained work and keeps working while children run; `thread-inspection` (3200) observes children through their events without disturbing them; `thread-steering` (3300) redirects or closes children with the narrowest control ([src/skills/thread-delegation/SKILL.md](../../bundles/features/threads/src/skills/thread-delegation/SKILL.md), [src/skills/thread-inspection/SKILL.md](../../bundles/features/threads/src/skills/thread-inspection/SKILL.md), [src/skills/thread-steering/SKILL.md](../../bundles/features/threads/src/skills/thread-steering/SKILL.md)).

### Spawning a child

- The child is named after `title`, else after the start of `prompt`, cut to 80 characters ([bundles/runtime/runtime/src/host/domain/runner.ts](../../bundles/runtime/runtime/src/host/domain/runner.ts), [bundles/runtime/runtime/src/contracts/model.ts](../../bundles/runtime/runtime/src/contracts/model.ts)).
- `agent` names an agent of `default.agents/v1`; the tool resolves it and passes its name, source and instructions to the runtime. Without a provider of `default.agents/v1`, a call that names an agent fails with `Agent types are unavailable in this runtime.`; a call that names none still spawns. A spawn without `agent` creates a plain child ([src/host/tools/thread-spawn.ts](../../bundles/features/threads/src/host/tools/thread-spawn.ts)).
- `model` and `effort` override the agent's own; without them the tool passes the agent's, and without those the runtime takes the parent's ([src/host/tools/thread-spawn.ts](../../bundles/features/threads/src/host/tools/thread-spawn.ts), [bundles/runtime/runtime/src/host/domain/runner.ts](../../bundles/runtime/runtime/src/host/domain/runner.ts)).
- The runtime spawns with `SpawnOptions` `{ agent?: { name, source, instructions }, model?, effort? }`. `source` is `built-in` or `workspace` and the instructions hold at most 64,000 characters; anything else fails the call's input validation before a Thread exists ([bundles/runtime/runtime/src/contracts/threads.ts](../../bundles/runtime/runtime/src/contracts/threads.ts)).
- The child runs on its parent's provider. It starts from the parent's stored model and effort: a spawn that names an effort takes it; a spawn that names another model alone takes that model's start effort; a spawn that names the parent's own model keeps the parent's effort. [Per-thread model](per-thread-model.md) describes the rules in full ([bundles/runtime/runtime/src/host/domain/runner.ts](../../bundles/runtime/runtime/src/host/domain/runner.ts)).
- When the spawn names a model or an effort, the runtime checks the result before it creates anything: against the models the provider lists (a provider that lists none accepts any), then through `models/v1.resolve`. A refusal rejects with a `ContractError` coded `invalid_execution` whose `details.issue` is `provider`, `model` or `effort`; a model `models/v1.resolve` cannot resolve rejects with that error. When the refused model came from the agent's definition, the tool's error names the agent and its model ([bundles/runtime/runtime/src/host/domain/runner.ts](../../bundles/runtime/runtime/src/host/domain/runner.ts), [bundles/runtime/runtime/src/host/domain/execution.ts](../../bundles/runtime/runtime/src/host/domain/execution.ts), [src/host/tools/thread-spawn.ts](../../bundles/features/threads/src/host/tools/thread-spawn.ts)).
- The runtime then creates the child with `origin: 'agent'`, the spawn's agent, the computed execution and the parent's `providerId`, stored in the child's `runtime.thread/v1` document, and queues the prompt ([bundles/runtime/runtime/src/host/domain/runner.ts](../../bundles/runtime/runtime/src/host/domain/runner.ts)).
- The public `Thread` record shows the agent's `name` and `source`, the `providerId`, the `model` and the `effort`, never the instructions ([bundles/runtime/runtime/src/host/store/threads.ts](../../bundles/runtime/runtime/src/host/store/threads.ts), [bundles/runtime/runtime/src/contracts/model.ts](../../bundles/runtime/runtime/src/contracts/model.ts)).
- On every run and every compaction of an agent Thread, the runner reads the instructions from the stored document and hands the executor the Thread with `agent.instructions`. A retry, a parent's send, a restart and a run after a host restart therefore use the same values. When no instructions are stored, the runner drops the agent and the Thread runs as the default agent ([bundles/runtime/runtime/src/host/domain/runner.ts](../../bundles/runtime/runtime/src/host/domain/runner.ts)).
- The runtime answers `forbidden` to the reader's `prompt`, `steer`, `rewind`, `editQueued` and `removeQueued` on an agent Thread, and to `delete` of one that is not archived. In the window, an agent Thread (`origin: 'agent'` with a `parentThreadId`) has no composer: its footer holds the three levers pause, continue and retry. A UI action sent from it is refused before it reaches the runtime. A bundle's `instruct` still reaches it ([bundles/runtime/runtime/src/host/domain/service.ts](../../bundles/runtime/runtime/src/host/domain/service.ts), [bundles/desktop/chat/src/client/views/chat-composer.tsx](../../bundles/desktop/chat/src/client/views/chat-composer.tsx), [bundles/desktop/chat/src/client/components/organisms/agent-thread-controls.tsx](../../bundles/desktop/chat/src/client/components/organisms/agent-thread-controls.tsx), [bundles/desktop/chat/src/client/services/send.ts](../../bundles/desktop/chat/src/client/services/send.ts), [Projects and Threads](projects-and-threads.md)).

### Results

- When a prompt of the child finishes, fails or is cancelled, the runtime stores it as the child's result; when the prompt's source is the parent, it also delivers it to the parent as a prompt of the source `{ kind: 'result', threadId, promptId, requestPromptId }`. A prompt of any other source delivers nothing ([bundles/runtime/runtime/src/host/domain/runner.ts](../../bundles/runtime/runtime/src/host/domain/runner.ts)).
- The text is a Markdown frame headed `# Delegated task result` that names the child Thread, the child prompt, the originating prompt and the status, followed by `## Result` and the child's final text ([bundles/runtime/runtime/src/host/domain/prompts.ts](../../bundles/runtime/runtime/src/host/domain/prompts.ts)).
- The child's text is redacted before it is framed, and the parent's accepted input is redacted again as it is stored, whether it is steered or queued ([bundles/runtime/runtime/src/host/domain/runner.ts](../../bundles/runtime/runtime/src/host/domain/runner.ts)).
- A parent running a prompt takes the result in as a steer at its next safe point; a parent that is idle runs it from its first-in, first-out queue; a parent that is stopping or paused queues it. Nothing is delivered to a closing or terminal parent, or within a closing Project ([bundles/runtime/runtime/src/host/domain/runner.ts](../../bundles/runtime/runtime/src/host/domain/runner.ts)).
- A parent's prompt removed from the child's queue delivers a `cancelled` result with the text `Removed from queue.` A parent's prompt interrupted by a host restart after it was already resumed twice closes `failed`, with the text of `resumeExhaustedError`, and that result is queued in the parent unless the parent is terminal, cancelling or in another Project ([bundles/runtime/runtime/src/host/domain/prompts.ts](../../bundles/runtime/runtime/src/host/domain/prompts.ts), [bundles/runtime/runtime/src/host/domain/runner.ts](../../bundles/runtime/runtime/src/host/domain/runner.ts), [bundles/runtime/runtime/src/host/store/threads.ts](../../bundles/runtime/runtime/src/host/store/threads.ts), [bundles/runtime/runtime/src/host/domain/service.ts](../../bundles/runtime/runtime/src/host/domain/service.ts)).

### In the conversation

- The chat turns a prompt whose source is `parent` or `result` into a delegated input `{ kind, threadId, status?, text }`: an instruction's text as written, a result's text without the host's frame, with the frame's status. The same durable events feed a live transcript and a replay ([bundles/desktop/chat/src/client/domain/delegated.ts](../../bundles/desktop/chat/src/client/domain/delegated.ts), [bundles/desktop/chat/src/client/domain/projector-input.ts](../../bundles/desktop/chat/src/client/domain/projector-input.ts)).
- A delegated input is a conversation node of its own, not a reader's turn, so it carries no author line of the reader ([bundles/desktop/chat/src/client/components/organisms/conversation/plugins/insert-thread-turn-nodes.tsx](../../bundles/desktop/chat/src/client/components/organisms/conversation/plugins/insert-thread-turn-nodes.tsx)).
- The node hosts the element a bundle registered for `chat.delegated-input/v1`, handing it the block `{ type: 'chat.delegated-input/v1', id, data: { promptId, input } }` and its focus, and passing the toggle key to its `toggle()`; without a registered renderer it draws the same block itself. A renderer registered for the prompt's input source takes precedence over the delegated-input renderer ([bundles/desktop/chat/src/client/components/organisms/conversation/nodes/delegated-turn-node.tsx](../../bundles/desktop/chat/src/client/components/organisms/conversation/nodes/delegated-turn-node.tsx), [bundles/desktop/chat/src/contracts/index.ts](../../bundles/desktop/chat/src/contracts/index.ts)).
- While `chat.views/v1` is served, the `threads` bundle registers `<threads-delegated-turn>` as that renderer ([src/client/index.ts](../../bundles/features/threads/src/client/index.ts)).
- The block is a collapsible block (`desktop/ui/collapsible-block`, [packages/desktop/src/collapsible-block.tsx](../../packages/desktop/src/collapsible-block.tsx)). Its header reads `Instruction from:` or `Result from:`, and an instruction's header begins with an 18-pixel agent icon; a result's has none. The prefix never wraps, and a chevron after the sender shows whether the block is open. The prefix and the chevron toggle the block. The sender's name follows, without quotes: its name when `runtime.records/v1` holds the Thread, as a link that opens its conversation; else the first eight characters of its id, in monospace, as plain text. Its tooltip is the full Thread id. The name truncates with an ellipsis, and its click does not toggle the block ([src/client/delegated-turn.tsx](../../bundles/features/threads/src/client/delegated-turn.tsx), [src/client/source.ts](../../bundles/features/threads/src/client/source.ts), [src/client/domain/delegated.ts](../../bundles/features/threads/src/client/domain/delegated.ts)).
- Open, the block shows `Status: <status>` when the result recorded one, and the text as read-only Markdown through `<chat-readonly-markdown>`, which writes `No message content.` for a text that is empty or only whitespace ([src/client/delegated-turn.tsx](../../bundles/features/threads/src/client/delegated-turn.tsx), [bundles/desktop/chat/src/client/components/organisms/conversation/readonly-markdown.tsx](../../bundles/desktop/chat/src/client/components/organisms/conversation/readonly-markdown.tsx)).
- An instruction starts open and a result starts closed. The mouse and the toggle key (Enter on the selected block) change one open state, kept by the element, or by the chat's node when chat draws the block itself, which survives updates of the transcript ([src/client/delegated-turn.tsx](../../bundles/features/threads/src/client/delegated-turn.tsx), [bundles/desktop/chat/src/client/components/organisms/conversation/nodes/delegated-turn-node.tsx](../../bundles/desktop/chat/src/client/components/organisms/conversation/nodes/delegated-turn-node.tsx), [bundles/desktop/chat/src/client/components/organisms/conversation/plugins/caret-navigation.tsx](../../bundles/desktop/chat/src/client/components/organisms/conversation/plugins/caret-navigation.tsx)).
- The bundle also draws each `thread-spawn` call as `<threads-spawn-call>`, a block of its own outside the activity group. It reads "Spawning", "Spawned" or "Spawn failed", links the child once it exists, and shows the agent, model and effort the call names and the prompt handed down, with the failure notice when the call failed. It is open while it spawns and when it failed, and closed once the child exists ([src/client/index.ts](../../bundles/features/threads/src/client/index.ts), [src/client/spawn-call.tsx](../../bundles/features/threads/src/client/spawn-call.tsx)).
- The client also registers a projector that claims the event types `threads.asked/v1` and `threads.answered/v1` and draws nothing for them, so a Thread whose log holds them replays without a block. When another bundle has claimed them first, its projection stands ([src/client/old-asks.ts](../../bundles/features/threads/src/client/old-asks.ts), [src/client/index.ts](../../bundles/features/threads/src/client/index.ts)).
