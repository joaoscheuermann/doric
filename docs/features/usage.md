# Feature: Usage

- Status: `implemented`

## Problem

A Thread spends money and context with every model call, and so do the child Threads it delegates to. The reader needs to see, at a glance, how full the selected Thread's context window is and roughly what the Thread and its whole subtree have cost, without opening each child. A cost the provider never reported must not look free, and a context capacity the measurement lacks should still be found when a model catalog knows it. The reader also needs to compact the context by hand and to move the point at which Doric compacts it on its own.

## Decisions

- The usage aggregate stays in the `runtime` bundle's Thread document, folded in the same commit as the event that changes it, while no other bundle needs to share that transaction. The `usage` bundle reads that projection and draws the UI; it stores nothing of its own.
- `usage/v1` reuses the runtime's shapes: its contracts module re-exports `ThreadUsage`, `UsageTotals` and `ContextUsage` from `runtime/contracts`, and `usage/v1.thread` answers `threadUsageSchema`.
- The capacity fill asks `models/v1.contextWindow` only when the projection has a `context` without `contextWindow`, sends `providerId` only when the measurement has one, accepts only a finite capacity above 0, and treats a failed call as no answer. A recorded capacity is never replaced. The `core` bundle chooses the candidate provider.
- `ThreadUsage.threads` lists the requested Thread first, then its descendants level by level, each level in creation order.
- A rewind changes the context but never refunds a call that has already run.
- A missing price is not zero: a call with no reported cost counts as unpriced, and a total with an unpriced call is partial. Cached and reasoning tokens are details of the input and output counts, never added to them again.
- The footer item is registered by the `usage` bundle's own client activation, as the region item `usage` with the order 30 in the `layout` bundle's region `shell.conversation.footer` ([layout README](../../bundles/desktop/layout/README.md)).
- The client read keeps one identifier guard and one set of messages (`The thread was not found.` for an unknown Thread, `Doric backend is unavailable.` for a lost connection), and gives the reads and settings writes a 10-second deadline and a compaction five minutes. The bundle's query client has no retry and no focus or reconnect refetch by default; the usage query sets its own: every 3 seconds, on window focus, stale after 1 second, 2 retries.
- The host's `GET /threads/:id/usage` calls `usage/v1` through the platform's services, and the `transport` bundle lists `usage/v1` only in `optional`, so the host keeps running when the `usage` bundle is disabled or quarantined.
- Deleting a Thread deletes its accounting with it.

The full contract is in the bundle's [README](../../bundles/features/usage/README.md). A process entry, [src/host/main.ts](../../bundles/features/usage/src/host/main.ts), serves `usage/v1` in a bundle process (slice S50c of [grpc-processes](../designs/grpc-processes.md)); the manifest is unchanged until S62.
- The `runtime` bundle holds the aggregate and answers it, unfilled, through `runtime.usage/v1.read(threadId)` ([bundles/runtime/runtime/src/contracts/usage.ts](../../bundles/runtime/runtime/src/contracts/usage.ts), [bundles/runtime/runtime/src/host/services/usage.ts](../../bundles/runtime/runtime/src/host/services/usage.ts); [README](../../bundles/runtime/runtime/README.md)).
- The `core` bundle answers `models/v1.contextWindow` from the cached catalogs of the configured providers ([bundles/foundation/core/src/host/models/capacity.ts](../../bundles/foundation/core/src/host/models/capacity.ts); [README](../../bundles/foundation/core/README.md)).
- The `openrouter` provider kind reports its catalog's context capacity (`catalogCapacity: true`) and prices its calls in credits ([bundles/providers/openrouter/src/host/kind.ts](../../bundles/providers/openrouter/src/host/kind.ts), [packages/llms/src/lib/providers/openrouter/parse.ts](../../packages/llms/src/lib/providers/openrouter/parse.ts); [README](../../bundles/providers/openrouter/README.md)).
- The `claude` provider kind also reports its catalog's context capacity (`catalogCapacity: true`), but reports no price, so its calls count as unpriced ([bundles/providers/claude/src/host/kind.ts](../../bundles/providers/claude/src/host/kind.ts), [packages/llms/src/lib/providers/claude.ts](../../packages/llms/src/lib/providers/claude.ts); [README](../../bundles/providers/claude/README.md)).
- The `default` bundle's executor records the provider events of each run, `response.started` among them ([bundles/runtime/default/src/host/executor.ts](../../bundles/runtime/default/src/host/executor.ts); [README](../../bundles/runtime/default/README.md)).
- The `postgres` bundle holds the document store whose JSONB value keeps each Thread document ([bundles/foundation/postgres/prisma/schema.prisma](../../bundles/foundation/postgres/prisma/schema.prisma); [README](../../bundles/foundation/postgres/README.md)).
- The `chat` bundle puts two items in the same footer region: its execution picker at the order 20, before the usage summary, and its composer at the order 40, after it. ### The aggregate

- `ThreadUsage` holds the Thread's `context` (the last measured model and provider, the capacity and the measured input tokens), a `total`, and one entry in `threads` per Thread of the subtree with its own calls, unpriced calls, cost and token counts. The full shape is in the [usage README](../../bundles/features/usage/README.md#data-shapes) ([bundles/runtime/runtime/src/contracts/model.ts](../../bundles/runtime/runtime/src/contracts/model.ts)).
- Each Thread document stores its usage state as JSON in the document store's JSONB value: the completed totals, one replaceable snapshot of the current call, and the context. An event append folds `response.started`, `usage` and `response.finished` events into it in the same commit as the events ([bundles/runtime/runtime/src/host/store/threads.ts](../../bundles/runtime/runtime/src/host/store/threads.ts), [bundles/runtime/runtime/src/host/store/usage.ts](../../bundles/runtime/runtime/src/host/store/usage.ts), [bundles/foundation/postgres/prisma/schema.prisma](../../bundles/foundation/postgres/prisma/schema.prisma)).
- `response.started` closes the previous call into the completed totals and opens a new one. It sets the context's `model`, its `providerId` and, when the event carries one above 0, its `contextWindow`; the context keeps its earlier values only when the model and provider are the same. A `usage` or `response.finished` event replaces the current call's token counts and cost rather than adding to them, so a repeated snapshot never charges twice; its input tokens become the context's `inputTokens`. A `response.started` without a string `model` closes the previous call and clears the context, opening no call; a `usage` or `response.finished` event with no open call changes nothing ([bundles/runtime/runtime/src/host/store/usage.ts](../../bundles/runtime/runtime/src/host/store/usage.ts)).
- The fold reads every provider's calls with their tokens, whatever the `provider` field of `response.started` names. Only a cost in the unit `credits` counts as a price; OpenRouter reports it. A call of any other provider, or a call interrupted before it reported a cost, counts in `unpricedCalls`. Doric asks no provider for a cost after the call ([bundles/runtime/runtime/src/host/store/usage.ts](../../bundles/runtime/runtime/src/host/store/usage.ts), [packages/llms/src/lib/providers/openrouter/parse.ts](../../packages/llms/src/lib/providers/openrouter/parse.ts)).
- The `default` bundle's executor adds the Thread's `providerId` to every `response.started` it records. The OpenRouter and Claude providers add the catalog's `contextWindow` to `response.started` when their catalog knows it ([bundles/runtime/default/src/host/executor.ts](../../bundles/runtime/default/src/host/executor.ts), [packages/llms/src/lib/providers/openrouter.ts](../../packages/llms/src/lib/providers/openrouter.ts), [packages/llms/src/lib/providers/claude.ts](../../packages/llms/src/lib/providers/claude.ts)).
- A Thread document with no stored usage derives it from its event log on each read, and the next usage event stores the result ([bundles/runtime/runtime/src/host/store/threads.ts](../../bundles/runtime/runtime/src/host/store/threads.ts)).
- A rewind keeps every charge already made, as completed totals, and takes the context from the events that survive the rewind ([bundles/runtime/runtime/src/host/store/threads.ts](../../bundles/runtime/runtime/src/host/store/threads.ts), [bundles/runtime/runtime/src/host/store/usage.ts](../../bundles/runtime/runtime/src/host/store/usage.ts)).
- A read covers the Thread and every existing descendant, opened or not: `threads` lists the Thread first, then its descendants level by level, each level in creation order, each with its own charges; `total` sums them; `context` is the Thread's own ([bundles/runtime/runtime/src/host/store/threads.ts](../../bundles/runtime/runtime/src/host/store/threads.ts), [bundles/runtime/runtime/src/host/store/usage.ts](../../bundles/runtime/runtime/src/host/store/usage.ts)).
- Deleting a Thread deletes the documents and event streams of its whole subtree, and with them their usage ([bundles/runtime/runtime/src/host/store/threads.ts](../../bundles/runtime/runtime/src/host/store/threads.ts)).

### The `usage/v1` contract

Every method is exposed to the desktop; the inputs, outputs and full behavior of each are in the [usage README](../../bundles/features/usage/README.md#contract-usagev1) ([src/contracts/index.ts](../../bundles/features/usage/src/contracts/index.ts), [src/host/usage.ts](../../bundles/features/usage/src/host/usage.ts)).

| Method                                     | Behavior                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| ------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `thread(threadId)`                         | Reads `runtime.usage/v1.read` and fills a missing capacity (below). `undefined` when the Thread does not exist.                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| `compact(threadId)`                        | Compacts one idle Thread through `runtime.threads/v1.compact` and answers its `CompactResult` unchanged: `compacted`, `refused` with a reason, `failed` with a code, or a status for a Thread it cannot compact, `busy` among them ([shape](../../bundles/features/usage/README.md#data-shapes)).                                                                                                                                                                                                                                                            |
| `compactionTarget()`                       | Answers `{ pressurePercent }`, the share of the context window at which the executor compacts, from the configuration in force (`host-config/v1`); a configuration without the section answers the default, 80.                                                                                                                                                                                                                                                                                                                                              |
| `setCompactionTarget({ pressurePercent })` | Writes the value into the configuration's `execution.contextCompaction`; a configuration without the section gets the default section with the new value ([behavior](../../bundles/features/usage/README.md#behavior-of-each-method)). A refused replacement answers the value the configuration still holds. The configuration accepts a whole number from 50 to 95 ([bundles/foundation/host-config/src/host/config/schema.ts](../../bundles/foundation/host-config/src/host/config/schema.ts); [README](../../bundles/foundation/host-config/README.md)). |

### The capacity fill

- When the stored context has no `contextWindow`, `usage/v1.thread` asks `models/v1.contextWindow` with the measured model, and with the measurement's `providerId` when it has one. A finite answer above 0 becomes the context's `contextWindow`, with `contextWindowSource: 'catalog'`; any other answer, or a failed call, leaves the capacity unknown ([src/host/usage.ts](../../bundles/features/usage/src/host/usage.ts)).
- `models/v1.contextWindow` looks for exactly one candidate among the configured providers whose kind reports `catalogCapacity`: the provider the measurement names, or, without one, the providers that list the model. With exactly one, it reads that provider's cached catalog; otherwise it answers nothing. It never throws ([bundles/foundation/core/src/host/models/capacity.ts](../../bundles/foundation/core/src/host/models/capacity.ts)).
- `runtime.threads/v1.usage` answers the same aggregate, filled by the runtime from the configured providers of the kind `openrouter` only ([bundles/runtime/runtime/src/host/domain/service.ts](../../bundles/runtime/runtime/src/host/domain/service.ts), [bundles/runtime/runtime/src/host/domain/usage-context.ts](../../bundles/runtime/runtime/src/host/domain/usage-context.ts)).

### Reaching it

- `GET /threads/:id/usage` answers `usage/v1.thread` with `Cache-Control: no-store`: a 400 `invalid_thread_id` for an invalid id, a 404 `thread_not_found` when the Thread does not exist, and a 500 `internal_error` when the call fails, as it does while no `usage/v1` provider serves the host ([bundles/foundation/transport/src/host/routes/threads.ts](../../bundles/foundation/transport/src/host/routes/threads.ts), [bundles/foundation/transport/src/host/routes/input.ts](../../bundles/foundation/transport/src/host/routes/input.ts), [bundles/foundation/transport/src/host/errors.ts](../../bundles/foundation/transport/src/host/errors.ts); [README](../../bundles/foundation/transport/README.md)).
- The window calls `usage/v1` over Connect, through the generated `UsageService` (slice S65d): the client part's calls go over `window.doric.connect` and the platform channel `doric:connect` to Electron main's `createConnectRelay`, which checks the sender, the `doric-client-part`, the method and its scope, and forwards them to the host. The bundle declares no desktop part of its own ([packages/desktop/src/client/connect.ts](../../packages/desktop/src/client/connect.ts), [app/desktop/doric/src/app/api/preload.ts](../../app/desktop/doric/src/app/api/preload.ts), [app/desktop/doric/src/platform/bridge/connect-relay.ts](../../app/desktop/doric/src/platform/bridge/connect-relay.ts); [how the window reaches `usage/v1`](../../bundles/features/usage/README.md#how-the-window-reaches-usagev1)).

### In the footer

- `<usage-summary>` shows the Thread that `workspace.selection/v1` names as selected, and nothing while none is selected. It mounts again when the selection changes ([src/client/components/usage-summary.tsx](../../bundles/features/usage/src/client/components/usage-summary.tsx), [src/client/api/workspace.ts](../../bundles/features/usage/src/client/api/workspace.ts); [workspace README](../../bundles/desktop/workspace/README.md)).
- It reads `usage/v1.thread` every 3 seconds and on window focus ([src/client/hooks/use-thread-usage.ts](../../bundles/features/usage/src/client/hooks/use-thread-usage.ts)). A failed read keeps the last values on the buttons and shows no message of its own; it shows only as `Usage could not be refreshed.` in the context tooltip and `Could not refresh costs.` in the cost popover ([src/client/components/thread-usage.tsx](../../bundles/features/usage/src/client/components/thread-usage.tsx)).
- The footer does not show where a capacity came from: no client code reads `contextWindowSource` ([src/client/components/thread-usage.tsx](../../bundles/features/usage/src/client/components/thread-usage.tsx)).
- The summary holds two buttons, the context and the cost, after `chat`'s execution picker; spacing alone separates the picker, the context and the cost ([src/client/components/thread-usage.tsx](../../bundles/features/usage/src/client/components/thread-usage.tsx), [bundles/desktop/layout/src/client/components/templates/conversation-frame.tsx](../../bundles/desktop/layout/src/client/components/templates/conversation-frame.tsx)).
- The context button reads `<used> / <capacity> · <percent>%` in compact numbers, with no prefix; `<used> / ?` when the capacity is unknown, `— / <capacity>` when no measurement exists and `—` when neither does ([src/client/domain/usage.ts](../../bundles/features/usage/src/client/domain/usage.ts)).
- The cost button reads `~$<total>` with two decimals, `~<$0.01` for a positive total below one cent, and `—` with no calls or when no call has a price. A partial total carries ` *` ([src/client/domain/usage.ts](../../bundles/features/usage/src/client/domain/usage.ts), [src/client/components/thread-usage.tsx](../../bundles/features/usage/src/client/components/thread-usage.tsx)).
- While no `usage/v1` provider serves the window, the context button has a tooltip instead of a popover: `Usage could not be refreshed.` after a failed read, `Waiting for an OpenRouter measurement.` otherwise ([src/client/components/thread-usage.tsx](../../bundles/features/usage/src/client/components/thread-usage.tsx)).

### The context popover

- The popover, `Context Window`, shows a bar of the used share of the capacity, and on it one vertical drag handle at the compaction percentage. The bar is empty while the capacity or the measurement is unknown. The handle moves from 50 % to 95 % of the full bar, by whole percents; it is disabled until the target loads and while a save runs, and saves the value through `setCompactionTarget` when it is released, on an arrow, Home, End or page key, or on blur; a failed save puts the handle back and shows the error. Under the bar it shows the used and capacity tokens and `Compact at` with the threshold in tokens, or in percent when the capacity is unknown. When the target fails to load, the popover shows the error, and `Compact at` and `Compaction threshold` show `—` ([src/client/components/thread-usage.tsx](../../bundles/features/usage/src/client/components/thread-usage.tsx), [src/client/domain/read.ts](../../bundles/features/usage/src/client/domain/read.ts)).
- A failure to load or save the target, or of `Compact Now`, shows one message in the popover's status note: `The item identifier is invalid.` for an invalid Thread id, `The compaction target must be a whole 50–95 percent.` for a target out of range, `Doric backend is unavailable.` when the bridge is lost, `Doric returned an invalid response.` for an invalid answer, and `The request could not be completed.` otherwise ([src/client/domain/read.ts](../../bundles/features/usage/src/client/domain/read.ts)).
- `Context Breakdown`, collapsed at first, lists `Used context`, `Available space`, `Context window` and `Compaction threshold`. An unknown value shows `—`; the breakdown counts no tokens per category ([src/client/components/thread-usage.tsx](../../bundles/features/usage/src/client/components/thread-usage.tsx)).
- `Compact Now` calls `usage/v1.compact` with a 5-minute deadline and shows the answer as one sentence: the messages condensed and the estimated tokens freed, the reason of a refusal, the code of a failure, `Wait for the active run (and the queued input) to finish.` for a busy Thread, or `This thread cannot be compacted.` for any other answer ([src/client/domain/read.ts](../../bundles/features/usage/src/client/domain/read.ts)).

### The cost popover

- The popover shows `Current Thread` with the Thread's own charges, then `Sub Threads` with the subtotal of all its descendants, each with its cost, its calls and its compact input and output token counts behind arrow icons. Cached and reasoning tokens are not shown. A `Total` row closes it on a shaded footer ([src/client/components/cost-breakdown.tsx](../../bundles/features/usage/src/client/components/cost-breakdown.tsx), [src/client/domain/usage.ts](../../bundles/features/usage/src/client/domain/usage.ts)).
- `Sub Threads` is collapsed at first and disabled without descendants. Its toggle shows `ChevronsUpDown` to open and `ChevronsDownUp` to close. Open, it shows a shaded list, without scrolling, of each descendant's title, truncated with an ellipsis, with its own cost, calls and token counts, aligned with the rows above ([src/client/components/cost-breakdown.tsx](../../bundles/features/usage/src/client/components/cost-breakdown.tsx)).
- A partial cost carries an asterisk; the explanation `Partial: <n> calls have no reported cost.` is its hover title and its screen-reader text ([src/client/components/cost-breakdown.tsx](../../bundles/features/usage/src/client/components/cost-breakdown.tsx)).
- With no calls the popover says `No reported usage yet.`; after a failed read it says `Could not refresh costs.` ([src/client/components/thread-usage.tsx](../../bundles/features/usage/src/client/components/thread-usage.tsx)).
