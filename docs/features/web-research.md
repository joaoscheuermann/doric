# Feature: Web research

- Status: `implemented`

## Problem

The agent's knowledge stops at its training data and at the Project's files. When an answer depends on a current library, API, specification or page, the agent needs to search the web, read a page as text and find the exact passage that supports a claim. It also needs to know when to do that and how to treat what it finds, so that a search snippet is not taken as evidence.

## Decisions

- The `web` bundle has a host part only. It requires only `tools/v1@^1.2.0` and publishes no contract of its own.
- The `web` tool is always available, at the model-visible order 700, between `tree` and `write`. The `web-research` skill has the order 1200.
- The `web-research` skill is registered once every host bundle of the activation phase has activated, so its `allowed-tools` entry `web` resolves against the whole `tools/v1` catalog.
- The tool's requests run in the generation process, with that process's global `fetch`; the tool never touches the Project's sandbox.

## Current behavior and contracts

### The bundle

- The `web` bundle, version 1.0.0, provides nothing and requires `tools/v1@^1.2.0` ([manifest.json](../../bundles/features/web/manifest.json)). Its contracts module exports nothing ([src/contracts/index.ts](../../bundles/features/web/src/contracts/index.ts)). Its overview is its [README](../../bundles/features/web/README.md).
- The host's composition enables `web`. Like every installed bundle, it runs in a process of its own, whose entry is `src/host/main.ts` ([bundle processes](bundle-processes.md), [app/backend/doric-host/composition.json](../../app/backend/doric-host/composition.json), [src/host/main.ts](../../bundles/features/web/src/host/main.ts), [app/backend/doric-host/src/lib/bundles/boot.ts](../../app/backend/doric-host/src/lib/bundles/boot.ts)).
- On activation the bundle registers one tool, `web`, through `tools/v1`, with `alwaysAvailable: true` and `order: 700`, using the global `fetch` ([src/host/part.ts](../../bundles/features/web/src/host/part.ts), [src/host/tools/web.ts](../../bundles/features/web/src/host/tools/web.ts)). The [`core` bundle](../../bundles/foundation/core/README.md) provides `tools/v1` and lists tools by `order`, then by registration ([bundles/foundation/core/src/host/tools/service.ts](../../bundles/foundation/core/src/host/tools/service.ts)). The neighbours of 700 are the [`files` bundle](../../bundles/features/files/README.md)'s `tree` (600) and `write` (800) ([bundles/features/files/src/host/tools/catalog.ts](../../bundles/features/files/src/host/tools/catalog.ts)).
- The bundle ships one skill, `src/skills/web-research/SKILL.md`. The bundle loader finds it under the built bundle's `skills/` directory ([packages/bundle/src/loader/skills.ts](../../packages/bundle/src/loader/skills.ts)). The host SDK registers it through `skills/v1` as the bundle's instance, from `context.assets` ([packages/bundle/src/sdk/host/skills.ts](../../packages/bundle/src/sdk/host/skills.ts)). Its frontmatter sets no `alwaysAvailable`, so it is registered as not always available ([packages/bundle/src/sdk/host/skills.ts](../../packages/bundle/src/sdk/host/skills.ts)).
- `skills/v1` checks each `allowed-tools` name against the `tools/v1` list the call sees and rejects a skill that names a missing tool with `unavailable_tool` ([bundles/foundation/core/src/host/skills/service.ts](../../bundles/foundation/core/src/host/skills/service.ts)).

### The `web` tool

- Description: `Search the web, open HTTP(S) pages as extracted text, or find literal text in a page.` ([src/host/tools/web.ts](../../bundles/features/web/src/host/tools/web.ts)).
- Input (strict): `{ action, query?, url?, pattern?, ignoreCase?, limit?, maxChars? }`, where `action` is `search`, `open_page` or `find_in_page`, and `limit` and `maxChars` are non-negative integers ([src/host/tools/web.ts](../../bundles/features/web/src/host/tools/web.ts)). The tool-call layer validates the payload before the tool runs and rejects an invalid one, unknown keys included, with a `ToolErrorObject` of code `invalid_payload` ([packages/tool/src/lib/tools.ts](../../packages/tool/src/lib/tools.ts)).
- Output (strict): `{ action, detail, results, page?, matches, total, truncated, error? }`. `results` holds `{ title, url, snippet }` items, `page` is `{ url, title, text }`, and `matches` holds `{ line, text }` items ([src/host/tools/web.ts](../../bundles/features/web/src/host/tools/web.ts)).
- `search` trims `query` and fetches `https://duckduckgo.com/html/?q=<query>`. It reads each result link's title and URL and the snippet at the same position; a DuckDuckGo redirect URL is replaced by its `uddg` target, and a protocol-relative URL gets `https:`. A result whose URL is empty is dropped. `limit` defaults to 5 and is clamped to 1–10. `detail` is the query, `total` the number of results kept, and `truncated` is true when that number exceeds the limit ([src/host/tools/web.ts](../../bundles/features/web/src/host/tools/web.ts), [tests/router.test.ts](../../bundles/features/web/tests/router.test.ts)).
- `open_page` accepts only an `http:` or `https:` URL. It returns `page` with the requested URL, the page's title and its extracted text, cut to `maxChars`, which defaults to 12,000 and is clamped to 1–50,000; `truncated` says whether the text was cut, `total` is 1 and `detail` is the URL. Redirects follow `fetch`'s default, and `page.url` is the requested URL, normalized, not the final one. The response body is read whole, with no size limit; `maxChars` applies only to the extracted text ([src/host/tools/web.ts](../../bundles/features/web/src/host/tools/web.ts)).
- The title is the content of the first `<title>` element with its tags removed, entities decoded and whitespace collapsed; titles and snippets of search results are cleaned the same way ([src/host/tools/web.ts](../../bundles/features/web/src/host/tools/web.ts), [tests/router.test.ts](../../bundles/features/web/tests/router.test.ts)).
- The extracted text drops the `<head>` and every `script`, `style` and `noscript` element, breaks lines at `<br>` and at the end of `p`, `div`, `li`, `h1`–`h6` and `tr`, removes the remaining tags, decodes numeric entities and `&amp;`, `&lt;`, `&gt;`, `&quot;`, `&apos;`, `&#39;` and `&nbsp;`, trims each line, collapses runs of spaces and tabs, and drops empty lines. It then removes all whitespace, newlines included, before `.`, `,`, `;`, `:`, `!` and `?`, so a line that starts with one of them joins the line before ([src/host/tools/web.ts](../../bundles/features/web/src/host/tools/web.ts), [tests/router.test.ts](../../bundles/features/web/tests/router.test.ts)).
- `find_in_page` takes an `http:` or `https:` URL and a trimmed, non-empty `pattern`. It searches the page's extracted text line by line for the literal pattern, case-insensitively unless `ignoreCase` is `false`, and returns each matching line with its 1-based line number. `limit` defaults to 20 and is clamped to 1–100. Counting stops at the first match past the limit: `truncated` is then true and `total` is the limit plus one; otherwise `total` is the number of matching lines. `detail` is `'<pattern>' in <url>` ([src/host/tools/web.ts](../../bundles/features/web/src/host/tools/web.ts), [tests/router.test.ts](../../bundles/features/web/tests/router.test.ts)).
- Every request sends a desktop Chrome `user-agent` header and is aborted after 20 seconds. The request is not tied to the prompt's abort signal ([src/host/tools/web.ts](../../bundles/features/web/src/host/tools/web.ts), [tests/router.test.ts](../../bundles/features/web/tests/router.test.ts)).
- A missing argument or a failed request is returned as output: `error` is set, `detail` is empty, the lists are empty, `total` is 0 and `truncated` false. The messages are `Missing query for search`, `Missing or invalid URL for open_page`, `Missing or invalid URL for find_in_page`, `Missing pattern for find_in_page`, `Request returned HTTP <status>` for a response that is not OK, `Request failed: timed out after <ms>ms` for the timeout, and `Request failed: <message>` for any other fetch failure ([src/host/tools/web.ts](../../bundles/features/web/src/host/tools/web.ts), [tests/router.test.ts](../../bundles/features/web/tests/router.test.ts)).
- A numeric entity above the last Unicode code point, such as `&#9999999;`, in text the action decodes (a search result's title or snippet, the page's `<title>`, or its body text) makes the tool throw `RangeError: Invalid code point`. The tool-call layer turns the throw into a `ToolErrorObject` of code `handler_failed` ([src/host/tools/web.ts](../../bundles/features/web/src/host/tools/web.ts), [packages/tool/src/lib/tools.ts](../../packages/tool/src/lib/tools.ts)).

### The `web-research` skill

- The skill `web-research` allows only the tool `web` and has the order 1200. Its description tells the agent to use it when the goal depends on facts or documentation not present in the workspace or the supplied context ([src/skills/web-research/SKILL.md](../../bundles/features/web/src/skills/web-research/SKILL.md), [tests/skill.test.ts](../../bundles/features/web/tests/skill.test.ts)).
- The [`default` bundle](../../bundles/runtime/default/README.md) lists the skills that are not always available in the built-in part of its skill catalog, in `skills/v1` order, so the order 1200 sets the skill's position there. The agent reads its body through `load_skill` ([bundles/runtime/default/src/host/skills/sources.ts](../../bundles/runtime/default/src/host/skills/sources.ts), [bundles/runtime/default/src/host/skills/catalog.ts](../../bundles/runtime/default/src/host/skills/catalog.ts)).
- The body is the search-open-find procedure: define the fact to find; `search` with a focused query, preferring official or primary sources; open the relevant pages instead of relying on titles or snippets; use `find_in_page` for exact terms, versions or headings in long pages; check date, scope and version and compare independent sources when a fact is uncertain; keep the source's title, URL and supporting passage, separate from inference; and narrow the query or the page range when output is truncated ([src/skills/web-research/SKILL.md](../../bundles/features/web/src/skills/web-research/SKILL.md)).
