# Feature: Context compaction

- Status: `implemented`

## Problem

A Thread's conversation grows with every prompt, tool result and answer, and the model reads all of it on every call. Sooner or later the history exceeds the model's context window, and a run fails or a resumed run cannot start. The agent needs the older part of its history condensed into a summary it can continue from, without losing the reader's view of the whole conversation, without breaking a tool call from its result, and without dropping the standing instructions it was given. The reader needs to see when this happens, to read what the model was given instead, to set when it happens and to ask for it on demand.

## Decisions

- On-demand compaction runs only on an idle Thread, under the Project's mutation lock. The runner's own state (the active prompt and the input queue) is what keeps a compaction and a run apart; the log is not scanned for an open bracket. A `compaction.started` with no closing event in the log is the readable sign of an interrupted compaction.
- The write order is fixed: `compaction.started` is recorded alone, before the summary is generated and before any rewrite; then one `PromptSession.record` call saves the rewritten history first and appends `compaction.finished` after it. The two writes are not one atomic commit: a crash before that call leaves the bracket open in the log and the history unchanged, and a crash between its two writes leaves the rewritten history saved with `compaction.started` open and no `compaction.finished`.
- A compaction drops the turn boundary of every prompt whose boundary falls inside the condensed span, so a rewind to such a prompt answers `unknown_prompt`: the summary is never undone. The boundaries that survive are re-based across the removed messages.
- A refusal decided before the bracket opens (`missing`, `inactive`, `busy`, `not_supported`, `disabled`, `missing_history`, `nothing_to_compact`) records nothing. A failure after the bracket opened records `compaction.failed` with a code from the closed set `summarizer_failed` and `unsafe_boundary`, and the optional `error` behind it.
- The summary is a `user` message whose text starts with the stable marker line `[Context summary]`. Being text, it survives storage, serialization and every provider, and it stays readable for the model.
- `tokensFreed` is an estimate, and the result says so.
- A manual compaction of a Thread whose stored provider or model is not available fails as `summarizer_failed`.
- When the provider reports a context overflow, the executor condenses the history at once, without measuring, so that the next resume starts condensed; the run still fails with the provider's error. The turn is not retried within the same run.
- A compaction always condenses from the start of the history: there is no compaction of an explicit region. There is no pruning of tool results and no offloading of images, and a single unit that cannot be split (a tool call with its results) larger than the window is not condensed.

## Current behavior and contracts

### The units

- The `default` bundle's executor (`executor/v1` 1.5.0) condenses the history: automatically during a run, and on demand through its `compact` method. The full shape of planning, summarizing and rewriting is in the [`default` README](../../bundles/runtime/default/README.md#compaction) ([manifest.json](../../bundles/runtime/default/manifest.json), [src/host/compact.ts](../../bundles/runtime/default/src/host/compact.ts)).
- The `runtime` bundle serves the on-demand compaction as `runtime.threads/v1.compact({ id })` (1.8.0) and calls the executor's `compact` through `executor/v1` ([`runtime` README](../../bundles/runtime/runtime/README.md#runtimethreadsv1), [bundles/runtime/runtime/src/host/domain/runner.ts](../../bundles/runtime/runtime/src/host/domain/runner.ts), [bundles/runtime/runtime/src/contracts/executor.ts](../../bundles/runtime/runtime/src/contracts/executor.ts)).
- The `chat` bundle draws each compaction as a row of the transcript ([`chat` README](../../bundles/desktop/chat/README.md), [bundles/desktop/chat/src/client/domain/projector.ts](../../bundles/desktop/chat/src/client/domain/projector.ts)).
- The `usage` bundle offers the reader `Compact Now` and the compaction target in the footer's context popover; see [usage.md](usage.md#the-context-popover) and the [`usage` README](../../bundles/features/usage/README.md#contract-usagev1) ([bundles/features/usage/src/host/usage.ts](../../bundles/features/usage/src/host/usage.ts)).
- The `transport` bundle serves `ThreadsService.Compact`, which replaced `POST /threads/:id/compact` in slice S69, over the same `runtime.threads/v1.compact` ([`transport` README](../../bundles/foundation/transport/README.md), [bundles/foundation/transport/src/host/api/operations/threads.ts](../../bundles/foundation/transport/src/host/api/operations/threads.ts)).

### Settings

- The policy is the configuration's optional `execution.contextCompaction`, which holds five required fields: `enabled`, `pressurePercent`, `tailMinMessages`, `summaryMaxChars` and `charBudget`. An absent section stands for the defaults, `pressurePercent` 80 among them; the ranges of each field are in [The configuration](../../bundles/foundation/host-config/README.md#the-configuration) and the defaults in [Shapes](../../bundles/foundation/host-config/README.md#shapes) of the `host-config` README ([bundles/foundation/host-config/src/contracts/index.ts](../../bundles/foundation/host-config/src/contracts/index.ts), [bundles/foundation/host-config/src/host/config/schema.ts](../../bundles/foundation/host-config/src/host/config/schema.ts), [src/host/compact.ts](../../bundles/runtime/default/src/host/compact.ts)).
- `pressurePercent` is the compaction target the reader reads and sets with the drag handle of the context popover, through `usage/v1.compactionTarget` and `usage/v1.setCompactionTarget`; see [usage.md](usage.md#the-usagev1-contract) ([bundles/features/usage/src/host/usage.ts](../../bundles/features/usage/src/host/usage.ts), [bundles/features/usage/src/client/components/thread-usage.tsx](../../bundles/features/usage/src/client/components/thread-usage.tsx)).
- With `enabled` false, nothing is condensed: a run never compacts, and `compact` answers `refused` with `disabled` ([src/host/compact.ts](../../bundles/runtime/default/src/host/compact.ts)).

### What is condensed

- The model reads the Thread's provider history, the executor's `default.history/v1` state: `messages`, and `meta` with the turn boundary of each prompt (`checkpoints`) and the index of each retained message (`retained`). A compaction rewrites only that history. The Thread's event log keeps every event, so the conversation the reader sees stays whole ([src/host/history.ts](../../bundles/runtime/default/src/host/history.ts), [src/host/compact.ts](../../bundles/runtime/default/src/host/compact.ts)).
- The condensed span always starts at the first message and ends at the largest safe boundary that leaves at least `tailMinMessages` messages after it. A boundary is safe when no assistant tool call has its request on one side and its result on the other. A tool result whose call is missing ends the scan: no boundary after it is safe ([src/host/compaction/compact.ts](../../bundles/runtime/default/src/host/compaction/compact.ts), [src/host/compaction/rewrite.ts](../../bundles/runtime/default/src/host/compaction/rewrite.ts), [src/host/compaction/boundaries.ts](../../bundles/runtime/default/src/host/compaction/boundaries.ts)).
- An empty history is refused as `missing_history`. When no safe boundary above the first message fits, or when the span holds only earlier summaries and retained messages, the compaction is refused as `nothing_to_compact`, before any summary is generated or any event recorded ([src/host/compaction/compact.ts](../../bundles/runtime/default/src/host/compaction/compact.ts)).

### Automatic compaction

- A run measures the pressure before its first provider call, counting the input it is about to send, and again after every `response.finished`. It never measures on a `usage` event that arrives while the provider is still streaming, so a condensation never rewrites the history a turn is answering ([src/host/executor.ts](../../bundles/runtime/default/src/host/executor.ts)).
- With a context window known from the last `response.started`, the projection is the last response's input tokens (the history's characters / 4 when none was reported) plus its output tokens plus the pending input's characters / 4, and pressure exists when it reaches `pressurePercent` % of the window. Without a window, the history's and the pending input's characters / 4 are compared with `pressurePercent` % of `charBudget` ([src/host/compaction/project.ts](../../bundles/runtime/default/src/host/compaction/project.ts), [src/host/executor.ts](../../bundles/runtime/default/src/host/executor.ts)).
- Under pressure the run condenses with the Thread's resolved provider and model. A refusal records nothing; a failure records `compaction.failed` and the run goes on with its history uncondensed. A stop during the summarization is such a failure: it records `compaction.failed` with `summarizer_failed` ([src/host/compact.ts](../../bundles/runtime/default/src/host/compact.ts)).
- After a condensation the run carries on with the rewritten messages, boundaries and retained indexes, and its next check of agents and skills compares with its system prompt again, so a change the summary replaced is told again; see [skills.md](skills.md) and [default-agent.md](default-agent.md) ([src/host/executor.ts](../../bundles/runtime/default/src/host/executor.ts)).

### Context overflow

- A provider error, in an `error` event of the stream or thrown by the run, reads as a context overflow when its `message`, `code` or `diagnostic`, or those of its `data`, name the context window, length or overflow, too many tokens, the maximum context, input tokens that exceed a limit, or a prompt that is too long. The match is textual ([src/host/compaction/project.ts](../../bundles/runtime/default/src/host/compaction/project.ts)).
- On such an error the run condenses once, without measuring the pressure; a second overflow in the same run does not condense again. The run then fails with the provider's error ([src/host/executor.ts](../../bundles/runtime/default/src/host/executor.ts)).

### Manual compaction

> **2026-11-27, slice S69:** `transport`'s REST routes and Socket.IO namespaces are removed; these operations answer over `doric.api.*` ([`ThreadsService`](../../bundles/foundation/transport/proto/doric/api/threads/v1/threads.proto) `Compact`) with the same refusal codes and messages. The REST wording of this section is rewritten in phase 8 of [the spec](../designs/grpc-processes.md).

- The reader asks for a compaction with `Compact Now` in the context popover, which calls `usage/v1.compact` with a five-minute deadline, since summarizing is a model generation; the popover's reads and its target writes keep a ten-second deadline. `usage/v1.compact` calls `runtime.threads/v1.compact`. The popover's sentence for each answer is described in [usage.md](usage.md#the-context-popover) ([bundles/features/usage/src/client/domain/read.ts](../../bundles/features/usage/src/client/domain/read.ts), [bundles/features/usage/src/client/components/thread-usage.tsx](../../bundles/features/usage/src/client/components/thread-usage.tsx), [bundles/features/usage/src/host/usage.ts](../../bundles/features/usage/src/host/usage.ts)).
- `POST /threads/:id/compact` reaches the same method. It answers `200` with the counts of a compaction, `404 thread_not_found` for an unknown Thread, and an HTTP error for every other outcome, a refusal and a failure each with an error code of its own; the mapping is in the [`transport` README](../../bundles/foundation/transport/README.md#routers) ([bundles/foundation/transport/src/host/api/operations/threads.ts](../../bundles/foundation/transport/src/host/api/operations/threads.ts)).
- `runtime.threads/v1.compact` answers `missing` for an unknown Thread, and takes the Project's mutation lock. Under it, a Thread that is not live, or whose Project or itself is closing or has ended, answers `inactive`; a Thread with an active prompt or queued input answers `busy`; a history whose format the executor does not read answers `not_supported`. Otherwise the runner records the compaction under a prompt id of its own, a UUID, with no prompt job, and passes the executor the policy's `tailMinMessages` and `summaryMaxChars`. The lock is held until the executor answers, so every other mutation of the Project, a prompt to another of its Threads included, waits for the summarization. Nothing cancels a manual compaction: the runner passes a signal it never aborts, and a caller's deadline does not stop it on the host ([bundles/runtime/runtime/src/host/domain/service.ts](../../bundles/runtime/runtime/src/host/domain/service.ts), [bundles/runtime/runtime/src/host/domain/runner.ts](../../bundles/runtime/runtime/src/host/domain/runner.ts)).
- The executor's `compact` summarizes with the Thread's resolved provider and model, without effort, and answers `compacted` with the summary id and the counts, `refused` with its reason, or `failed` with its code ([src/host/compact.ts](../../bundles/runtime/default/src/host/compact.ts), [bundles/runtime/runtime/src/contracts/executor.ts](../../bundles/runtime/runtime/src/contracts/executor.ts)).

### The summary and the rewrite

- The summarizer reads the span without its retained messages, as a transcript of user, assistant and tool-result blocks, of which only the tail is kept past `summaryMaxChars` × 8 characters. The model is asked for a Markdown summary an agent can resume from with no other memory. An empty answer fails as `summarizer_failed`; a longer one than `summaryMaxChars` is cut at a line break and marked `[summary truncated]` ([src/host/compaction/summarize.ts](../../bundles/runtime/default/src/host/compaction/summarize.ts)).
- Before the rewrite, the cut is checked again against the messages the plan read; the history is not read a second time. A cut that splits a tool call from its result fails as `unsafe_boundary` ([src/host/compaction/compact.ts](../../bundles/runtime/default/src/host/compaction/compact.ts)).
- The summary message takes the span's place. It reads `[Context summary]`, then a line naming the trigger and the condensed range, then the summary. After it come the span's retained messages, verbatim and in order, then the "Loaded skills" message when there is one, then the kept tail in its order without its `thinking` and `redacted_thinking` replay items ([src/host/compaction/markers.ts](../../bundles/runtime/default/src/host/compaction/markers.ts), [src/host/compaction/rewrite.ts](../../bundles/runtime/default/src/host/compaction/rewrite.ts)).
- The boundaries inside the span are dropped, and the later boundaries and the retained indexes are re-based to where their messages now sit ([src/host/compaction/rewrite.ts](../../bundles/runtime/default/src/host/compaction/rewrite.ts)).
- `tokensFreed` is ⌊(characters of the condensed messages, plus the replaced "Loaded skills" message) / 4⌋ minus ⌊(characters of the whole summary message, plus the new "Loaded skills" message) / 4⌋, never below zero ([src/host/compaction/rewrite.ts](../../bundles/runtime/default/src/host/compaction/rewrite.ts)).

### Retained messages

- A bundle instruction given with `retain` (`runtime.threads/v1.instruct`, see [prompt-control.md](prompt-control.md)) is a standing instruction. When a run stores it, the executor records its index in `meta.retained` under the key `<bundleId>:<reason>` ([src/host/executor.ts](../../bundles/runtime/default/src/host/executor.ts), [src/host/history.ts](../../bundles/runtime/default/src/host/history.ts)).
- A compaction keeps every retained message of the span except `default:loaded-skills` verbatim after the summary and leaves it out of the summarizer's input ([src/host/compaction/rewrite.ts](../../bundles/runtime/default/src/host/compaction/rewrite.ts), [src/host/compaction/compact.ts](../../bundles/runtime/default/src/host/compaction/compact.ts)).
- A rewind forgets every retained message past its boundary, so that instruction can be given again ([src/host/history.ts](../../bundles/runtime/default/src/host/history.ts)).
- The skills loaded in the span stay in effect through one retained `default:loaded-skills` message, which a later compaction replaces rather than keeps; see [skills.md](skills.md#loaded-skills-across-a-compaction) ([src/host/skills/loaded.ts](../../bundles/runtime/default/src/host/skills/loaded.ts)).

### Events

- Every compaction is bracketed on the Thread's log. `{ type: 'compaction.started', trigger }`, with `trigger` `automatic` or `manual`, is recorded before the summary is generated. A success records the rewritten history and `compaction.finished`, with the summary id, the whole summary and the counts, in one `PromptSession.record` call, which saves the history and then appends the event. A failure records `compaction.failed` with its `code` and `error`. The payload of each event is in the [`default` README](../../bundles/runtime/default/README.md#compaction). Any error after the bracket opens that is not `unsafe_boundary`, a storage failure included, is recorded as `compaction.failed` with `summarizer_failed` when storage accepts that event ([src/host/compact.ts](../../bundles/runtime/default/src/host/compact.ts), [bundles/runtime/runtime/src/host/domain/session.ts](../../bundles/runtime/runtime/src/host/domain/session.ts)).
- After a crash between the two writes, the next run reads the rewritten history, summary first; the chat keeps the open bracket as a shimmering `Compacting` row; and a later compaction plans over the rewritten history like any other ([src/host/compact.ts](../../bundles/runtime/default/src/host/compact.ts), [src/host/executor.ts](../../bundles/runtime/default/src/host/executor.ts), [bundles/runtime/runtime/src/host/domain/session.ts](../../bundles/runtime/runtime/src/host/domain/session.ts), [bundles/desktop/chat/src/client/domain/projector.ts](../../bundles/desktop/chat/src/client/domain/projector.ts), [bundles/desktop/chat/src/client/components/organisms/conversation/nodes/compaction-turn-node.tsx](../../bundles/desktop/chat/src/client/components/organisms/conversation/nodes/compaction-turn-node.tsx)).
- A storage error on the append of `compaction.finished` leaves the rewritten history saved, and the compaction records `compaction.failed` with `summarizer_failed` in place of the owed `compaction.finished`. When storage accepts that event, a manual `compact` answers `{ status: 'failed', code: 'summarizer_failed' }`, and a run goes on with its messages uncondensed: its next history save, at the latest the one it makes when it ends, replaces the rewritten history. When storage rejects it too, `runtime.threads/v1.compact` fails with the storage error and no retry runs, so the bracket stays open over the rewritten history; a run ends on the storage error. If storage is full or low (a free-space check finds 10 % or less of the disk free, or the write fails with `ENOSPC`), the run's Thread pauses, and resuming its queue runs the session's retry: it saves the last history the run recorded, then appends `compaction.failed`. After a compaction between turns that history is the run's uncondensed one; after a compaction before the run's first provider call it is the rewritten one, since the run has saved no other history by then. Any other storage error during a run closes its Thread as `persistence_failed` ([src/host/compact.ts](../../bundles/runtime/default/src/host/compact.ts), [src/host/executor.ts](../../bundles/runtime/default/src/host/executor.ts), [src/host/deltas.ts](../../bundles/runtime/default/src/host/deltas.ts), [bundles/runtime/runtime/src/host/domain/session.ts](../../bundles/runtime/runtime/src/host/domain/session.ts), [bundles/runtime/runtime/src/host/domain/runner.ts](../../bundles/runtime/runtime/src/host/domain/runner.ts), [bundles/runtime/runtime/src/host/domain/storage-pause.ts](../../bundles/runtime/runtime/src/host/domain/storage-pause.ts), [bundles/runtime/runtime/src/host/domain/storage-pressure.ts](../../bundles/runtime/runtime/src/host/domain/storage-pressure.ts)).
- In `compaction.finished`, `summaryId` is `compaction-<uuid>`; `summary` is the whole summary message; `retainedMessages` is the number of messages the rewritten history holds ([src/host/compaction/compact.ts](../../bundles/runtime/default/src/host/compaction/compact.ts), [src/host/compaction/rewrite.ts](../../bundles/runtime/default/src/host/compaction/rewrite.ts)).
- Automatic events belong to the running prompt; manual ones to the compaction's own prompt id ([src/host/executor.ts](../../bundles/runtime/default/src/host/executor.ts), [bundles/runtime/runtime/src/host/domain/runner.ts](../../bundles/runtime/runtime/src/host/domain/runner.ts)).

### Rewind after a compaction

- A rewind to a prompt whose boundary was condensed away finds no boundary, and the runtime answers `unknown_prompt`. A rewind to a later prompt truncates the rewritten history at its re-based boundary ([src/host/history.ts](../../bundles/runtime/default/src/host/history.ts), [bundles/runtime/runtime/src/host/store/threads.ts](../../bundles/runtime/runtime/src/host/store/threads.ts), [bundles/runtime/runtime/src/host/domain/runner.ts](../../bundles/runtime/runtime/src/host/domain/runner.ts)).

### In the conversation

- The chat turns each bracket into one compaction row, where the prompt's log holds it. `compaction.started` shows a shimmering `Compacting` row at once, and the closing event updates the same row; a bracket the log never closes stays a shimmering `Compacting` row, and a closing event with no open bracket draws nothing ([bundles/desktop/chat/src/client/domain/projector.ts](../../bundles/desktop/chat/src/client/domain/projector.ts), [bundles/desktop/chat/src/client/components/organisms/conversation/nodes/compaction-turn-node.tsx](../../bundles/desktop/chat/src/client/components/organisms/conversation/nodes/compaction-turn-node.tsx)).
- A completed row reads `Context compacted · <n> messages → summary (<tokens> tokens freed)`, or `Context compacted` when the event carries no counts. Its label, with the expansion icon right after it, expands the summary sent to the model as read-only Markdown with a Copy button; a row whose event carries no summary reads `The summary of this older compaction was not kept in the history.` The summary comes from the row's own `compaction.finished`, so a later compaction does not change it ([bundles/desktop/chat/src/client/domain/projector.ts](../../bundles/desktop/chat/src/client/domain/projector.ts), [bundles/desktop/chat/src/client/components/organisms/conversation/nodes/compaction-turn-node.tsx](../../bundles/desktop/chat/src/client/components/organisms/conversation/nodes/compaction-turn-node.tsx)).
- A failed row shows the error notice of its code, `summarizer_failed` or `unsafe_boundary`, with the cause the event carries when there is one ([bundles/desktop/chat/src/client/domain/projector.ts](../../bundles/desktop/chat/src/client/domain/projector.ts), [bundles/desktop/chat/src/client/domain/error-catalog.ts](../../bundles/desktop/chat/src/client/domain/error-catalog.ts)).
- The compaction row is read-only: nobody can type into it ([bundles/desktop/chat/src/client/domain/conversation-nodes.ts](../../bundles/desktop/chat/src/client/domain/conversation-nodes.ts)).
