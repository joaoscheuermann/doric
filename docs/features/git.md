# Feature: Git

- Status: `implemented`

## Problem

The agent works in Git repositories inside its Project's sandbox: it clones, commits, rebases, resolves conflicts, pushes and manages worktrees. It needs a way to run Git that cannot hang on a prompt or an editor and whose output stays readable. The reader needs to see what the agent changed, compare each changed file with `HEAD`, discard changes, see the working directory and branch of the selected Thread, switch to another local branch without risking work in progress, and choose the identity the agent commits with.

## Decisions

- `git.commands/v1` reads of a Thread run on the live Thread through `runtime.workspace/v1.withThread`, and reads of a Project run on the Project's current lease through `runtime.lease/v1.withLease`. None acquires a lease, and a Thread or lease state (`missing`, `inactive`, `pending`, `unavailable`, `expired`) is an answer, never a failure.
- `status` runs without the Project mutation lock and refreshes the Thread's repository hint (`git` or `github`, which the runtime keeps for the root of the Thread's working directory). `branches`, `switchBranch` and `discard` run under the Project mutation lock, so no new prompt starts while they run.
- The branch switch only checks out an existing local branch, with `git switch --no-guess`. It never forces, stashes, creates a branch or fetches. Every refusal is a `refused` answer with the sentence the window shows.
- Running work blocks a branch switch and a Discard. Running work is the working directory of every Thread of the Project with an active or queued prompt, and of every terminal of `terminal/v1.list` that has not exited and is either an agent terminal or a manual shell whose current command is not `bash`. `terminal/v1` is optional: without a provider, only prompts block.
- A branch switch is blocked when running work is in the same repository root as the Thread's working directory. A Discard is blocked when running work is in the repository, in a directory inside it or in a directory above it.
- A Discard cannot be undone, so every guard runs before the first write, and the first guard that fails answers `refused` with nothing written.
- The Changes view, the Changes tab's badge and the Files tree's marks share one changes read per Project and working directory. The changes read carries status and line totals only; no file content or patch reaches the window. One file's content is read only when its comparison opens.
- Line totals compare `HEAD` with the working tree, count untracked files against empty content, and count a binary file as 0 lines. In a repository whose branch has no commit yet, every listed file counts against empty content.
- A directory's mark summarizes the changes under it: untracked counts as added, a mix of statuses is modified, and a conflict anywhere under it makes it conflicted.
- `git` provides `files.decorations/v1`, the contract `files` declares, so `files` names no `git` contract. `git` takes the `files.*` contracts it uses by id.
- The Files column footer holds only the working directory and branch. The line totals sit on the Changes tab, shown only when a line was added or removed.
- The `git` tool runs Git from an argument array, never through a shell, with the environment `GIT_TERMINAL_PROMPT=0`, `GIT_EDITOR=true`, `GIT_SEQUENCE_EDITOR=true` and `GCM_INTERACTIVE=Never`. It takes no credential: authentication comes from what the runtime applies to the sandbox.
- A finished `git` tool call in a conversation the window holds asks for its Project's refresh, through `chat.hooks/v2` of the [`chat`](../../bundles/desktop/chat/README.md) bundle; without `chat.hooks/v2` nothing asks.

### The `git` tool

- The tool `git` is registered with `tools/v1` as not always available, at the model-visible order 900 ([src/host/index.ts](../../bundles/features/git/src/host/index.ts)).
- Input: `{ args, working_directory?, timeout_ms? }`. `args` holds 1 to 128 strings of at most 8,192 characters each and runs as `git <args>`. A missing or blank `working_directory` is the Thread's current working directory; a relative one resolves against it. `timeout_ms` defaults to 120,000 and is capped at 600,000 ([src/host/tools/git.ts](../../bundles/features/git/src/host/tools/git.ts)).
- The working directory must stay under the sandbox root. Once the working directory and the sandbox are known, a directory outside the root and a sandbox command that rejects answer `exit_code` -1 with stderr `Failed to execute Git in sandbox: <reason>`. A command that ends with no exit code answers `exit_code` -1 with Git's own output. When reading the working directory or reaching the sandbox fails, the tool call itself fails ([src/host/tools/git.ts](../../bundles/features/git/src/host/tools/git.ts)).
- Output, schema `git.command.v1`: `working_directory`, `exit_code`, `duration_ms`, `success` (exit code 0), and `stdout` and `stderr`, each `{ bytes, text, truncated, omitted_bytes }`. A stream of at most 24,000 bytes is returned whole; a longer one keeps its first and last 12,000 bytes around a line `[<n> bytes omitted]` ([src/host/tools/git.ts](../../bundles/features/git/src/host/tools/git.ts)).
- The tool reaches the working directory through `runtime.workspace/v1.cwd` and the sandbox through `runtime.lease/v1` in the calling prompt's scope ([src/host/sandbox.ts](../../bundles/features/git/src/host/sandbox.ts)).
- Six skills name `git` in their `allowed-tools`: `git-cloning`, `git-commit-preparation`, `git-conflict-resolution`, `git-rebase`, `git-remote-synchronization` and `git-worktrees`, at the orders 2100 to 2600. The bundle loader reads them from `src/skills/<name>/SKILL.md` ([src/skills](../../bundles/features/git/src/skills), [packages/bundle/src/loader/skills.ts](../../packages/bundle/src/loader/skills.ts)).
- When a `tool.finished` event of the tool `git` reaches the window through `chat.hooks/v2.onThreadUpdateHook`, the client asks for the Thread's Project refresh ([src/client/tool-refresh.ts](../../bundles/features/git/src/client/tool-refresh.ts), [src/client/index.ts](../../bundles/features/git/src/client/index.ts)).

### `git.commands/v1`

`git.commands/v1` 1.2.0 is the host service the window reads Git through. Every method is exposed to the desktop, with the scope fields `projectId`, `threadId` and `promptId`. The host's REST routes call the same service: `GET /threads/:id/git`, `GET` and `POST /threads/:id/branches`, and `GET /projects/:id/changes`, `/diff` and `/files/diff` ([src/contracts/index.ts](../../bundles/features/git/src/contracts/index.ts), [src/host/service.ts](../../bundles/features/git/src/host/service.ts), [bundles/foundation/transport/src/host/routes/threads.ts](../../bundles/foundation/transport/src/host/routes/threads.ts), [bundles/foundation/transport/src/host/routes/projects.ts](../../bundles/foundation/transport/src/host/routes/projects.ts)). The [`git` README](../../bundles/features/git/README.md) holds the full shapes of the service, the host's [Routes](../../app/backend/doric-host/README.md#routes) tables those of the routes, and the [`transport` README](../../bundles/foundation/transport/README.md#routers) how each route answers.

| Method                                           | What it answers                                                                                                                                                                                                                                                        |
| ------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `status(threadId)`                               | The Thread's Git summary: `{ repo: false }`, or the repository root, `head`, `detached`, `unborn`, `upstream`, `ahead`, `behind`, the staged, modified and untracked counts, `conflicted`, the operation in progress, `worktree`, `shallow`, `stash` and `submodules`. |
| `branches(threadId)`                             | The local branches (`name`, `current`, short `commit`, `subject`, the `worktree` path that holds it) and, when switching is not possible, `blocked` with the reason.                                                                                                   |
| `switchBranch({ threadId, branch, cwd })`        | The branches after the switch, or `refused` with a sentence.                                                                                                                                                                                                           |
| `discard({ threadId, cwd, repository, paths? })` | `ready` with the paths discarded, `refused` with a sentence and nothing written, or `failed` with a sentence and the paths discarded before the failure.                                                                                                               |
| `changes({ path? })`                             | Per repository the path reaches: its changed files and its added and removed line totals.                                                                                                                                                                              |
| `diff({ path? })`                                | Per repository the path reaches: its tracked diff and its changed paths.                                                                                                                                                                                               |
| `fileDiff({ repository, path })`                 | One changed file: its change, and the `original` (`HEAD`) and `modified` (working) text, with `binary` and `truncated`.                                                                                                                                                |

- The Git summary comes from one sandbox command: `git status --porcelain=v2 --branch` plus the operation markers (`merge`, `rebase`, `cherry-pick`, `revert`, `bisect`), the stash count, the submodule count when `.gitmodules` exists, whether the checkout is a linked worktree and whether the clone is shallow. A directory that is no repository answers `{ repo: false }` ([src/host/status.ts](../../bundles/features/git/src/host/status.ts)).
- `changes`, `diff` and `fileDiff` take the Project from the call's scope. A `path` that escapes the workspace answers `invalid_path`, and a missing one `not_found` ([src/host/service.ts](../../bundles/features/git/src/host/service.ts)).

### Branches

- `branches` lists `refs/heads/` newest commit first. It answers no branch and a `blocked` reason when the working directory or the repository resolves outside the workspace (`pwd -P`) and when the directory is no repository. When a Git operation is in progress or a file is conflicted, it answers the list with `blocked` set to `Finish the current Git operation and resolve conflicts before switching branches.` Running work also keeps the list and sets `blocked` to `Wait for active prompts and terminal commands in this worktree to finish before switching branches.` ([src/host/branches.ts](../../bundles/features/git/src/host/branches.ts), [src/host/service.ts](../../bundles/features/git/src/host/service.ts)).
- `switchBranch` refuses, in order: a `cwd` that differs from the Thread's working directory (`The working directory changed. Reopen the branch picker and try again.`), running work, any `blocked` reason, a branch that does not exist, and a branch checked out in another worktree. Switching to the current branch answers the branches unchanged. When `git switch` fails, it answers `Git could not switch branches. Commit or stash conflicting local changes and try again.` ([src/host/service.ts](../../bundles/features/git/src/host/service.ts), [src/host/branches.ts](../../bundles/features/git/src/host/branches.ts)).

### Changes and line totals

- A repository is a directory under the workspace root that holds a `.git` directory or file; a repository nested in another is left to the outer one ([packages/sandbox/src/lib/files.ts](../../packages/sandbox/src/lib/files.ts)). A `path` reaches every repository it lies in or holds, and keeps only the changes under the path ([src/host/changes.ts](../../bundles/features/git/src/host/changes.ts)).
- Each changed file comes from `git status --porcelain=v1 -z --untracked-files=all`, so names keep every character. A file carries its `status` (`added`, `modified`, `deleted`, `renamed`, `untracked` or `conflicted`), `staged`, `unstaged`, its two status letters, and, for a rename or a copy, `originalPath` ([src/host/changes.ts](../../bundles/features/git/src/host/changes.ts), [src/contracts/reads.ts](../../bundles/features/git/src/contracts/reads.ts)).
- The totals come from `git diff --numstat -z --no-ext-diff --no-textconv --find-renames <HEAD commit> --` over the whole repository, kept to the listed paths and their rename origins, and from `git diff --numstat --no-index /dev/null <path>` for each untracked file ([src/host/changes.ts](../../bundles/features/git/src/host/changes.ts)).

### Comparisons

- `fileDiff` reads the path's status, the working file and `HEAD`'s copy in parallel. A new file compares with empty content, a deleted file with an empty working side, and a rename with `HEAD`'s copy at its original path. Each side is read up to 262,144 bytes; a longer side is cut there and the comparison is marked `truncated`. A side holding a NUL byte makes the comparison `binary`, with no text on either side. A path with no change, or a `repository` that is no repository, answers `not_found`; a `repository` or `path` with a NUL, a leading `/` or a `..` part, or an empty path, answers `invalid_path` ([src/host/changes.ts](../../bundles/features/git/src/host/changes.ts), [src/host/service.ts](../../bundles/features/git/src/host/service.ts)).

### Discard

- A Discard runs these guards, in order: the `cwd` sent is still the Thread's working directory (`The working directory changed. Reopen the Changes view and try again.`); `repository` is listed by the Thread's changes read; no running work is in, under or above the repository; each path in `paths` has a listed change and is not a nested repository or submodule; no target is conflicted ([src/host/discard.ts](../../bundles/features/git/src/host/discard.ts)).
- Without `paths`, every listed change of the repository is a target, except nested repositories and submodules ([src/host/discard.ts](../../bundles/features/git/src/host/discard.ts)).
- Each target runs one command with literal pathspecs: `git clean --force` for an untracked file (ignored files stay), `git rm --force` for a staged new file in a repository with no commit, and otherwise `git restore --source=HEAD --staged --worktree`, which also restores a rename's origin. The first failing command stops the run. A new changes read then decides what was discarded; a target still listed answers `failed` ([src/host/discard.ts](../../bundles/features/git/src/host/discard.ts)).

#### Refresh

- The Changes view, the comparison tab and the footer's working directory register their Project with `files.refresh/v1` while they are mounted. A refresh of a Project rereads its changes, its open comparisons and the Git summaries of its Threads together; without `files.refresh/v1`, `git` rereads only its own reads ([src/client/hooks/use-project-reads.ts](../../bundles/features/git/src/client/hooks/use-project-reads.ts), [src/client/state.ts](../../bundles/features/git/src/client/state.ts), [src/client/changes/store.ts](../../bundles/features/git/src/client/changes/store.ts)).
- A read that answers `pending` polls again after the host's hint, at least 1 second, or after 3 seconds without one. A failed changes read, Git summary read or comparison read is retried 3 times, waiting 1, 2 and 4 seconds ([src/client/changes/store.ts](../../bundles/features/git/src/client/changes/store.ts), [src/client/hooks/use-thread-git.ts](../../bundles/features/git/src/client/hooks/use-thread-git.ts), [src/client/hooks/use-file-diff.ts](../../bundles/features/git/src/client/hooks/use-file-diff.ts), [packages/desktop/src/reads/read-policy.ts](../../packages/desktop/src/reads/read-policy.ts)). A failed branch read is not retried; the branch picker shows its error with a retry ([src/client/hooks/use-branches.ts](../../bundles/features/git/src/client/hooks/use-branches.ts), [src/client/cwd/branch-picker.tsx](../../bundles/features/git/src/client/cwd/branch-picker.tsx)). The Changes view shows a failed tree or changes read as one toast, with a retry that refreshes the Project ([src/client/changes/git-changes.tsx](../../bundles/features/git/src/client/changes/git-changes.tsx)).

#### The working directory and branch

- The element `git-workspace-cwd` in the Files column footer draws nothing without a selected Thread. Its trigger shows the Thread's full working directory, truncated when needed, then a middle dot and the branch, or `@<commit>` when detached; while the environment is starting or unavailable it shows `Preparing environment…` or `Environment unavailable` instead of the branch. Its tooltip adds the Git summary line: the branch (`DETACHED @<commit>` when detached, `<branch> · initial` before the first commit), then, each only when not zero, `↑<ahead> ↓<behind>`, `+<staged> !<modified> ?<untracked>`, `CONFLICT·<n>`, and the operation in capitals (`MERGE`, `REBASE`, `CHERRY-PICK`, `REVERT`, `BISECT`), joined by `·` ([src/client/domain/thread-git.ts](../../bundles/features/git/src/client/domain/thread-git.ts), [src/client/cwd/workspace-cwd.tsx](../../bundles/features/git/src/client/cwd/workspace-cwd.tsx), [src/client/cwd/workspace-cwd-view.tsx](../../bundles/features/git/src/client/cwd/workspace-cwd-view.tsx)).
- The trigger opens a popover. In a repository it names the current worktree root, with a button that copies its path, and whether it is the main or a linked worktree; outside a repository it shows `Working directory` and the working directory, with the same copy button. The working directory cannot be edited there ([src/client/cwd/workspace-cwd.tsx](../../bundles/features/git/src/client/cwd/workspace-cwd.tsx)).
- In a repository, the popover has a branch row with the branch and its status line (tracking, changes, conflicts and operation, or `Working tree clean`). The row opens a second popover to its side, the branch picker, and the first popover stays open. Choosing a branch or pressing Escape closes only the picker; closing the first popover closes both. The branch row is disabled while the Thread is running ([src/client/cwd/workspace-cwd.tsx](../../bundles/features/git/src/client/cwd/workspace-cwd.tsx), [src/client/domain/thread-git.ts](../../bundles/features/git/src/client/domain/thread-git.ts)).
- The branch picker reads `branches` while it is open. It lists the local branches with a search field (`Search branches`), each with its short commit and subject, and `In use: <path>` for a branch checked out in another worktree. A branch is disabled while a switch runs, while the Thread is running, while the host answers a `blocked` reason, and when another worktree holds it; the host's `blocked` reason itself is not shown. While the environment is starting or unavailable, the picker shows that state instead of the list ([src/client/cwd/branch-picker.tsx](../../bundles/features/git/src/client/cwd/branch-picker.tsx), [src/client/hooks/use-branches.ts](../../bundles/features/git/src/client/hooks/use-branches.ts), [src/client/api/git-api.ts](../../bundles/features/git/src/client/api/git-api.ts)).
- Choosing the current branch only closes the picker. Choosing another calls `switchBranch` with the working directory the picker read with; on success the picker takes the new list and the Project is refreshed before the switch counts as done. A refusal or a failed call shows its sentence as a toast and reads the branches again ([src/client/hooks/use-branches.ts](../../bundles/features/git/src/client/hooks/use-branches.ts), [src/client/api/git-api.ts](../../bundles/features/git/src/client/api/git-api.ts)).

#### The Changes view

- The Changes tab's badge shows the added and removed line totals of the selected Project and working directory, in 12-pixel tabular figures, added in the added color and removed in the deleted color. It shows nothing until the read is ready, and nothing when both totals are 0 ([src/client/changes/changes-badge.tsx](../../bundles/features/git/src/client/changes/changes-badge.tsx), [src/client/changes/change-counts.tsx](../../bundles/features/git/src/client/changes/change-counts.tsx)).
- The element `git-changes` reads the changes of the selected Thread's working directory. Without a Project it says so; while the Files tree read of `files.sandbox/v1` shows the sandbox cannot be read, it explains the Project's state; it shows a state for a read not yet made, a read loading, a changes read that answers a lease state (`The changes cannot be read`, with the Project's state), a directory with no repository and a workspace with no change ([src/client/changes/git-changes.tsx](../../bundles/features/git/src/client/changes/git-changes.tsx)).
- Changed files are drawn as a directory tree grouped by repository, with no search or collapse-all toolbar. Each repository with changes is a tree row at depth 0, labelled with its path (`workspace` for the root), led by a branch icon, that expands like a directory; its own badge holds its added and removed totals. Its changed paths are the Files tree's rows nested under it, each directory expanding on its own. Expansion is kept per Project and working directory ([src/client/changes/changes-tree.tsx](../../bundles/features/git/src/client/changes/changes-tree.tsx), [src/client/reads/change-tree.ts](../../bundles/features/git/src/client/reads/change-tree.ts), [src/client/changes/store.ts](../../bundles/features/git/src/client/changes/store.ts)).
- A repository row opens and closes with a click, Enter, Space, ArrowRight and ArrowLeft. It draws the hover and pressed fill and the keyboard focus outline. The tree scrolls sideways, and each row's mark stays pinned to the visible right edge on an opaque backing that follows the row's state ([src/client/changes/changes-tree.tsx](../../bundles/features/git/src/client/changes/changes-tree.tsx), [src/client/changes/git-changes.tsx](../../bundles/features/git/src/client/changes/git-changes.tsx)).
- A file row carries its status letter (`A`, `M`, `D`, `R`, `U`, `!` for a conflict) in its status color, struck through when deleted; its description reads the status, staged or unstaged, and the rename origin. A directory row carries the count of changed files under it ([src/client/reads/change-tree.ts](../../bundles/features/git/src/client/reads/change-tree.ts)).
- A file row opens that file's comparison. The row of the file whose comparison tab is selected is the selected row ([src/client/changes/git-changes.tsx](../../bundles/features/git/src/client/changes/git-changes.tsx), [src/client/commands.ts](../../bundles/features/git/src/client/commands.ts)).
- With a selected Thread, a file row's context menu holds "Discard changes" and a repository row's "Discard all changes"; directory rows have none. Either opens a confirmation, `Discard changes to <name>?` or `Discard all changes in <name>?`, that says `This cannot be undone.` Confirming calls `discard` with the working directory the view read with. After `ready` or `failed` the view waits for the Project's refresh first; `ready` closes the dialog, and any other answer shows its sentence in the dialog, which stays open until Cancel ([src/client/changes/git-changes.tsx](../../bundles/features/git/src/client/changes/git-changes.tsx), [src/client/changes/discard-dialog.tsx](../../bundles/features/git/src/client/changes/discard-dialog.tsx)).

- Through `files.decorations/v1`, the Files tree draws the same marks from the same changes read: each changed file's letter and color, and each ancestor folder's count and color. #### `git.changes/v1`

- `git.changes/v1.observe({ projectId, cwd? }, listener)` (client) answers the changes read of one Project and working directory, with its marks by workspace path, its error and whether it fetches. The read runs only while something observes it ([src/contracts/index.ts](../../bundles/features/git/src/contracts/index.ts), [src/client/changes/store.ts](../../bundles/features/git/src/client/changes/store.ts)).

#### The comparison tab

- `git.open-comparison/v1({ projectId, repository, path })` opens the comparison as a workspace tab through `layout.tabs/v2`, with the id `["diff", projectId, repository, path]`, the file's name as title, the accessible name `<name> changes`, the path as tooltip and the element `git-file-diff-icon` as icon. The tab's context menu holds "Open file", which runs `files.open-file/v1` ([src/client/commands.ts](../../bundles/features/git/src/client/commands.ts)).
- The tab's element `git-file-diff` reads `fileDiff` when it opens. It draws a read-only Monaco diff editor of `HEAD` against the working file, unified by default with a single line-number gutter. The reader chooses unified or side by side in the footer; a chosen side-by-side layout shows unified while the editor is at most 700 pixels wide, as its tooltip `Side by side when space allows; unified below 700 px` says ([src/client/diff/diff-footer.tsx](../../bundles/features/git/src/client/diff/diff-footer.tsx), [src/client/diff/file-diff.tsx](../../bundles/features/git/src/client/diff/file-diff.tsx), [packages/desktop/src/code/diff-editor.tsx](../../packages/desktop/src/code/diff-editor.tsx)). Monaco's codicon font is registered from the bundled `monaco-editor` package ([packages/desktop/src/code/monaco-runtime.ts](../../packages/desktop/src/code/monaco-runtime.ts)).
- One toolbar shows the status letter in its color, with a tooltip `HEAD ↔ Working tree · <description>`; the path, its folder muted and its name struck when deleted; the added and removed line counts, or `…` while they are computed; for a truncated comparison a warning whose tooltip says `Only the beginning of each file is shown; line counts are partial.`; and an "Open file" icon, enabled once the comparison is read or answers `not_found`, and disabled for a deleted file ([src/client/diff/diff-toolbar.tsx](../../bundles/features/git/src/client/diff/diff-toolbar.tsx), [src/client/diff/file-diff.tsx](../../bundles/features/git/src/client/diff/file-diff.tsx)).
- The footer shows the full path and icon controls for the unified or side-by-side layout and for the previous and next change; the change buttons are disabled when nothing changed ([src/client/diff/diff-footer.tsx](../../bundles/features/git/src/client/diff/diff-footer.tsx)).
- A binary comparison shows `Binary file changed` and `A text comparison is not available for this file.`. A comparison with nothing to show (`not_found`) shows `This comparison is unavailable` and `This file no longer has a comparison to show. It may have been committed, reverted or removed.`; a sandbox that cannot be read explains the Project's state. A refresh keeps the editor mounted ([src/client/diff/file-diff.tsx](../../bundles/features/git/src/client/diff/file-diff.tsx)).

#### Versioning settings

- The section at `/settings/git` edits the settings window's draft through `settings.config/v1`. It chooses the `GIT` credential the agent commits with (`gitCredentialId`, a username and an email, no secret) and the `API_TOKEN` credential that authenticates a push and the sandbox's GitHub CLI (`githubCredentialId`). "None" removes the choice. The credentials come from `secrets/v1.list` ([src/client/settings/versioning.tsx](../../bundles/features/git/src/client/settings/versioning.tsx), [src/client/settings/settings-versioning.tsx](../../bundles/features/git/src/client/settings/settings-versioning.tsx), [src/client/domain/credentials.ts](../../bundles/features/git/src/client/domain/credentials.ts), [src/host/credentials.ts](../../bundles/features/git/src/host/credentials.ts)).
- The host refuses a configuration whose `gitCredentialId` names no stored `GIT` credential or whose `githubCredentialId` names no stored `API_TOKEN` credential ([bundles/foundation/host-config/src/host/config/service.ts](../../bundles/foundation/host-config/src/host/config/service.ts); see the [`host-config` README](../../bundles/foundation/host-config/README.md)).
- The runtime applies the identity to each Project sandbox as Git settings and, when a token is chosen, writes Git's credential store and the GitHub CLI's hosts file for `github.com`. The token travels only in that process's environment, and a failure is a warning that never fails a prompt ([bundles/runtime/runtime/src/host/domain/git-credentials.ts](../../bundles/runtime/runtime/src/host/domain/git-credentials.ts)).
