# Feature: Files

- Status: `implemented`

## Problem

The agent works on the code of its Project, which lives in the Project's sandbox. It needs to map that workspace, search it, read an image in it, and change files precisely, with every relative path resolved against the directory it works in. The reader needs to see the same workspace beside the conversation: browse its tree, open a file and read it, and make an empty file or folder, while what the panel shows follows what the agent changes without a watcher on the sandbox.

## Decisions

- The window refreshes a Project after a sandbox-writing tool because the owner of that tool asks for it: `files` and `git` observe `chat.hooks/v2.onThreadUpdateHook` and call `files.refresh/v1.request` after their own tools finish. `chat.hooks/v2.onSandboxActivityHook` does not fire after a finished tool call. The `terminal` tool also writes the sandbox, and its finished call requests no refresh: `terminal` requests one only when the list of a Project's terminals changes ([src/client/refresh/tool-refresh.ts](../../bundles/features/files/src/client/refresh/tool-refresh.ts), [src/client/index.ts](../../bundles/features/files/src/client/index.ts), [bundles/features/git/src/client/index.ts](../../bundles/features/git/src/client/index.ts), [bundles/desktop/chat/src/client/domain/project-refresh.ts](../../bundles/desktop/chat/src/client/domain/project-refresh.ts), [bundles/features/terminal/src/client/store.ts](../../bundles/features/terminal/src/client/store.ts)).
- `files.decorations/v1` is a contract of cardinality `many` with one method, `observe`: several bundles provide it at once, each provider declares `{ cardinality: 'many' }` or is quarantined, and the consumer collects every provider through `whenAvailable` instead of `use`, as [contracts.md](../architecture/bundles/contracts.md#services-and-methods) describes. `files` declares it and does not provide it; `git` provides the marks of its changes ([src/contracts/index.ts](../../bundles/features/files/src/contracts/index.ts), [src/client/hooks/use-decorations.ts](../../bundles/features/files/src/client/hooks/use-decorations.ts), [bundles/features/git/manifest.json](../../bundles/features/git/manifest.json)).
- `files.sandbox/v1.observeTree` takes `{ projectId, cwd? }`, where `cwd` is the Thread's raw working directory. The tree's root is derived from it with `workspacePath(cwd)`, and the tree's query key is `['files', projectId, 'tree', cwd]` ([src/contracts/index.ts](../../bundles/features/files/src/contracts/index.ts), [src/client/sandbox-store.ts](../../bundles/features/files/src/client/sandbox-store.ts), [src/contracts/reads.ts](../../bundles/features/files/src/contracts/reads.ts)).
- Every `files/v1` method answers a `LeaseOutcome` through `runtime.lease/v1.withLease` and never acquires a lease. The window maps that outcome itself: `pending` with `retryAfterSeconds: 1`, `not_found` as not found, every other refusal as `invalid_path`, and a failed call as `Doric backend is unavailable.`, `The request could not be completed.` or `Doric returned an invalid response.` ([src/host/reads.ts](../../bundles/features/files/src/host/reads.ts), [src/client/api/reads.ts](../../bundles/features/files/src/client/api/reads.ts)).
- The refresh coordinator has no React. A change of what it watches (the selected Project and its state, the selected Thread and its working directory, the Project's Thread activity, whether something of the Project is shown, the connection) requests a refresh; window focus and the 15-second poll act only while a registrant of the selected Project is active, the window is connected and the document is visible. The chat's activity hook requests a refresh whatever the connection. Terminal activity arrives as `request`. "Shown" means that a registrant is active: the tree and each file tab register while they are mounted ([src/client/refresh/coordinator.ts](../../bundles/features/files/src/client/refresh/coordinator.ts), [src/client/hooks/use-project-reads.ts](../../bundles/features/files/src/client/hooks/use-project-reads.ts)).
- The tools register at fixed global model-visible positions, so the order of the tool list does not depend on the order the bundles load in ([src/host/index.ts](../../bundles/features/files/src/host/index.ts)).
- `files/contracts` re-exports the sandbox vocabulary that `git` reads (`workspacePath`, `SANDBOX_ROOT`, `ROOT_PATH`, `sandboxNotice`, `ProjectLeaseState`, `SandboxStatus`) from `src/contracts/reads.ts`. That file imports nothing at runtime because a window loads the contracts module by its own specifier. The `files` client rereads only its own `['files', projectId, …]` keys ([src/contracts/reads.ts](../../bundles/features/files/src/contracts/reads.ts), [src/contracts/index.ts](../../bundles/features/files/src/contracts/index.ts), [src/client/sandbox-store.ts](../../bundles/features/files/src/client/sandbox-store.ts)).
- The text the tree skeleton announces belongs to the bundle that shows the tree: `files` passes `Loading files` ([src/client/tree/files-tree.tsx](../../bundles/features/files/src/client/tree/files-tree.tsx), [packages/desktop/src/panels/tree-skeleton.tsx](../../packages/desktop/src/panels/tree-skeleton.tsx)).
- The Files column is always shown: 328 px wide by default, resizable between 14rem and 30rem, and never collapsed. Reveal in Files selects the Files view with `select('files')` ([bundles/desktop/layout/src/client/components/templates/workspace-layout.tsx](../../bundles/desktop/layout/src/client/components/templates/workspace-layout.tsx), [src/client/commands.ts](../../bundles/features/files/src/client/commands.ts)).
- New file and New folder are the only writes the bundle's window part makes to the workspace ([src/client/tree/files-tree.tsx](../../bundles/features/files/src/client/tree/files-tree.tsx), [src/client/api/writes.ts](../../bundles/features/files/src/client/api/writes.ts)).

### The workspace's visibility rules

- One implementation in [`packages/sandbox`](../../packages/sandbox/README.md) decides what a listing of the workspace shows: a path must stay inside the workspace root; `.gitignore` files apply, with negation; `node_modules` and `__pycache__` are ignored as rules of the workspace root placed before every `.gitignore`, so a negation there shows them again; hidden entries are left out except `.agents`; `.git` is never listed; directories come first, then files, each sorted by name ([packages/sandbox/src/lib/files.ts](../../packages/sandbox/src/lib/files.ts)).
- The `tree` tool, every `files/v1` listing (the Files panel's tree among them) and the file routes of [`transport`](../../bundles/foundation/transport/README.md), which call `files/v1`, read through those rules ([src/host/tools/tree.ts](../../bundles/features/files/src/host/tools/tree.ts), [src/host/reads.ts](../../bundles/features/files/src/host/reads.ts), [bundles/foundation/transport/src/host/routes/projects.ts](../../bundles/foundation/transport/src/host/routes/projects.ts)).
- `find` and `grep` read with rules of their own: the `.gitignore` files inside the searched directory, with negation and the last matching rule winning, and `.git` and `node_modules` always pruned. Hidden files are searched ([src/host/tools/visible-files.ts](../../bundles/features/files/src/host/tools/visible-files.ts)).

### The file tools

All the tools are always available and run in the calling prompt's Project sandbox through `runtime.lease/v1`. A relative path resolves against the calling Thread's working directory, read from `runtime.workspace/v1` at call time; an absolute path is used as it is ([src/host/index.ts](../../bundles/features/files/src/host/index.ts), [src/host/sandbox.ts](../../bundles/features/files/src/host/sandbox.ts)).

| Order | Tool         | What it does                                                                  |
| ----- | ------------ | ----------------------------------------------------------------------------- |
| 100   | `cwd`        | Reports or moves the Thread's working directory ([cwd-tool.md](cwd-tool.md)). |
| 200   | `edit`       | Changes a file through exact-text replacements.                               |
| 300   | `find`       | Finds files by glob.                                                          |
| 400   | `grep`       | Searches file contents.                                                       |
| 600   | `tree`       | Shows the directory structure as an ASCII tree.                               |
| 800   | `write`      | Creates or overwrites a whole file.                                           |
| 850   | `view-image` | Hands the model an image of the workspace.                                    |

The positions 500 and 700 are the `terminal` tool of [`terminal`](../../bundles/features/terminal/README.md) ([terminal.md](terminal.md)) and the `web` tool of [`web`](../../bundles/features/web/README.md) ([web-research.md](web-research.md)) ([src/host/index.ts](../../bundles/features/files/src/host/index.ts)).

Each tool's input, output, limits and errors are in [the bundle README](../../bundles/features/files/README.md#tools). `edit` changes a file through exact-text replacements and `write` creates or overwrites one; both answer a diff of the changed lines, which the conversation draws. `find` and `grep` stop at a result limit and say when they cut their answer, and `tree` stops at a depth and counts the entries it leaves out. `view-image` reads the file's bytes, keeps them as an attachment of the Project through `runtime.attachments/v1`, and answers the attachment's reference line; it declares `resultModalities: ['image']`. The executor of [`default`](../../bundles/runtime/default/README.md#attachments) then turns that line into the image in the request the model reads, as [attachments.md](attachments.md) describes, and leaves the tool out of a run whose model's catalog names input modalities without `image` ([bundles/runtime/default/src/host/executor.ts](../../bundles/runtime/default/src/host/executor.ts), [bundles/runtime/default/src/host/attachments.ts](../../bundles/runtime/default/src/host/attachments.ts), [src/host/tools/edit.ts](../../bundles/features/files/src/host/tools/edit.ts), [src/host/tools/write.ts](../../bundles/features/files/src/host/tools/write.ts), [src/host/tools/find.ts](../../bundles/features/files/src/host/tools/find.ts), [src/host/tools/grep.ts](../../bundles/features/files/src/host/tools/grep.ts), [src/host/tools/tree.ts](../../bundles/features/files/src/host/tools/tree.ts), [src/host/tools/view-image.ts](../../bundles/features/files/src/host/tools/view-image.ts)).

### In the conversation

- While `chat.views/v1` is served, the bundle registers how the chat draws three tools, each in a registration of its own ([src/client/index.ts](../../bundles/features/files/src/client/index.ts), [src/client/chat/views.ts](../../bundles/features/files/src/client/chat/views.ts)).
- `edit` and `write` calls are drawn by `files-edit-call`, a block of its own, open until the reader closes it: `Editing`, `Edited` or `Failed to edit`, the file's name, the `+added / −removed` counts and the numbered diff. The first 16 diff lines show, then `⋯ Show <n> more lines`. A failed call shows the failure notice, with `tool_failed` as its fallback code ([src/client/chat/edit-call.tsx](../../bundles/features/files/src/client/chat/edit-call.tsx), [src/client/chat/edit-tool.ts](../../bundles/features/files/src/client/chat/edit-tool.ts)).
- `view-image` keeps the chat's generic row, open until the reader closes it, so the image stands beside the call ([src/client/chat/views.ts](../../bundles/features/files/src/client/chat/views.ts)).

### The `files/v1` contract

`files/v1` 1.3.0 is the host's contract for the Project's sandbox: it lists one directory, a whole tree or several directories, reads one file, and makes one empty file or directory. Every method runs on the Project's current lease through `runtime.lease/v1.withLease`, never acquires a lease, and answers the lease state when the lease is not ready. Its methods, answers and limits are in [the bundle README](../../bundles/features/files/README.md#filesv1-host-130) ([src/contracts/index.ts](../../bundles/features/files/src/contracts/index.ts), [src/host/reads.ts](../../bundles/features/files/src/host/reads.ts), [src/host/writes.ts](../../bundles/features/files/src/host/writes.ts)).

- `createFile` and `createDirectory` never overwrite: a name that exists answers `exists` and keeps its content, and an invalid name or a folder outside the workspace or missing is refused ([src/host/writes.ts](../../bundles/features/files/src/host/writes.ts)).
- The window calls `files/v1` with `services.use(FilesV1, { projectId })`. The `files` client checks its input before the call and throws `The item identifier is invalid.` for a Project id that is empty, longer than 200 characters or holds a NUL, and `The workspace path is invalid.` for a path that is absolute, has a `..` segment, holds a NUL or is longer than 4,096 characters, and for a `directories` read of no path or of more than 1,000 distinct paths; [the bundle README](../../bundles/features/files/README.md#errors-and-failure-behavior) gives these errors ([src/client/api/reads.ts](../../bundles/features/files/src/client/api/reads.ts)).
- The desktop bridge routes the window's call to the host's provider and carries only the scope keys that `files` lists for `files/v1` under `desktopScope`, `projectId`, `threadId` and `promptId`; a call whose scope holds another key is refused with `invalid_input`, as [manifest.md](../architecture/bundles/manifest.md#desktopscope) describes ([manifest.json](../../bundles/features/files/manifest.json), [app/desktop/doric/src/platform/bridge/client-routing.ts](../../app/desktop/doric/src/platform/bridge/client-routing.ts), [app/desktop/doric/src/platform/bridge/dispatcher.ts](../../app/desktop/doric/src/platform/bridge/dispatcher.ts)).

### The Files panel

- The Files column sits on the right of the workspace window and is always shown: 328 px wide by default, resizable between 14rem and 30rem, with a 40 px header and a 28 px footer row. [ui-redesign.md](ui-redesign.md) describes the window ([bundles/desktop/layout/src/client/components/templates/workspace-layout.tsx](../../bundles/desktop/layout/src/client/components/templates/workspace-layout.tsx)).
- The Files view is the region item `files` of `shell.panel`, with the order 100, the label `Files` and the `files-file-icon` element as its icon, chosen from the column header's tabs beside the Changes view of [git.md](git.md). The client selects it when it activates ([src/client/index.ts](../../bundles/features/files/src/client/index.ts)).
- The footer row is the region `shell.panel.footer`, where `git` draws the working directory and the branch ([bundles/desktop/layout/src/client/views/workspace-view.tsx](../../bundles/desktop/layout/src/client/views/workspace-view.tsx), [bundles/features/git/src/client/index.ts](../../bundles/features/git/src/client/index.ts)).

#### The tree

- The view reads the selected Project's sandbox and roots its tree at the selected Thread's working directory, so selecting another Thread of the Project roots the tree elsewhere; a working directory outside `/workspace`, or no selected Thread, roots it at the workspace root. It reads the selection through `workspace.selection/v1` and the records through `runtime.records/v1` ([src/client/tree/files-tree.tsx](../../bundles/features/files/src/client/tree/files-tree.tsx), [src/client/api/selection.ts](../../bundles/features/files/src/client/api/selection.ts)).
- With no Project selected the view shows `No project selected` and `Select a project to see its sandbox.` During the first read it shows skeleton rows that match the tree's row height, indentation and icons, announced as `Loading files`. When the first read fails, the panel body stays empty and only the read toast shows. When the sandbox cannot be read it shows `No files to show` with the sentence of `sandboxNotice` for the state, as [projects-and-threads.md](projects-and-threads.md) describes the lease states; a lease the host has not prepared yet reads `The sandbox is still being prepared; the host suggests trying again in 1 seconds.` When the root itself cannot be listed, the read answers `not_found` for a working directory that is gone and `invalid_path` for one that is not a directory, and the view shows `No files to show` with `That path is no longer in the workspace.` or `That path is not inside the workspace.` An empty root shows `No files` and `This directory is empty.` ([src/client/tree/files-tree.tsx](../../bundles/features/files/src/client/tree/files-tree.tsx), [src/contracts/reads.ts](../../bundles/features/files/src/contracts/reads.ts), [src/client/api/reads.ts](../../bundles/features/files/src/client/api/reads.ts), [src/client/sandbox-store.ts](../../bundles/features/files/src/client/sandbox-store.ts), [src/client/reads/directory-tree.ts](../../bundles/features/files/src/client/reads/directory-tree.ts), [packages/desktop/src/panels/tree-skeleton.tsx](../../packages/desktop/src/panels/tree-skeleton.tsx)).
- The tree is read per directory through `files/v1.directories`: one call reads the root and every open folder. A folder opened later is read on its own, with the folders opened with it, and merged in; until its children arrive it shows the line `Loading…`, and an open folder with no children shows the line `This directory is empty.` A folder whose read fails closes again, and its failure is the panel's read toast. An open folder that its parent's listing does not hold as a directory is not shown, and a folder whose own read answers that it cannot be listed makes the whole tree read again, the root and every open folder in one call ([src/client/sandbox-store.ts](../../bundles/features/files/src/client/sandbox-store.ts), [src/client/reads/directory-tree.ts](../../bundles/features/files/src/client/reads/directory-tree.ts), [packages/desktop/src/panels/file-tree.tsx](../../packages/desktop/src/panels/file-tree.tsx)).
- Which folders are open is kept per Project and root, apart from the read, so leaving a Thread and coming back keeps them open ([src/client/stores/expansion.ts](../../bundles/features/files/src/client/stores/expansion.ts)).
- A row shows a file, folder or open-folder icon and the entry's name, and its tooltip is the path. Click, Enter or Space opens a file or toggles a folder; Right opens a closed folder and Left closes an open one. The row of the selected file tab is the selected row. Only the rows in view are drawn, and the focused row stays drawn ([packages/desktop/src/panels/file-tree.tsx](../../packages/desktop/src/panels/file-tree.tsx), [src/client/tree/files-tree.tsx](../../bundles/features/files/src/client/tree/files-tree.tsx)).
- The tree scrolls both ways. A row's mark is pinned to the visible right edge of the row, and its backing follows the row's hover and selected states ([src/client/tree/files-tree.tsx](../../bundles/features/files/src/client/tree/files-tree.tsx), [packages/desktop/src/panels/file-tree.tsx](../../packages/desktop/src/panels/file-tree.tsx)).

#### Marks

- The view asks every provider of `files.decorations/v1` for the marks of the tree it shows and draws their merge; [the bundle README](../../bundles/features/files/README.md#filesdecorationsv1-declared-client-many) gives the contract's shape. The view keeps each provider's answer under the bundle id that `whenAvailable` reports for that provider, and drops it when the provider goes. For a path two providers mark, the provider whose bundle id is smaller, by code unit, wins; the first error in bundle-id order is shown, and the tree's own read error wins over it ([src/contracts/index.ts](../../bundles/features/files/src/contracts/index.ts), [src/client/hooks/use-decorations.ts](../../bundles/features/files/src/client/hooks/use-decorations.ts), [src/client/tree/decorations.ts](../../bundles/features/files/src/client/tree/decorations.ts), [src/client/tree/files-tree.tsx](../../bundles/features/files/src/client/tree/files-tree.tsx)).
- A mark always has a description, the row's accessible label and tooltip suffix, and a count, which a directory row shows as its badge: how many marked entries lie below it. It may add a tone (class names for the name and the badge), a letter, which a file row shows as its badge, and a strike-through of a file's name; [the bundle README](../../bundles/features/files/README.md#filesdecorationsv1-declared-client-many) gives its fields. Marks are keyed by path, so a folder never opened carries them too ([src/contracts/index.ts](../../bundles/features/files/src/contracts/index.ts), [packages/desktop/src/panels/file-tree.tsx](../../packages/desktop/src/panels/file-tree.tsx)). `git` provides the marks of its changes, as [git.md](git.md) describes.

#### Row menus

- A file row's context menu holds Copy relative path, which copies the path relative to the tree's root ([src/client/tree/files-tree.tsx](../../bundles/features/files/src/client/tree/files-tree.tsx)).
- A folder row's menu holds New file and New folder, and no other place does, so nothing can be made in the tree's root itself, an empty root included, which shows no rows. Each opens the folder and shows a name row as its first child. Enter sends the trimmed name to `createFile` or `createDirectory`, and an empty name cancels; Escape or leaving the field cancels, except while the call runs, and a change of Project or root closes the row. A created entry closes the row and requests a refresh of the Project; any other answer shows its reason under the row, which keeps the typed name: `<name> already exists.`, `A name cannot contain / or \, cannot be . or .., and has at most 255 bytes.`, `This folder is outside the Project.`, `This folder no longer exists.`, the command's first stderr line, a lease sentence (`The Project is starting. Try again in a moment.`, `The Project is unavailable.`, `The Project's sandbox expired. Reopen the Project.`, `The Project no longer exists.`), or `Could not create <name>.` when the call fails ([src/client/tree/files-tree.tsx](../../bundles/features/files/src/client/tree/files-tree.tsx), [src/client/tree/pending-entry.tsx](../../bundles/features/files/src/client/tree/pending-entry.tsx)).

#### Read failures

- A failed read never replaces what the tree shows: a tree already drawn stays, and the failure is one toast, `Unable to update`, with the message and a `Try again` action that requests a refresh. The toast has the id `layout-panel-read`, which the Changes view of [`git`](../../bundles/features/git/README.md) passes too, so the panel's views share one toast; it is shown once per message, held while a read is on its way, and dismissed by the next successful read ([src/client/tree/files-tree.tsx](../../bundles/features/files/src/client/tree/files-tree.tsx), [bundles/features/git/src/client/changes/git-changes.tsx](../../bundles/features/git/src/client/changes/git-changes.tsx), [src/client/reads/state.ts](../../bundles/features/files/src/client/reads/state.ts), [packages/desktop/src/panels/use-read-error.ts](../../packages/desktop/src/panels/use-read-error.ts)).
- A failed read is retried three times, after 1, 2 and 4 seconds. A read that answers `pending` is read again every second; any other answer that is not ready waits for a refresh that is not periodic ([src/client/sandbox-store.ts](../../bundles/features/files/src/client/sandbox-store.ts), [packages/desktop/src/reads/read-policy.ts](../../packages/desktop/src/reads/read-policy.ts), [src/client/api/reads.ts](../../bundles/features/files/src/client/api/reads.ts)).
- The panel shows no updating label. A refresh in the background keeps the tree and the reader's position, and a refresh that changes nothing leaves every row as it is ([src/client/tree/files-tree.tsx](../../bundles/features/files/src/client/tree/files-tree.tsx), [src/client/sandbox-store.ts](../../bundles/features/files/src/client/sandbox-store.ts)).

### Revalidation and `files.refresh/v1`

`files.refresh/v1` 1.0.0 is the window's one Project refresh coordinator, a client contract: the reads of a Project register with it while they are mounted and say whether they are shown, and a request for a Project refreshes every registrant of that Project and of no other. Its methods are in [the bundle README](../../bundles/features/files/README.md#filesrefreshv1-client-100) ([src/contracts/index.ts](../../bundles/features/files/src/contracts/index.ts), [src/client/refresh/coordinator.ts](../../bundles/features/files/src/client/refresh/coordinator.ts)).

An agent's change reaches the panel and the open tabs in this order:

1. An `edit` or `write` call finishes, and the chat receives its live `tool.finished` event. Only a Thread the chat holds delivers it, and a `tool.failed` event refreshes nothing ([src/client/refresh/tool-refresh.ts](../../bundles/features/files/src/client/refresh/tool-refresh.ts), [bundles/desktop/chat/src/client/stores/thread-chats.ts](../../bundles/desktop/chat/src/client/stores/thread-chats.ts)).
2. The chat hands the event to `files` through `chat.hooks/v2.onThreadUpdateHook`, as [the chat README](../../bundles/desktop/chat/README.md) describes ([src/client/index.ts](../../bundles/features/files/src/client/index.ts)).
3. `files` calls `files.refresh/v1.request` with the Thread's Project ([src/client/refresh/tool-refresh.ts](../../bundles/features/files/src/client/refresh/tool-refresh.ts)).
4. Every registrant of that Project rereads: the Files tree, each file tab of the Project, and the reads of `git` ([src/client/refresh/coordinator.ts](../../bundles/features/files/src/client/refresh/coordinator.ts), [bundles/features/git/src/client/hooks/use-project-reads.ts](../../bundles/features/git/src/client/hooks/use-project-reads.ts)).
5. Requests that arrive within 250 ms share one reread, and a request during a reread leaves one more after it ([packages/desktop/src/reads/refresh.ts](../../packages/desktop/src/reads/refresh.ts), [src/client/sandbox-store.ts](../../bundles/features/files/src/client/sandbox-store.ts)).
6. The reread calls `files/v1.directories` for the tree and `files/v1.content` for each tab over the desktop bridge; the host runs it on the Project's lease through `runtime.lease/v1.withLease` and lists or reads through [`packages/sandbox`](../../packages/sandbox/README.md) ([src/client/api/reads.ts](../../bundles/features/files/src/client/api/reads.ts), [src/host/reads.ts](../../bundles/features/files/src/host/reads.ts)).

A reader opens a file in this order: a click on its row runs `files.open-file/v1`, which calls `layout.tabs/v2.open`; the layout creates the `files-file-view` element as the tab's body, and the element reads the file through `files/v1.content` ([src/client/tree/files-tree.tsx](../../bundles/features/files/src/client/tree/files-tree.tsx), [src/client/commands.ts](../../bundles/features/files/src/client/commands.ts), [bundles/desktop/layout/src/client/services/layout-tabs.ts](../../bundles/desktop/layout/src/client/services/layout-tabs.ts), [src/client/file/file-view.tsx](../../bundles/features/files/src/client/file/file-view.tsx)).

- The Files tree and each file tab register while they are mounted; `git` registers its own reads ([src/client/hooks/use-project-reads.ts](../../bundles/features/files/src/client/hooks/use-project-reads.ts), [bundles/features/git/src/client/hooks/use-project-reads.ts](../../bundles/features/git/src/client/hooks/use-project-reads.ts)).
- There is no filesystem watcher. The coordinator requests a refresh of the selected Project, while the window is connected, when any of these changes: the selected Project or its state, the selected Thread or its working directory, a Thread of the Project (its id, its state — the start of a run excepted, its end counted in any state — or its working directory), whether something of the Project is shown, or the connection coming back. A Thread that starts to run is not a change ([src/client/refresh/coordinator.ts](../../bundles/features/files/src/client/refresh/coordinator.ts)).
- While something of the selected Project is shown, the window is connected and the document is visible, window focus and a visibility change request a refresh, and a poll requests a periodic one every 15 seconds ([src/client/refresh/coordinator.ts](../../bundles/features/files/src/client/refresh/coordinator.ts), [src/client/index.ts](../../bundles/features/files/src/client/index.ts)).
- Other bundles request refreshes. A Thread the chat holds is one whose conversation the chat keeps loaded. The chat's `onSandboxActivityHook` requests one when the chat starts to hold a Thread, a held Thread's working directory changes, or its state changes to any state other than `running`; `files` itself requests one after an `edit` or `write` call finishes in a held Thread's conversation (`onThreadUpdateHook`); `git` after a `git` call; and `terminal` when the id, state, command or working directory of a Project's terminals changes ([src/client/index.ts](../../bundles/features/files/src/client/index.ts), [bundles/desktop/chat/src/client/domain/project-refresh.ts](../../bundles/desktop/chat/src/client/domain/project-refresh.ts), [bundles/features/terminal/src/client/store.ts](../../bundles/features/terminal/src/client/store.ts), [src/client/refresh/tool-refresh.ts](../../bundles/features/files/src/client/refresh/tool-refresh.ts), [bundles/features/git/src/client/index.ts](../../bundles/features/git/src/client/index.ts), [terminal.md](terminal.md)).
- A refresh of the `files` reads rereads the Project's tree and file reads that are observed, and only marks an unobserved read stale; requests close together share one read, and a periodic refresh skips a read that failed or did not answer ready. [The bundle README](../../bundles/features/files/README.md#filesrefreshv1-client-100) gives the timing and the rules ([src/client/sandbox-store.ts](../../bundles/features/files/src/client/sandbox-store.ts), [packages/desktop/src/reads/refresh.ts](../../packages/desktop/src/reads/refresh.ts)).

### `files.sandbox/v1`

`files.sandbox/v1` 1.0.0 is the window's one tree read per Project and raw working directory, shared by every observer through `observeTree`, which reads only while observed. Its observation is in [the bundle README](../../bundles/features/files/README.md#filessandboxv1-client-100) ([src/contracts/index.ts](../../bundles/features/files/src/contracts/index.ts), [src/client/sandbox-store.ts](../../bundles/features/files/src/client/sandbox-store.ts)).

### File tabs and the viewer

- The command `files.open-file/v1` opens a file of a Project as the tab `file:<path>` through `layout.tabs/v2`, titled with the file's name and drawn by `files-file-view`; opening a file whose tab is open selects that tab. The tab belongs to the owner that [`workspace`](../../bundles/desktop/workspace/README.md#selection-and-routes) names to [`layout`](../../bundles/desktop/layout/README.md#layouttabsv2-200): the route's Thread, else `project:<projectId>` on `/projects/:projectId` with a Project selected. With no owner, `open` rejects with `unavailable` and `No thread or project is selected.`, and the tree's row click ignores that rejection, so nothing opens. [The bundle README](../../bundles/features/files/README.md#filesopen-filev1-client-command-100) gives its input and the tab it opens ([bundles/desktop/layout/src/client/services/layout-tabs.ts](../../bundles/desktop/layout/src/client/services/layout-tabs.ts), [src/contracts/index.ts](../../bundles/features/files/src/contracts/index.ts), [src/client/commands.ts](../../bundles/features/files/src/client/commands.ts), [bundles/desktop/workspace/src/client/index.ts](../../bundles/desktop/workspace/src/client/index.ts), [bundles/desktop/workspace/src/client/domain/route-selection.ts](../../bundles/desktop/workspace/src/client/domain/route-selection.ts), [src/client/tree/files-tree.tsx](../../bundles/features/files/src/client/tree/files-tree.tsx)).
- Clicking a file row runs that command, so the file opens beside the conversation and the tree stays as it is ([src/client/tree/files-tree.tsx](../../bundles/features/files/src/client/tree/files-tree.tsx)).
- A file tab's context menu holds Reveal in Files. It opens the file's ancestor folders under the tree's root, selects the Files view with `layout.panel/v3.select('files')` and selects the tab, so the tree selects the file's row. A file outside the root, or of a Project other than the selected one, only selects the Files view and the tab, without opening folders ([src/client/commands.ts](../../bundles/features/files/src/client/commands.ts)).
- File tabs share the viewer with the comparisons of [git.md](git.md), the terminals of [terminal.md](terminal.md) and the Thread tabs that [`chat`](../../bundles/desktop/chat/README.md) opens when `workspace` asks ([conversation.md](conversation.md)); a delegated child Thread ([delegation.md](delegation.md)) opens there like any other Thread. The viewer is a resizable column beside the conversation, present while a tab is open. Each owner keeps its own tabs and their order. A tab stays mounted while another is selected or the tabs are reordered, so a file keeps its editor and position. Its tabs are 28 px pills that reorder by dragging (from 6 px of movement) or with Alt+Shift+Left/Right, close with a middle click, and drop their transitions under reduced motion; [ui-redesign.md](ui-redesign.md) describes them ([bundles/desktop/layout/src/client/components/templates/workspace-layout.tsx](../../bundles/desktop/layout/src/client/components/templates/workspace-layout.tsx), [packages/desktop/src/panels/tab-strip.tsx](../../packages/desktop/src/panels/tab-strip.tsx), [packages/desktop/src/panels/use-tab-strip.ts](../../packages/desktop/src/panels/use-tab-strip.ts), [bundles/desktop/layout/src/client/services/layout-tabs.ts](../../bundles/desktop/layout/src/client/services/layout-tabs.ts), [bundles/desktop/layout/src/client/components/organisms/workspace-tabs.tsx](../../bundles/desktop/layout/src/client/components/organisms/workspace-tabs.tsx), [bundles/desktop/chat/src/client/services/thread-tabs.ts](../../bundles/desktop/chat/src/client/services/thread-tabs.ts)).
- The tab reads the file on demand through `files/v1.content` as text, and refreshes with the Project. Until the first answer it shows twelve skeleton lines; a later read keeps the text on screen. A failed read is the tab's own toast, with `Try again`, and a tab whose first read fails has an empty body; a file the sandbox cannot give shows `This file cannot be shown` with the sentence of `sandboxNotice` ([src/client/file/file-view.tsx](../../bundles/features/files/src/client/file/file-view.tsx), [src/client/reads/state.ts](../../bundles/features/files/src/client/reads/state.ts)).
- The text is drawn by a read-only Monaco editor, with the language its path calls for, no minimap and no word wrap, in the app's theme, which follows the color scheme. Monaco loads once per window, on the first editor, with its editor worker only, as the [`desktop` README](../../packages/desktop/README.md#code-view-and-diff-editor-desktopuicode) describes. A new read of the file keeps the reader's position ([src/client/file/file-view.tsx](../../bundles/features/files/src/client/file/file-view.tsx), [packages/desktop/src/code/code-view.tsx](../../packages/desktop/src/code/code-view.tsx), [packages/desktop/src/code/monaco.ts](../../packages/desktop/src/code/monaco.ts), [packages/desktop/src/code/monaco-runtime.ts](../../packages/desktop/src/code/monaco-runtime.ts)).
- A binary file shows `This is a binary file, so its contents are not shown.` A file past the read limit shows its first part and `This file is larger than the read limit, so only its first part is shown.` ([src/client/file/file-view.tsx](../../bundles/features/files/src/client/file/file-view.tsx), [src/client/reads/state.ts](../../bundles/features/files/src/client/reads/state.ts)).
- The tab has its own footer: the file's workspace-relative path in a monospace font, cut at the end when it is too long, with the whole path as its tooltip, and `Updating…` while a read is on its way ([src/client/file/file-view.tsx](../../bundles/features/files/src/client/file/file-view.tsx)).
- The bundle's style sheet shapes Monaco's scrollbar slider as the app's other scroll areas; [the bundle README](../../bundles/features/files/README.md#parts) gives the rule ([src/client/styles.css](../../bundles/features/files/src/client/styles.css)).
