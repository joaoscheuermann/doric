# Feature: thread archive

- Status: `implemented`

## Problem

Every Thread of a Project sits in the sidebar's Thread tree. Agents spawn many agent threads, and main threads go unused for days, so the tree grows past what the reader can scan. The reader needs to hide a Thread without deleting it: an agent thread that is not archived cannot be deleted, and the spawn card in its parent's conversation still opens it. Finished agent threads and inactive main threads should leave the tree on their own, while a Thread that still needs the reader (a failure, a question, an unread result, a pin, or a window showing it) stays in view.

## Decisions

- Archived is a field on the Thread, not a state. The public record carries optional `archivedAt` (ISO 8601) and optional `pinned`; the stored document (`runtime.thread/v1` 1.3.0) keeps `archive: { at, batch }`, `pinned`, `restoredAt`, `viewedAt` and `result.reason`. Absent means not archived, not pinned, never restored, never viewed. `ThreadOutcome` does not change, and no archive reason is recorded.
- Archive, restore, pin and view writes do not move `updatedAt` and do not recompute `open`, so a sweep never makes a Project look active.
- The rules are pure functions; the archiver and the service only gather facts and write.
- The agent-thread rule archives only the Thread itself, never its descendants. Its 30 s delay counts from the later of the turn's end and the end of the last view.
- A restored Thread (by Restore, Undo or un-archiving by activity) is not archived on its own again until a turn ends after the restore. Restoring counts as activity for the main-thread rule, and until such a turn ends the restored Thread counts as pending, so its main thread's subtree is not archived by inactivity.
- The main-thread rule evaluates the whole subtree: no non-archived Thread in it may be pending. Its activity time is the latest `createdAt` or `result.at` in the subtree, archived Threads included, or the main thread's restore time. When it fires it archives the main thread and every non-archived descendant in one batch.
- A manual archive refuses a busy target. It archives the target and every non-archived descendant except busy and pinned ones, failed and cancelled ones included, in one batch.
- A Thread never viewed has no unread result.
- New activity un-archives the one Thread it reaches, never its ancestors, at four points of the runner: an accepted input, a resumed prompt, a resumed queue that took jobs, and the start of a run. A delivered child result un-archives its parent.
- Restore un-archives the target and every descendant carrying the same batch. Undo is a Restore that names the batch the archive answered, so it still restores the rest of the batch when activity already un-archived the target.
- Presence is a desktop-exposed stream: a view lasts while its stream is open. The runtime counts views per Thread across windows, with no TTL or heartbeat.
- The archiver is one sweep every 10 s over the live Projects, for both rules, with no per-Thread timers; an agent thread is archived 30 s to 40 s after the later of its turn's end and its last view's end, plus the time its write waits for the Project lock.
- Settings apply at the next sweep, which reads the configuration each time; there is no configuration-change hook. Turning the agent-thread toggle on archives, at the next sweep, every eligible agent thread whose last turn ended after its restore time.
- Archive, restore and the rule writes run under the Project lock, and they update the live record before publishing it.
- `deleteThread` refuses an agent thread only while it is not archived; the subtree must still be terminal. The sidebar offers Delete on an archived agent thread.
- No REST change: archive, restore, pin and view are desktop-exposed only, and each changed record goes out as a Thread update (`thread:updated`), with no new Socket.IO event ([transport](../../bundles/foundation/transport/README.md)).
- The configuration's `threads: { autoArchive: { agentThreads, mainThreadsAfter } }` is strict, optional and last in the configuration; absent keys mean `agentThreads: true` and `mainThreadsAfter: '7d'`. The default configuration does not change.
- The Chat tab draws non-archived Threads and the archived ancestors of one (dimmed, archive mark, still selectable, Restore in their menu). The Archived tab draws, per date section, the Threads archived in that section and their ancestors as inert context rows. The search filters the open tab's tree.
- Pin and Unpin are context-menu entries; a pinned row shows a pin mark at rest, which turns into an Unpin button on hover or focus. A row's hover actions are, right to left, the plus, Archive, and Unpin on a pinned row.
- UI text is English; the agent-thread switch is "Archive finished agent threads".
- The sidebar tab is window state, not persisted, kept across Project changes. Beginning a sidebar draft row switches to the Chat tab. Selecting an archived Thread (spawn card, route, Archived tab) neither switches the sidebar tab nor un-archives it.
- Only the reader's stop (`result.reason: 'interrupted'`) blocks the rules; a parent's stop, a removed queued input and a close do not.
- The host decides an open question from the result text alone, with `hasQuestionForm`, built from the same fence and question-line rules the chat and openui read, in `runtime/contracts`. The runtime reads no `openui.answered/v1` row and takes no dependency on openui.
- A sweep reads storage outside the Project lock and decides again under the lock before writing. It never waits for a Project lock: a Project whose previous write has not finished is skipped.
- Archive and restore are one store commit each; a commit over the storage batch limit (about 5 000 Threads) is refused with `limit_exceeded` before anything is written. The sweep tries again at its next pass.
- Every time the feature writes or compares comes from `Date`; only the sweep's scheduler is injected.
- When its generation starts draining, the archiver stops sweeping and ends every open view stream with `unavailable`, so each window opens it again on the active generation. A Project is swept only once it has been live in the process for 30 s.
- The Archived tab's delete dialog names how many non-archived descendants the delete removes.
- In the window, the refusals `busy`, `already_archived` and `not_archived` are `ClientError('conflict')`; an archive time that does not parse groups as Older.

## Current behavior and contracts

The runtime owns the archive: the record fields, the four calls, the rules and the sweep ([runtime](../../bundles/runtime/runtime/README.md)). The host configuration carries the auto-archive choice ([host-config](../../bundles/foundation/host-config/README.md)), which Settings edits ([settings](../../bundles/desktop/settings/README.md)). A window reaches the calls through its records mirror, `runtime.records/v1`: the sidebar ([workspace](../../bundles/desktop/workspace/README.md)) archives, restores and pins through it, and the chat ([chat](../../bundles/desktop/chat/README.md)) reports which Threads the window shows. The chat and openui ([openui](../../bundles/features/openui/README.md)) read question forms with the same fence rules as the runtime.

### Record and storage

- The public `Thread` (`runtime.threads/v1` 1.8.0) carries optional `archivedAt` and `pinned` ([bundles/runtime/runtime/src/contracts/model.ts](../../bundles/runtime/runtime/src/contracts/model.ts)); the stored document (`runtime.thread/v1` 1.3.0) carries `archive: { at, batch }` while archived, `restoredAt`, `pinned: true` while pinned, `viewedAt`, and `result.reason: 'interrupted'` for a reader's stop ([bundles/runtime/runtime/src/contracts/storage.ts](../../bundles/runtime/runtime/src/contracts/storage.ts)).
- The store archives a list of Threads in one commit with one `{ at, batch }`, restores a list by removing `archive` and setting `restoredAt`, sets or removes `pinned`, and writes `viewedAt`; none of these moves `updatedAt` or `open` ([bundles/runtime/runtime/src/host/store/threads.ts](../../bundles/runtime/runtime/src/host/store/threads.ts)). A commit over the storage batch limit rejects with `limit_exceeded` and writes nothing; the service logs it and rethrows ([bundles/runtime/runtime/src/host/domain/service.ts](../../bundles/runtime/runtime/src/host/domain/service.ts), `oversized`).

### The calls (`runtime.threads/v1` 1.8.0)

All four are exposed to the desktop only; the transport ([transport](../../bundles/foundation/transport/README.md)) adds no route for them and sends each published record as `thread:updated` ([bundles/foundation/transport/src/host/sockets/workspace.ts](../../bundles/foundation/transport/src/host/sockets/workspace.ts), [bundles/runtime/runtime/src/host/services/threads.ts](../../bundles/runtime/runtime/src/host/services/threads.ts), [bundles/runtime/runtime/src/contracts/threads.ts](../../bundles/runtime/runtime/src/contracts/threads.ts)). Archive, restore and pin each run under the Project lock, set the live record and publish every changed record as a Thread update ([bundles/runtime/runtime/src/host/domain/service.ts](../../bundles/runtime/runtime/src/host/domain/service.ts)). A view takes no lock; its `viewedAt` write neither updates the live record nor is published.

- `archiveThread({ id })` answers `{ status: 'archived', batch, threads }`, the target first, or `missing`, `busy` (the target is queued, running, cancelling or holds work) or `already_archived`. It archives the target and every descendant that is not archived, busy or pinned, in one batch with a new id ([bundles/runtime/runtime/src/host/domain/archive.ts](../../bundles/runtime/runtime/src/host/domain/archive.ts), `manualArchiveSet`; [bundles/runtime/runtime/src/host/domain/archiver.ts](../../bundles/runtime/runtime/src/host/domain/archiver.ts), `writeArchive`).
- `restoreThread({ id, batch? })` answers `{ status: 'restored', threads }`, or `missing`, or `not_archived` when neither the Thread nor a descendant carries the batch: `batch` when given, else the Thread's own. It restores the target when it carries that batch and every descendant carrying it, never an ancestor (`restoreSet`, [bundles/runtime/runtime/src/host/domain/archive.ts](../../bundles/runtime/runtime/src/host/domain/archive.ts)).
- `setThreadPinned({ id, pinned })` answers the record, or `undefined` for a missing Thread.
- `viewThread({ threadId }, listener)` holds a view while the stream is open and emits one `{ kind: 'viewing', threadId }`. The stream ends when disposed, when the host link closes, with `not_found` for a missing Thread, with `unavailable` when the runtime hands over to a new generation, and with `internal` after logging `Thread view failed` when the record read fails; the last three hold no view. The first view of a Thread and the end of its last view each write `viewedAt`, and the Thread counts as viewed until that last write settles ([bundles/runtime/runtime/src/host/domain/archiver.ts](../../bundles/runtime/runtime/src/host/domain/archiver.ts), `view`).
- `deleteThread` answers `forbidden` for an agent thread that is not archived; an archived agent thread is deleted with its subtree, which must be terminal ([bundles/runtime/runtime/src/host/domain/service.ts](../../bundles/runtime/runtime/src/host/domain/service.ts), [bundles/runtime/runtime/src/host/store/threads.ts](../../bundles/runtime/runtime/src/host/store/threads.ts), `deleteSubtree`).

### The rules

A main thread is a Thread with no parent; an agent thread is one with origin `agent` and a parent. A child Thread the reader opened is neither, so the rules archive it only with its main thread's subtree. The rules read, per Thread: the record, its batch, `restoredAt`, `viewedAt`, whether the stored result is a reader's stop, whether it is busy (state queued, running or cancelling, or live jobs, an active prompt or a storage pause in this process), whether a view is held, and whether its result text holds a question form ([bundles/runtime/runtime/src/host/domain/archiver.ts](../../bundles/runtime/runtime/src/host/domain/archiver.ts), `factsOf`; [bundles/runtime/runtime/src/host/domain/archive.ts](../../bundles/runtime/runtime/src/host/domain/archive.ts)).

- Agent-thread rule (`finishedDue`): with `agentThreads` on, an agent thread, itself not archived and not pinned, in state `ready` or `cancelled`, whose queue is not paused, with no question form, not busy and not viewed, whose result is `completed` or `cancelled` without a reader's stop, and with no restore or a turn ended after it, is due at the later of `result.at` and `viewedAt`, plus 30 s. It is archived alone.
- A Thread is pending for the main-thread rule (`pending`) when it is not archived and any of these holds: state queued, running, cancelling or failed; a paused queue; a question form; busy; viewed; pinned; a failed result or a reader's stop; a result that ended after `viewedAt` (unread; a Thread with no `viewedAt` has none); or a restore with no turn ended since.
- Main-thread rule (`inactiveDue`): with `mainThreadsAfter` other than `never`, a main thread that is not archived and whose subtree holds no pending Thread is due at the latest `createdAt` or `result.at` in the subtree (archived Threads included) or its own `restoredAt`, plus 1, 7 or 30 days. It is archived with every non-archived descendant in one batch.
- The question test is `hasQuestionForm(result.text)` ([bundles/runtime/runtime/src/contracts/fences.ts](../../bundles/runtime/runtime/src/contracts/fences.ts)): walking the trimmed text's lines, every fence opened with three or more backticks or tildes runs to the first line that closes it, or to the end of the text; a fence tagged `openui-lang` whose first non-blank completed line matches `root = AskForm(` is a question form, wherever in the text it sits. A Thread without a result has no question form. Answering a form is the reader's next message, whose turn replaces the result.
- The same file exports the line rules the chat reads fences with (`fenceMarker`, `closesFence`, `fenceInfo`; [bundles/desktop/chat/src/client/domain/fences.ts](../../bundles/desktop/chat/src/client/domain/fences.ts)) and the ones openui reads programs with (`completedStatements`, `firstCompletedLine`, `isQuestionLine`; [bundles/features/openui/src/contracts/fold.ts](../../bundles/features/openui/src/contracts/fold.ts), [bundles/features/openui/src/client/folds.ts](../../bundles/features/openui/src/client/folds.ts)).

### The sweep

- The archiver arms a sweep 10 s after it is created and each next one 10 s after the previous ends, on a timer that does not keep the process alive ([bundles/runtime/runtime/src/host/domain/archiver.ts](../../bundles/runtime/runtime/src/host/domain/archiver.ts)).
- Each sweep reads `threads.autoArchive` from the configuration, defaults applied (`autoArchiveSettings`, [bundles/runtime/runtime/src/host/domain/archive.ts](../../bundles/runtime/runtime/src/host/domain/archive.ts); [bundles/runtime/runtime/src/host/domain/service.ts](../../bundles/runtime/runtime/src/host/domain/service.ts)); a failed read logs a warning and skips that sweep.
- For each live Project it skips one that is closing, one first seen by a sweep less than 30 s ago, and one whose previous write has not finished. It reads the Project's Threads outside the lock; when a group is due, it starts the write as its own task and goes on. The write takes the Project lock, reads and decides again, and archives each due group in one batch: first each main thread due by inactivity with its subtree, then each due agent thread not in such a group; every group overdue at that moment is archived in the same pass. A failed group write ends that Project's pass, and its remaining due groups wait for the next sweep. A failed read or write is logged, and the next sweep tries again.
- On drain the archiver stops sweeping and ends every open view with `unavailable`; a view asked for after that ends at once.

### Un-archiving by activity

- The runner un-archives the Thread an activity reaches: an accepted input, a resumed prompt, a resumed queue that took jobs, and the start of a run. A child's result is delivered as an input to its parent, so it un-archives the parent. Un-archiving restores that Thread alone, writing `restoredAt`, and publishes it; a failure logs `Could not un-archive a Thread` and leaves the input to go on ([bundles/runtime/runtime/src/host/domain/runner.ts](../../bundles/runtime/runtime/src/host/domain/runner.ts), `wake`).

### Configuration and Settings

- The configuration's optional, strict `threads: { autoArchive: { agentThreads?: boolean, mainThreadsAfter?: '1d' | '7d' | '30d' | 'never' } }` (`host-config/v1` and `host-config.configuration/v1` 1.2.0) refuses unknown keys; absent means `agentThreads: true` and `mainThreadsAfter: '7d'` ([bundles/foundation/host-config/src/contracts/index.ts](../../bundles/foundation/host-config/src/contracts/index.ts), [bundles/foundation/host-config/src/host/config/schema.ts](../../bundles/foundation/host-config/src/host/config/schema.ts)).
- Settings has a Threads section (order 25, between Execution and Tools) with the Auto-archive group: the switch "Archive finished agent threads" and the choice "Archive inactive main threads after" (1 day, 7 days noted default, 30 days, Never). An absent policy shows the defaults, and each change goes into the window's draft, which autosaves ([bundles/desktop/settings/src/client/domain/sections.ts](../../bundles/desktop/settings/src/client/domain/sections.ts), [bundles/desktop/settings/src/client/components/organisms/settings-threads.tsx](../../bundles/desktop/settings/src/client/components/organisms/settings-threads.tsx)). The save keeps only the known keys of `threads` and refuses a value no host accepts ([bundles/desktop/settings/src/client/api/settings-api.ts](../../bundles/desktop/settings/src/client/api/settings-api.ts)). Settings requires `host-config/v1@^1.2.0`.

### The window: records mirror, sidebar and views

- `runtime.records/v1` 1.0.0 offers `archiveThread({ threadId })` (resolving `{ batch, threads }`), `restoreThread({ threadId, batch? })`, `setThreadPinned({ threadId, pinned })` and `view({ threadId })`; each write puts every answered record into the mirror ([bundles/runtime/runtime/src/contracts/records.ts](../../bundles/runtime/runtime/src/contracts/records.ts), [bundles/runtime/runtime/src/client/records.ts](../../bundles/runtime/runtime/src/client/records.ts)). A `missing` answer rejects with `ClientError('not_found')`; `busy`, `already_archived` and `not_archived` reject with `ClientError('conflict')` ([bundles/runtime/runtime/src/client/api/workspace-api.ts](../../bundles/runtime/runtime/src/client/api/workspace-api.ts)). Archived Threads stay in the mirror like any other, so a spawn card or a route still opens one.
- The mirror follows one `viewThread` stream per Thread held by `view`. A silent end (`disconnected`, `unavailable`, `generation_lost`) opens the stream again, so a view survives a runtime hand-over; a failing end drops it, until the window's views change and name the Thread again ([bundles/runtime/runtime/src/client/api/thread-views.ts](../../bundles/runtime/runtime/src/client/api/thread-views.ts)).
- The chat holds one `view` per Thread on screen: the Thread of the Thread route, and the Thread of the selected `layout.tabs/v2` tab when the chat opened that tab ([layout](../../bundles/desktop/layout/README.md)). It takes the views again on every change of the route, the tabs and the mirror, taking the new ones before disposing the previous ones, and holds none while `runtime.records/v1` is unavailable ([bundles/desktop/chat/src/client/services/thread-views.ts](../../bundles/desktop/chat/src/client/services/thread-views.ts), [bundles/desktop/chat/src/client/domain/thread-views.ts](../../bundles/desktop/chat/src/client/domain/thread-views.ts)).
- The sidebar ([bundles/desktop/workspace/src/client/components/organisms/project-sidebar.tsx](../../bundles/desktop/workspace/src/client/components/organisms/project-sidebar.tsx)) draws two icon-only tabs above the Thread tree, Chat and Archived, each with a tooltip and no counter ([bundles/desktop/workspace/src/client/components/molecules/sidebar-tabs.tsx](../../bundles/desktop/workspace/src/client/components/molecules/sidebar-tabs.tsx)). The open tab is component state, Chat at first, kept across Project changes; it returns to Chat when the sidebar is drawn again after the dashboard ([bundles/desktop/workspace/src/client/elements/navigation-elements.tsx](../../bundles/desktop/workspace/src/client/elements/navigation-elements.tsx)), and beginning a draft switches to Chat. ⌘F (Ctrl+F), without Alt or Shift and not from a Monaco editor or a terminal, focuses the search, which filters the open tab's tree.
- Chat tab: every non-archived Thread and every archived ancestor of one, plus an archived parent a draft row names, with its ancestors; the archived ones are context rows, dimmed with an archive mark, selectable, with Restore in their menu ([bundles/desktop/workspace/src/client/domain/thread-archive.ts](../../bundles/desktop/workspace/src/client/domain/thread-archive.ts), `chatThreads`). A Chat row's hover actions are, right to left, the plus, Archive when the row is archivable (not archived and not queued, running or cancelling), and Unpin on a pinned row, which shows a pin mark at rest. Its context menu has "Pin thread" or "Unpin thread" on every row, busy ones included, and "Archive thread" only when the row is archivable ([bundles/desktop/workspace/src/client/components/molecules/thread-branches.tsx](../../bundles/desktop/workspace/src/client/components/molecules/thread-branches.tsx), [bundles/desktop/workspace/src/client/components/molecules/row-add-action.tsx](../../bundles/desktop/workspace/src/client/components/molecules/row-add-action.tsx), [bundles/desktop/workspace/src/client/components/molecules/item-context-menu.tsx](../../bundles/desktop/workspace/src/client/components/molecules/item-context-menu.tsx)).
- Archive needs no confirmation: it shows the toast "Thread archived" with `"<name or Untitled>" moved to Archived`, whose Undo restores the answered batch. Restore and pin show no toast. A failed write is stored as the workspace error ([bundles/desktop/workspace/src/client/hooks/use-workspace.ts](../../bundles/desktop/workspace/src/client/hooks/use-workspace.ts)).
- Archived tab: the archived Threads grouped by their archive time in local time into Today (from today's local midnight), Last 7 days (from the local midnight seven days before that) and Older; sections run newest first, rows inside a section keep the list's order, and each section draws its archived Threads with every ancestor; an ancestor not archived in that section is an inert context row, including one archived in another section ([bundles/desktop/workspace/src/client/domain/thread-archive.ts](../../bundles/desktop/workspace/src/client/domain/thread-archive.ts), `archivedSections`). Archived rows offer Restore and Delete on hover and in their menu; an archived Thread of any kind offers Delete ([bundles/desktop/workspace/src/client/domain/thread-kind.ts](../../bundles/desktop/workspace/src/client/domain/thread-kind.ts), `threadControl`). The tab shows "No archived threads" with no archived Thread, and "No threads match" when the search matches none ([bundles/desktop/workspace/src/client/components/organisms/archived-threads.tsx](../../bundles/desktop/workspace/src/client/components/organisms/archived-threads.tsx)).
- Deleting an archived Thread removes its whole subtree; the dialog adds "1 child thread is still in Chat and will be deleted too." or "{n} child threads are still in Chat and will be deleted too." for its non-archived descendants ([bundles/desktop/workspace/src/client/elements/navigation-elements.tsx](../../bundles/desktop/workspace/src/client/elements/navigation-elements.tsx), [bundles/desktop/workspace/src/client/components/molecules/delete-dialog.tsx](../../bundles/desktop/workspace/src/client/components/molecules/delete-dialog.tsx)).
