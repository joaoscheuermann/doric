# Feature: Resource monitor

- Status: `implemented`

## Problem

The reader needs to see how hard the agent's environment is working: how much CPU and memory the selected Project's sandbox uses against what it was given, and how loaded the machine Doric runs on is. Looking must never change what it observes: a reading must not bring a Project up, restart its sandbox or interrupt the agent, and a provider that cannot measure must leave the sandbox working. The reading must stay on screen without flicker, and draw attention only when a value crosses a threshold.

## Decisions

- The connection badge draws the cloud-fill glyph when connected and the cloud-off-fill glyph when disconnected. The two glyphs ship inside the `resources` bundle; no shared icon module holds them, since no other surface draws them.
- Connected, with a memory or a CPU warning set on the sandbox or the machine reading, the badge draws the cloud-fill glyph in the theme's warning tone. The button carries `data-status` `connected`, `disconnected` or `warning`.
- The badge is one 14×14 button named "Connection and resources", its own Tab stop apart from the avatar button. It builds its accessible description itself: "Connected" or "Disconnected", followed by " · memory high" and " · CPU high" for each warning set.
- Polling and the sustained-CPU verdict live in the always-mounted badge, not in the popover, so the readings and the tone stay current while the popover is closed.
- The popover's "Updated … ago" is measured from the sandbox reading's time, else from the machine reading's; with neither, the header reads "Connected" alone.
- `resources/v1.project()` reads the sandbox on the lease the Project holds now and never acquires one. A sandbox whose provider has no reading, or whose reading fails, answers a ready outcome with an `unavailable` container.
- The machine's CPU sample is module state of the process that serves `resources/v1`, so the first reading of that process has no CPU percent.
- `runtime.lease/v1` has no resource read: the Project read is `resources/v1.project()` alone.
- `ContainerResources` and its schema are declared in `resources/contracts`. `LeaseOutcome` stays in `runtime/contracts`, and `resources/contracts` imports and re-exports it from there.
- The host's REST routes call `resources/v1` through the platform's services, not through requires of the `transport` bundle.
- The client part names its slot as the literal `'account.status'`, checked against `ACCOUNT_STATUS` through a type-only import of `account/contracts`, never a value import. Without the `account` bundle the badge is absent, and nothing reports it.
- `workspace.selection/v1` and `runtime.records/v1` are both under `requires` of the bundle.
- The client part has its own query client, with nothing retried or refetched unless a query asks for it, and caches under the keys `['resources', 'host']` and `['resources', projectId]`.

## Current behavior and contracts

### The bundle

- The `resources` bundle, version 1.1.5, provides `resources/v1@1.0.0`. It requires `runtime.lease/v1`, `ui/v1`, `regions/v1`, `workspace.selection/v1` and `runtime.records/v1`, and the desktop may call `resources/v1` with the scope keys `projectId`, `threadId` and `promptId` ([manifest.json](../../bundles/features/resources/manifest.json)). The bundle's [README](../../bundles/features/resources/README.md) describes the bundle, its contract and its development commands.
- The host part provides `resources/v1`; the client part defines the element `<resources-monitor>` and adds it to the account status ([src/host/index.ts](../../bundles/features/resources/src/host/index.ts), [src/client/index.ts](../../bundles/features/resources/src/client/index.ts)).

### The `resources/v1` contract

- `resources/v1` (1.0.0) has two reads, both with no input and both callable from the desktop ([src/contracts/index.ts](../../bundles/features/resources/src/contracts/index.ts), [src/host/index.ts](../../bundles/features/resources/src/host/index.ts)):
  - `host()` answers `HostResources`: `at` (ISO-8601), `cpuCount`, `cpuPercent?` (0 to 100 across every core), `loadAverage?`, `memoryTotalBytes`, `memoryUsedBytes` and `uptimeSeconds`. It needs no Project and no lease.
  - `project()` answers `LeaseOutcome<ContainerResources>` for the Project of `call.scope.projectId`: `{ status: 'ready', value }`, or `{ status }` with `pending`, `unavailable`, `expired` or `missing`. `ContainerResources` is `status` (`ready` or `unavailable`), `at`, and the optional `cpuPercent`, `cpuCount`, `memoryUsedBytes` and `memoryLimitBytes`.

### Reading the machine

- `host()` reads the machine the host process runs on from `node:os`. Memory used is the total minus the free memory, the load average is the one-minute average, and uptime is rounded to whole seconds ([src/host/machine.ts](../../bundles/features/resources/src/host/machine.ts)).
- The CPU percent is the busy share of every core between this reading and the previous one, from the cumulative per-core counters, clamped to 0 to 100. The process keeps one previous sample, shared by every caller, so the first reading has no percent, and so does a reading whose counters did not advance ([src/host/machine.ts](../../bundles/features/resources/src/host/machine.ts)).

### Reading a Project's sandbox

- `project()` runs its read through `runtime.lease/v1.withLease` in the call's scope. `withLease` never acquires a lease: a Project with no record answers `missing`, one in a terminal state `expired`, one without a live runtime or that is closing `unavailable`, and one whose lease is still being acquired `pending`. A Project whose closing starts or whose lease drops while the read runs answers `unavailable`. A call whose scope has no `projectId` rejects with `invalid_input` and the message "runtime.lease/v1 needs a Project or Thread scope.", and the read of a Project in standby waits until this process adopts it ([src/host/index.ts](../../bundles/features/resources/src/host/index.ts), [bundles/runtime/runtime/src/host/domain/service.ts](../../bundles/runtime/runtime/src/host/domain/service.ts), [bundles/runtime/runtime/src/contracts/lease.ts](../../bundles/runtime/runtime/src/contracts/lease.ts), [bundles/runtime/runtime/src/host/services/lease.ts](../../bundles/runtime/runtime/src/host/services/lease.ts)). The lease states are described in [Projects and Threads](projects-and-threads.md) and in the [`runtime` README](../../bundles/runtime/runtime/README.md).
- On a live lease the bundle calls the sandbox's `stats()`. It answers a `ready` container with the fields the provider measured and the time the bundle read it (the provider's own `at` is not kept). A sandbox without `stats`, a `stats()` that answers `undefined`, and a `stats()` that throws all answer an `unavailable` container, so a provider that cannot measure never fails the read and never brings a Project down ([src/host/container.ts](../../bundles/features/resources/src/host/container.ts), [packages/sandbox/src/lib/sandbox.ts](../../packages/sandbox/src/lib/sandbox.ts)).
- `Sandbox.stats()` is a read: it never provisions, restarts or interrupts anything. Each provider normalizes it to the sandbox's own allotment, so a sandbox using every core it was given reads 100 percent ([packages/sandbox/src/lib/types/sandbox.ts](../../packages/sandbox/src/lib/types/sandbox.ts), [the `sandbox` README](../../packages/sandbox/README.md)). The providers and their bundles are described in [Sandboxes](sandboxes.md) and in the READMEs of the [`docker`](../../bundles/sandboxes/docker/README.md) and [`firecracker`](../../bundles/sandboxes/firecracker/README.md) bundles:
  - Docker reads the daemon's container statistics. The CPU percent is the container's share of the host between the daemon's two samples, scaled from the host's online CPUs to the cores the sandbox was given; memory used is the usage minus the reclaimable file cache, against the container's memory limit ([packages/docker-sandbox/src/lib/provider.ts](../../packages/docker-sandbox/src/lib/provider.ts), [packages/docker-sandbox/src/lib/mapping.ts](../../packages/docker-sandbox/src/lib/mapping.ts)).
  - Firecracker reads its guest's `/proc/stat` and `/proc/meminfo`. The CPU percent is measured between two reads, so the first read has none; memory is measured from `MemTotal` and `MemAvailable`, with `MemTotal` as the limit, and `cpuCount` is the cores the VM was given. A guest read that fails throws, which the bundle answers as `unavailable` ([packages/firecracker-sandbox/src/lib/runtime.ts](../../packages/firecracker-sandbox/src/lib/runtime.ts), [packages/firecracker-sandbox/src/lib/stats.ts](../../packages/firecracker-sandbox/src/lib/stats.ts)).

### The REST routes

- The host serves the two reads over REST, with `Cache-Control: no-store` ([bundles/foundation/transport/src/host/routes/resources.ts](../../bundles/foundation/transport/src/host/routes/resources.ts), [bundles/foundation/transport/src/host/routes/projects.ts](../../bundles/foundation/transport/src/host/routes/projects.ts), [the `transport` README](../../bundles/foundation/transport/README.md)):
  - `GET /resources` answers `resources/v1.host()` unchanged; a call that fails, including one with no `resources/v1` provider, answers `500 internal_error` ([bundles/foundation/transport/src/host/routes/resources.ts](../../bundles/foundation/transport/src/host/routes/resources.ts), [bundles/foundation/transport/src/host/app.ts](../../bundles/foundation/transport/src/host/app.ts), [bundles/foundation/transport/src/host/errors.ts](../../bundles/foundation/transport/src/host/errors.ts)).
  - `GET /projects/:id/resources` calls `resources/v1.project()` bound to that Project. A ready outcome answers the container, whether `ready` or `unavailable`. The lease states answer as every Project workspace read does: `missing` is `404 project_not_found`, `pending` is `202 { status: 'pending' }` with `Retry-After: 1`, `expired` is `410 project_files_expired`, and `unavailable` is `409 project_files_unavailable`. An `:id` that is not a UUID answers `400 invalid_project_id`; a call that fails, including one with no `resources/v1` provider, answers `500 internal_error` ([bundles/foundation/transport/src/host/routes/projects.ts](../../bundles/foundation/transport/src/host/routes/projects.ts), [bundles/foundation/transport/src/host/routes/input.ts](../../bundles/foundation/transport/src/host/routes/input.ts), [bundles/foundation/transport/src/host/errors.ts](../../bundles/foundation/transport/src/host/errors.ts)).

### In the window

- The client part adds the item `{ id: 'resources', tag: 'resources-monitor', order: 10 }` to the `account.status` slot of the `account` bundle, which draws its items in a 14×14 box over the bottom-right corner of the reader's avatar ([src/client/index.ts](../../bundles/features/resources/src/client/index.ts), [bundles/desktop/account/src/client/components/organisms/account-status.tsx](../../bundles/desktop/account/src/client/components/organisms/account-status.tsx), [the `account` README](../../bundles/desktop/account/README.md)). Where the account status sits in the window is described in [UI redesign](ui-redesign.md).
- The element reads the selected Project's id from `workspace.selection/v1.current()` and whether the window is connected from `runtime.records/v1.connection()`, each followed through its contract's `subscribe`. While no provider serves `runtime.records/v1`, the badge shows Disconnected; while none serves `workspace.selection/v1`, only the machine is read. A composition without the `runtime` or the `workspace` bundle quarantines `resources` with `missing_dependency` ([src/client/monitor/resources-monitor.tsx](../../bundles/features/resources/src/client/monitor/resources-monitor.tsx), [src/client/api/peers.ts](../../bundles/features/resources/src/client/api/peers.ts), [packages/bundle/src/runtime/catalog.ts](../../packages/bundle/src/runtime/catalog.ts)). The selection is described in the [`workspace` README](../../bundles/desktop/workspace/README.md), the connection in the [`runtime` README](../../bundles/runtime/runtime/README.md).
- The element calls `resources/v1` directly: `host()` with no scope, and `project()` bound to `{ projectId }`. A Project id that is empty, longer than 200 characters or holds a NUL fails with "The item identifier is invalid.". A `pending` outcome is kept with a retry hint of one second. A failed call rejects with "Doric backend is unavailable." when the host is unreachable, "Doric returned an invalid response." for an invalid answer, and "The request could not be completed." otherwise. These messages reach no screen: the monitor keeps its last reading (see [Polling](#polling)) ([src/client/api/resources.ts](../../bundles/features/resources/src/client/api/resources.ts)).

### Polling

- While the badge is mounted it polls the machine every 3 seconds, and the selected Project's sandbox every 3 seconds too, or every second while the Project's lease is pending. With no Project selected the sandbox is not read. Both reads also refetch when the window regains focus and the reading is more than a second old, and each retries twice before it fails ([src/client/hooks/use-resources.ts](../../bundles/features/resources/src/client/hooks/use-resources.ts), [packages/desktop/src/reads/read-policy.ts](../../packages/desktop/src/reads/read-policy.ts)).
- A failed read keeps the last reading on screen: the monitor never blanks, shows no error and raises no toast. It has no refresh button ([src/client/hooks/use-resources.ts](../../bundles/features/resources/src/client/hooks/use-resources.ts), [src/client/monitor/connection-badge.tsx](../../bundles/features/resources/src/client/monitor/connection-badge.tsx)).

### Thresholds

- Memory warns at 85 percent of its limit or more: the container's memory limit for the sandbox, the total memory for the machine. With no limit, memory never warns ([src/client/domain/resources.ts](../../bundles/features/resources/src/client/domain/resources.ts), [src/client/monitor/resource-monitor.tsx](../../bundles/features/resources/src/client/monitor/resource-monitor.tsx)).
- CPU warns only when sustained: three consecutive readings at 90 percent or more. A reading below 90 percent, or with no percent, ends the run. Only a reading with a new time advances the count, so one reading never counts twice ([src/client/domain/resources.ts](../../bundles/features/resources/src/client/domain/resources.ts), [src/client/hooks/use-resources.ts](../../bundles/features/resources/src/client/hooks/use-resources.ts)).
- Only the value that crossed a threshold wears the warning tone, in its text and its bar ([src/client/monitor/resource-monitor.tsx](../../bundles/features/resources/src/client/monitor/resource-monitor.tsx)).

### The badge and the popover

- The badge is a cloud: green when connected, a red cloud-off when disconnected, and the warning tone when connected with any warning on either reading. Disconnected overrides the warnings, in the tone and in the accessible description ([src/client/monitor/connection-badge.tsx](../../bundles/features/resources/src/client/monitor/connection-badge.tsx), [src/client/monitor/cloud-glyphs.ts](../../bundles/features/resources/src/client/monitor/cloud-glyphs.ts)).
- A click opens a 256 px popover below the badge. Its header reads "Connected · Updated Ns ago" (in seconds, then minutes, then hours), "Connected" when there is no reading yet, or "Disconnected". Below it come a "Sandbox" and a "Machine" section, each with a Memory and a CPU gauge; while disconnected both sections are dimmed ([src/client/monitor/connection-badge.tsx](../../bundles/features/resources/src/client/monitor/connection-badge.tsx), [src/client/monitor/resource-monitor.tsx](../../bundles/features/resources/src/client/monitor/resource-monitor.tsx), [src/client/domain/resources.ts](../../bundles/features/resources/src/client/domain/resources.ts)).
- Memory reads as used over limit in the unit of the larger, such as "0.3 / 2 GiB", or the used value alone, with no bar, without a limit; CPU reads as a whole percent. A value with no reading shows "—" and no bar ([src/client/domain/resources.ts](../../bundles/features/resources/src/client/domain/resources.ts), [src/client/monitor/resource-monitor.tsx](../../bundles/features/resources/src/client/monitor/resource-monitor.tsx)).
- The Sandbox section shows a sentence in place of its gauges when there is nothing to measure: "Preparing environment…" while the lease is pending, "Environment unavailable" when it is unavailable, expired or missing, and "Resources unavailable in this provider" when the provider has no reading. With no Project selected the Sandbox gauges show "—". The Machine section depends on no lease ([src/client/domain/resources.ts](../../bundles/features/resources/src/client/domain/resources.ts), [src/client/monitor/resource-monitor.tsx](../../bundles/features/resources/src/client/monitor/resource-monitor.tsx)).
