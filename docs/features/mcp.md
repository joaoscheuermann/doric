# Feature: MCP servers

- Status: `implemented`

## Problem

A Project's agent needs tools that Doric does not ship: the tools of MCP (Model Context Protocol) servers, remote ones reached over HTTP and local ones run as a command. The reader adds those servers to a Project, sees whether each one is connected, and signs in to a remote server that asks for OAuth. A server's tools, its credentials and the processes it runs must stay inside the Project the server was added to.

## Decisions

- The `mcp` bundle may reach the network from the host, run commands in a Project's sandbox and handle credentials, by the user's explicit approval under the rules that keep boundaries minimal and protect sensitive surfaces.
- The OAuth client name and scopes of an `http` server, and the MCP client info of either transport, are per-server settings, set in the Advanced section of the server's dialog, because some servers and authorization servers accept only client names they know.
- A sign-in gets its OAuth client only through dynamic client registration. A server can name no client created in its authorization server's console.
- `default` reads the skills of MCP servers through `default.skill-sources/v1`, which `default` declares and `mcp` provides. `default` imports nothing from `mcp` and does not list it as a dependency.

## Current behavior and contracts

### The bundles

- The `mcp` bundle, version 1.3.0, provides `mcp/v1` 1.2.0, the storage type `mcp.server/v1` 1.1.0 and a source of `default.skill-sources/v1` 1.0.0, and registers the credential kind `MCP_TOKEN` ([manifest.json](../../bundles/features/mcp/manifest.json), [src/host/index.ts](../../bundles/features/mcp/src/host/index.ts)). Its host part holds the servers, their connections and the OAuth sign-ins; its client part draws the sidebar's MCP pane ([src/client/index.ts](../../bundles/features/mcp/src/client/index.ts)). [The bundle's README](../../bundles/features/mcp/README.md) is the bundle's complete overview: its contracts, data, behavior, limits, errors, build and tests.
- The `default` bundle's agent uses the servers' tools as it uses any tool of `tools/v1`, which [`core`](../../bundles/foundation/core/README.md) provides ([bundles/runtime/default/src/host/executor.ts](../../bundles/runtime/default/src/host/executor.ts)); [the `default` README](../../bundles/runtime/default/README.md) describes the agent.
- The `mcp` bundle provides `default.skill-sources/v1` over its connected servers: the source lists the skills each one lists through the MCP Skills extension and reads one only when the agent loads it, through the same path as `mcp/v1.readSkill` ([src/host/index.ts](../../bundles/features/mcp/src/host/index.ts), [src/host/skills.ts](../../bundles/features/mcp/src/host/skills.ts)). [Skills](skills.md) describes how the agent lists and loads them.

### Servers belong to a Project

- Every method of `mcp/v1` works on the servers of the Project of `call.scope.projectId`; a call without a Project scope is refused with `invalid_input`. A server belongs to the Project it was created in, never to the host, and a method that names another Project's server answers `mcp_server_missing` ([src/host/index.ts](../../bundles/features/mcp/src/host/index.ts)).
- Every method but `readSkill` is reachable from a desktop window; `readSkill` is host only ([src/contracts/index.ts](../../bundles/features/mcp/src/contracts/index.ts)). [The README's method table](../../bundles/features/mcp/README.md#methods) gives each method's input, output and errors.
- Each server is one `mcp.server/v1` document, listed per Project in creation order. The document holds the server's name, whether it is enabled, its transport and the non-secret part of its OAuth state; no secret is stored in it ([src/host/store.ts](../../bundles/features/mcp/src/host/store.ts)).
- Two servers of one Project cannot have names with the same slug (`mcp_server_name_taken`). A name is trimmed, holds 1 to 64 characters and at least one ASCII letter, digit or `-`. The slug is the name lowercased, each run of characters outside `[a-z0-9-]` turned into one `_`, cut to 20 characters, with no leading or trailing `_`, so it is never empty ([src/contracts/index.ts](../../bundles/features/mcp/src/contracts/index.ts), [src/host/index.ts](../../bundles/features/mcp/src/host/index.ts)).
- A server's state is one of the seven [the README lists](../../bundles/features/mcp/README.md#statuses), from `disabled` to `error`; an `error` carries a message with every secret of the server's entries masked as `[REDACTED]` ([src/contracts/index.ts](../../bundles/features/mcp/src/contracts/index.ts), [src/host/manager.ts](../../bundles/features/mcp/src/host/manager.ts), [src/host/credentials.ts](../../bundles/features/mcp/src/host/credentials.ts)).

### Transports

- **`http`.** The host part reaches the server from the host machine over Streamable HTTP. When that fails for a reason other than authorization, it tries the HTTP+SSE transport with a new client; when both fail, the message gives the Streamable HTTP failure, then the HTTP+SSE one. Each request carries the server's own headers only ([src/host/open.ts](../../bundles/features/mcp/src/host/open.ts)).
- **`stdio`.** The server runs only in the Project's sandbox, never as a host process: the host part starts `command` and `args` through `runtime.lease/v1.withLease` of [`runtime`](../../bundles/runtime/runtime/README.md) and the sandbox's `start`, on the sandbox the Project holds, in the transport's `cwd` when it sets one. Its environment is the sandbox image's plus the server's own entries, and nothing else from the host. JSON-RPC runs newline-delimited over the process's stdin and stdout; each stderr line is masked and kept to at most its last 4,096 characters, and the last one ends the message of a server whose process closes the connection ([src/host/open.ts](../../bundles/features/mcp/src/host/open.ts), [src/host/stdio.ts](../../bundles/features/mcp/src/host/stdio.ts), [src/host/manager.ts](../../bundles/features/mcp/src/host/manager.ts)).
- A `stdio` server whose Project holds no sandbox lease, or loses it while the server starts, is `waiting-for-sandbox`; its process, if one started, is ended. A Project that does not exist or has ended, or a sandbox that cannot keep a process running, leaves the server in `error` ([src/host/open.ts](../../bundles/features/mcp/src/host/open.ts)).
- Either transport introduces itself in the MCP `initialize` request with the server's optional `clientInfo`; an absent `name` reads as `doric` and an absent `version` as `1.0.0` ([src/contracts/index.ts](../../bundles/features/mcp/src/contracts/index.ts), [src/host/open.ts](../../bundles/features/mcp/src/host/open.ts)).

### Header and environment entries

- An `http` server's header and a `stdio` server's environment variable is an entry: a literal `value`, or the `credentialId` of a stored credential whose secret is read through `secrets/v1` of [`core`](../../bundles/foundation/core/README.md) when that server connects. Only the connecting server's own entries are read ([src/contracts/index.ts](../../bundles/features/mcp/src/contracts/index.ts), [src/host/credentials.ts](../../bundles/features/mcp/src/host/credentials.ts)).
- An entry that names an `MCP_TOKEN` credential, which holds one server's sign-in, is refused with `invalid_input` on `create`, on `update` and when the server connects. A credential that holds no secret is refused when the server connects ([src/host/credentials.ts](../../bundles/features/mcp/src/host/credentials.ts), [src/host/index.ts](../../bundles/features/mcp/src/host/index.ts)).
- In the server's dialog, an entry's credential is picked with the key button from the stored credentials other than `MCP_TOKEN` ones, or a typed token is stored as a new `API_TOKEN` credential ([src/client/api.ts](../../bundles/features/mcp/src/client/api.ts), [src/client/server-dialog.tsx](../../bundles/features/mcp/src/client/server-dialog.tsx)). [Credentials](credentials.md) describes the credential store.

### When servers connect and stop

- `create` stores the server; an enabled one connects at once when a window already watches its Project, else when its Project is next watched. `update` stores the change and reconnects the server when it was live or its Project is watched, or stops it when it is disabled. Disposing the last watch keeps the connections ([src/host/index.ts](../../bundles/features/mcp/src/host/index.ts), [src/host/manager.ts](../../bundles/features/mcp/src/host/manager.ts)).
- Servers connect:
  - when a window watches their Project: `watch` connects every enabled server of the Project that is not connected. The client part's MCP pane, in the sidebar's stack (`layout.stack/v2` of [`layout`](../../bundles/desktop/layout/README.md)), keeps one watch open, on the Project selected through `workspace.selection/v1` of [`workspace`](../../bundles/desktop/workspace/README.md) ([src/host/index.ts](../../bundles/features/mcp/src/host/index.ts), [src/client/index.ts](../../bundles/features/mcp/src/client/index.ts));
  - when a prompt of the Project starts: the `runtime.hooks/v1.onPromptStartedHook` handler connects them and makes the prompt wait at most ten seconds for them; a server that cannot connect never fails the prompt ([src/host/index.ts](../../bundles/features/mcp/src/host/index.ts)). `default` reads the Project's tools once, when the run starts, after that wait: a server that connects later, or a `tools/list_changed` that arrives during the run, reaches the next prompt ([bundles/runtime/default/src/host/executor.ts](../../bundles/runtime/default/src/host/executor.ts), [bundles/runtime/runtime/src/host/domain/runner.ts](../../bundles/runtime/runtime/src/host/domain/runner.ts));
  - when a sign-in finishes: `finishSignIn` reconnects its server ([src/host/index.ts](../../bundles/features/mcp/src/host/index.ts));
  - when the Project's sandbox becomes ready: the `runtime.hooks/v1.onProjectReadyHook` handler connects the Project's servers that are `waiting-for-sandbox` ([src/host/manager.ts](../../bundles/features/mcp/src/host/manager.ts)).
- A tool call that fails with no MCP answer, outside a cancelled prompt, is checked. An authorization failure moves the server to `needs-sign-in`. Any other failure makes the host part ping the server, for at most ten seconds, while the server stays `connected`; a ping that fails on authorization moves it to `needs-sign-in`, and a ping that fails otherwise connects it again, which ends in `connected` or in `error` ([src/host/manager.ts](../../bundles/features/mcp/src/host/manager.ts)).
- A server whose process or connection closes on its side goes to `error` ([src/host/manager.ts](../../bundles/features/mcp/src/host/manager.ts)).
- When a Project closes, the `runtime.hooks/v1.onProjectClosingHook` handler stops its servers, which read as `idle` again; a connection begun before the close starts none. The runtime fires that hook when the Project's state becomes `cancelling` ([src/host/index.ts](../../bundles/features/mcp/src/host/index.ts), [src/host/manager.ts](../../bundles/features/mcp/src/host/manager.ts), [bundles/runtime/runtime/src/host/domain/service.ts](../../bundles/runtime/runtime/src/host/domain/service.ts)).
- When a Project is deleted (the `projectDeleted` notice of `runtime/v2.watch` of [`runtime`](../../bundles/runtime/runtime/README.md)), the host part stops its servers, deletes their documents and their `MCP_TOKEN` credentials, and cancels their waiting sign-ins ([src/host/index.ts](../../bundles/features/mcp/src/host/index.ts)).
- `remove` deletes the server's `MCP_TOKEN` credentials and its document, stops it, unregisters its tools and cancels its waiting sign-in ([src/host/index.ts](../../bundles/features/mcp/src/host/index.ts)).
- When the bundle deactivates, every connection, process and waiting sign-in ends and every tool is unregistered ([src/host/index.ts](../../bundles/features/mcp/src/host/index.ts), [src/host/manager.ts](../../bundles/features/mcp/src/host/manager.ts)).

### Tools

- While a server is connected, each of its tools is registered with `tools/v1` under the server's Project, so only calls of that Project see it. It is registered at the order 1000. Its name is `mcp__<server slug>__<tool>`, in which every character outside `[a-zA-Z0-9_-]` becomes `_`; a name over 64 characters, or one that two tools of the server would share, keeps its first 55 characters and ends with `_` and eight hex digits of a hash of the MCP tool's name. Since a slug never holds `__`, two servers' tools never share a name ([src/host/manager.ts](../../bundles/features/mcp/src/host/manager.ts), [src/host/tools.ts](../../bundles/features/mcp/src/host/tools.ts), [src/contracts/index.ts](../../bundles/features/mcp/src/contracts/index.ts), [bundles/foundation/core/src/host/tools/service.ts](../../bundles/foundation/core/src/host/tools/service.ts)).
- The model sees the server's input schema verbatim; the tool is not strict, and the server validates the arguments. A call may take up to 300 seconds and is cancelled with its prompt. The result's blocks are joined as text, with an image kept as a Project attachment; a result the server flags as an error fails the call with `mcp_tool_failed` ([src/host/tools.ts](../../bundles/features/mcp/src/host/tools.ts), [src/host/manager.ts](../../bundles/features/mcp/src/host/manager.ts)).
- The tools are unregistered whenever the server leaves `connected`. A `tools/list_changed` notification keeps the registration of each unchanged tool and replaces the others. A tool whose schema is unusable, or whose name `tools/v1` refuses, is left out and logged; the server's view lists only what is registered ([src/host/manager.ts](../../bundles/features/mcp/src/host/manager.ts)).

### OAuth sign-in

- A background connection of an `http` server never registers a client or opens anything: it uses and refreshes the stored tokens, and a server that asks for authorization they do not give goes to `needs-sign-in` ([src/host/oauth.ts](../../bundles/features/mcp/src/host/oauth.ts), [src/host/manager.ts](../../bundles/features/mcp/src/host/manager.ts)).
- The pane's "Sign in" link starts the browser sign-in ([src/client/sign-in.ts](../../bundles/features/mcp/src/client/sign-in.ts)):
  1. The window calls `signIn`. The host part drops the server's stored tokens, binds a loopback callback on the host's `127.0.0.1` on a fresh port, and lets the MCP SDK (`@modelcontextprotocol/sdk`) discover the authorization server. When no client is stored, or the stored one does not name that redirect URI or the server's client name, it registers a new one through dynamic client registration; since the port is fresh at every sign-in, in practice every sign-in registers a new client. The registration sends `client_name` set to the server's `clientName` (`Doric` when it sets none) and `token_endpoint_auth_method: none`. It answers an authorization URL with PKCE `S256` and, as the `resource`, the server's URL, or the URL its protected-resource metadata names when that one is allowed for it, asking for the server's `scopes` when it sets them and for the ones the server names otherwise ([src/host/oauth.ts](../../bundles/features/mcp/src/host/oauth.ts)).
  2. The window opens the URL in the system browser through `doric.browser/v1`; where no browser opens, a toast offers the link ([src/client/sign-in.ts](../../bundles/features/mcp/src/client/sign-in.ts), [src/client/api.ts](../../bundles/features/mcp/src/client/api.ts)).
  3. The window calls `finishSignIn`, which waits for the browser's redirect, checks its `state`, refuses an `iss` other than the authorization server's issuer, and refuses a redirect with no `iss` when the authorization server's metadata sets `authorization_response_iss_parameter_supported`. It then exchanges the code for tokens and reconnects the server ([src/host/oauth.ts](../../bundles/features/mcp/src/host/oauth.ts), [src/host/index.ts](../../bundles/features/mcp/src/host/index.ts)).
- An authorization server without metadata, without PKCE `S256` or without dynamic client registration cannot be signed in to, and a `stdio` server has no sign-in. `signIn` also fails when the caller cancels, the bundle deactivates or the server's URL changes while it prepares, or when the loopback callback cannot start; `finishSignIn` fails when no sign-in of the server waits, when another `finishSignIn` already waits on it, and when the caller cancels or the sign-in is cancelled, as the next item lists ([src/host/oauth.ts](../../bundles/features/mcp/src/host/oauth.ts), [src/contracts/index.ts](../../bundles/features/mcp/src/contracts/index.ts)). [The README's error codes](../../bundles/features/mcp/README.md#error-codes) give the code and message of each failure.
- One sign-in per server waits at a time: a newer one of the same server replaces it, and another server's is left alone. A sign-in nobody finishes is cancelled after ten minutes; changing the server's transport kind or URL, removing the server, or deactivating the bundle cancels it ([src/host/oauth.ts](../../bundles/features/mcp/src/host/oauth.ts), [src/host/index.ts](../../bundles/features/mcp/src/host/index.ts)).
- The access token, the refresh token and a client secret are `MCP_TOKEN` credentials named `mcp:<serverId>:access`, `mcp:<serverId>:refresh` and `mcp:<serverId>:client`; the server's document keeps only their ids and the non-secret OAuth state ([src/host/credentials.ts](../../bundles/features/mcp/src/host/credentials.ts), [src/host/store.ts](../../bundles/features/mcp/src/host/store.ts)).
- Those credentials are deleted with the server, with its Project, and when an `update` changes the server's transport kind or URL. OAuth state is stored only for the URL it was earned for, so tokens earned for a former URL are never stored. Changing only the client name, the scopes or the client info keeps the tokens ([src/host/index.ts](../../bundles/features/mcp/src/host/index.ts), [src/host/credentials.ts](../../bundles/features/mcp/src/host/credentials.ts), [src/host/oauth.ts](../../bundles/features/mcp/src/host/oauth.ts)).
- A connection refreshes one token at a time, each refresh sending the latest stored refresh token ([src/host/oauth.ts](../../bundles/features/mcp/src/host/oauth.ts)).

### Limits

- The OAuth callback is a loopback on the host's `127.0.0.1`: a sign-in completes only where the browser's `127.0.0.1` is the host's ([src/host/oauth.ts](../../bundles/features/mcp/src/host/oauth.ts)). The [Claude login](../../bundles/features/claude-login/README.md)'s callback is a host loopback too, on `localhost` ([bundles/features/claude-login/src/host/login.ts](../../bundles/features/claude-login/src/host/login.ts), [packages/oauth/src/lib/claude-oauth.ts](../../packages/oauth/src/lib/claude-oauth.ts)).
