# Feature: cwd tool

- Status: `implemented`

## Problem

The Threads of a Project share one sandbox, and each Thread works from its own directory inside it. The model must be able to see and move that directory, the reader must be able to move it too, and the model must know when the directory is the root of a repository, so it can load the skills that repository work needs.

## Decisions

- Each Thread has one working directory. A new top-level Thread starts at the workspace root `/workspace`; a child starts where its parent is when it is created.
- The agent moves the directory with the `cwd` tool, and the reader moves the same Thread's with `PATCH /threads/:id`. Both reach one resolving rule in the runtime, which refuses any path that resolves outside the workspace root.
- A relative path a tool is given resolves against the Thread's working directory, the way `cd` resolves one against the current directory.
- The `cwd` result, not the system prompt, says whether the directory is a repository root; a move into a repository during a run is reported by the same result.
- The result carries the boolean `repositoryRoot` on every status, and the `note` with one exact text only at a root.
- Only a directory that itself holds a `.git` directory or file is a root; a subdirectory of a repository is not.
- The repository fact comes from the runtime through `runtime.workspace/v1.location()`, which the tool calls after every outcome and which probes now. `location()` answers which repository host the root points at (`CwdRepo`); the tool reports a boolean.
- The repository hint belongs to the runtime, which stores it on the Thread record; the `git` bundle's status read asks the runtime to refresh it.
- Each sandbox request of the hint probe is bounded at 5000 ms. A refresh whose probe does not finish never clears the stored hint; a move whose probe does not finish stores no hint; a move whose probe times out rejects instead of hanging.

## Current behavior and contracts

The flow crosses the `files` bundle ([README](../../bundles/features/files/README.md)), the `runtime` bundle ([README](../../bundles/runtime/runtime/README.md)), the `transport` bundle ([README](../../bundles/foundation/transport/README.md)), the `git` bundle ([README](../../bundles/features/git/README.md)), the `terminal` bundle ([README](../../bundles/features/terminal/README.md)) and the `default` bundle ([README](../../bundles/runtime/default/README.md)). Each README is the overview of its bundle.

### The working directory

- A Thread record stores `cwd` and the repository hint `cwdRepo` (`git`, `github` or none). A new top-level Thread stores `/workspace` and no hint; a child stores its parent's `cwd` and `cwdRepo` at creation ([bundles/runtime/runtime/src/host/store/threads.ts](../../bundles/runtime/runtime/src/host/store/threads.ts), [bundles/runtime/runtime/src/host/domain/runner.ts](../../bundles/runtime/runtime/src/host/domain/runner.ts)).
- A move resolves the path with `cd` semantics: an absolute path stands alone, a relative one joins the current directory, and the result is normalized. It is refused as `outside` when it leaves the workspace root, also through a symbolic link the sandbox resolves outside it, as `missing` when nothing is there, and as `not-directory` when it is not a directory ([bundles/runtime/runtime/src/host/domain/runner.ts](../../bundles/runtime/runtime/src/host/domain/runner.ts), [bundles/runtime/runtime/src/host/domain/cwd.ts](../../bundles/runtime/runtime/src/host/domain/cwd.ts)). A refused move changes nothing.
- An accepted move probes the new directory's repository hint and writes `cwd` and the hint to the Thread record, both inside the Project's lock, and publishes a Thread update. Outside the lock it then fires `runtime.hooks/v1.onThreadCwdChangedHook` with the values before and after, and awaits it before the move answers, so an instruction a handler gives the running prompt is read after the current tool batch ([bundles/runtime/runtime/src/host/domain/runner.ts](../../bundles/runtime/runtime/src/host/domain/runner.ts), [bundles/runtime/runtime/src/contracts/hooks.ts](../../bundles/runtime/runtime/src/contracts/hooks.ts)).
- Every time a Project acquires its sandbox, one command checks the directory of each live, non-terminal Thread not at the workspace root. A directory that is missing, is not a directory, or resolves outside the root through a symbolic link is reset to the root with no hint, before any Thread runs, and `onThreadCwdChangedHook` fires without being awaited. When the check cannot run, every stored directory is kept ([bundles/runtime/runtime/src/host/domain/service.ts](../../bundles/runtime/runtime/src/host/domain/service.ts), [bundles/runtime/runtime/src/host/domain/cwd.ts](../../bundles/runtime/runtime/src/host/domain/cwd.ts), [bundles/runtime/runtime/src/host/domain/runner.ts](../../bundles/runtime/runtime/src/host/domain/runner.ts)).
- Tools read the Thread's directory through `runtime.workspace/v1.cwd()` and work from it: the other tools of the `files` bundle resolve their relative paths against it ([bundles/features/files/src/host/sandbox.ts](../../bundles/features/files/src/host/sandbox.ts)), the `terminal` tool runs its commands there ([bundles/features/terminal/src/host/tool.ts](../../bundles/features/terminal/src/host/tool.ts)), the `git` tool runs there ([bundles/features/git/src/host/sandbox.ts](../../bundles/features/git/src/host/sandbox.ts)), and the `default` executor reads workspace skills from it ([bundles/runtime/default/src/host/skills/sources.ts](../../bundles/runtime/default/src/host/skills/sources.ts)).

### The `cwd` tool

- Tool `cwd` of the `files` bundle ([bundles/features/files/src/host/tools/cwd.ts](../../bundles/features/files/src/host/tools/cwd.ts)). Input: `{ path?: string }`. Without a path, or with one that is blank once trimmed, it reports; with one it trims the path and moves through `runtime.workspace/v1.setCwd`.
- Output, keys in this order: `cwd` (string), `status` (`reported`, `set` or `refused`), `reason` (refusals only: `outside`, `missing` or `not-directory`), `repositoryRoot` (boolean, every status), `note` (only when `repositoryRoot` is true). The note's text is exactly `Remember to load the skills that match your task when working in a repository.`
- A refusal is a value of the result, not a failure of the tool call, so the model corrects its own path.
- After every outcome — report, move or refusal — the tool calls `runtime.workspace/v1.location()` once, so `cwd` and `repositoryRoot` describe the directory the Thread is in after the call; on a refusal that is the unchanged directory. `repositoryRoot` is true exactly when `location()` answers a `repo`. A rejection of `setCwd` or `location()` fails the tool call.

### `runtime.workspace/v1` and the repository hint

- `runtime.workspace/v1` 1.2.0, provided by `runtime` 3.0.0 and required by `files` at `^1.2.0` ([bundles/runtime/runtime/src/contracts/workspace.ts](../../bundles/runtime/runtime/src/contracts/workspace.ts), [bundles/runtime/runtime/manifest.json](../../bundles/runtime/runtime/manifest.json), [bundles/features/files/manifest.json](../../bundles/features/files/manifest.json)), serves the calling prompt's own Thread: `cwd()`, `setCwd(path)` answering a `CwdChange` (`set` with the new `cwd`, or `outside`, `missing` or `not-directory`), `location()` and the local-only `withThread`.
- `location(): Promise<CwdLocation>`, with `CwdLocation = { cwd: string; repo?: 'git' | 'github' }`, probes the hint now when the Project holds a sandbox, and answers the stored hint when it holds none. When the probed hint differs from the stored one it writes it to the Thread record, publishes a Thread update and fires `onThreadCwdChangedHook`, so a caller that polls causes those writes. `setCwd` and `location()` reject with `Thread control is no longer active.` when the Project or the Thread is closing, or the calling prompt is no longer the Thread's active one ([bundles/runtime/runtime/src/host/domain/runner.ts](../../bundles/runtime/runtime/src/host/domain/runner.ts)).
- The probe is `cwdRepoHint` ([bundles/runtime/runtime/src/host/domain/repository-hint.ts](../../bundles/runtime/runtime/src/host/domain/repository-hint.ts)). It runs one sandbox command with `timeoutMs: 5000`. A directory whose own root holds a `.git` directory or file is a repository: `github` when the host of its `origin` is `github.com`, in any letter case and in any URL scheme or the scp-like `git@github.com:owner/repo.git` form, and `git` otherwise. An exit other than 0, `null` included (the command was killed), rejects with `HintProbeIncompleteError`; an exec that rejects passes its error through.
- A timeout makes the exec reject: after 5000 ms on Firecracker, with `Sandbox command timed out` ([packages/firecracker-sandbox/src/lib/ssh.ts](../../packages/firecracker-sandbox/src/lib/ssh.ts)), and on Docker after 5000 ms for each of the exec's three requests, so at most 15 000 ms, with `DockerRequestTimeoutError` ([packages/docker-sandbox/src/lib/docker.ts](../../packages/docker-sandbox/src/lib/docker.ts)).
- The hint is refreshed by `location()`, after each prompt of the Thread settles ([bundles/runtime/runtime/src/host/domain/runner.ts](../../bundles/runtime/runtime/src/host/domain/runner.ts)), and by `withThread({ refreshHint: true })` when the task runs, which `git.commands/v1.status` uses on every Git status read ([bundles/runtime/runtime/src/host/domain/service.ts](../../bundles/runtime/runtime/src/host/domain/service.ts), [bundles/features/git/src/host/commands.ts](../../bundles/features/git/src/host/commands.ts)). A refresh probes outside the Project's lock and writes only when the Thread is still in the directory it probed; a probe that rejects, for any reason, keeps the stored hint, so the `cwdRepo` the desktop reads is never cleared by an incomplete probe.
- On a move, a probe that rejects with `HintProbeIncompleteError` stores no hint and the move succeeds; an exec that rejects, a timeout included, makes the move reject, with nothing written ([bundles/runtime/runtime/src/host/domain/runner.ts](../../bundles/runtime/runtime/src/host/domain/runner.ts)). This holds for the `cwd` tool and `PATCH /threads/:id` alike.

### `PATCH /threads/:id`

- `PATCH /threads/:id` ([bundles/foundation/transport/src/host/routes/threads.ts](../../bundles/foundation/transport/src/host/routes/threads.ts)) accepts `cwd` beside `name`, `providerId`, `model` and `effort`. A `cwd` that is blank, longer than 4096 characters or holds a NUL character answers `422 invalid_thread`; the route does not trim it.
- A `name` in the same request is applied first and is kept when the move is then refused or rejects. The move goes through `runtime.threads/v1.setThreadCwd` ([bundles/runtime/runtime/src/host/services/threads.ts](../../bundles/runtime/runtime/src/host/services/threads.ts)), the same resolving rule the `cwd` tool reaches.
- A refused move answers `400 invalid_cwd` with `The working directory must stay inside the workspace.`, `No such directory.` or `The working directory must be a directory.`; a missing Thread answers `404 thread_not_found`; a Thread that cannot move now answers `409 thread_inactive` ([bundles/foundation/transport/src/host/routes/input.ts](../../bundles/foundation/transport/src/host/routes/input.ts)). A move that rejects, a probe timeout included, answers `500 internal_error` ([bundles/foundation/transport/src/host/errors.ts](../../bundles/foundation/transport/src/host/errors.ts)).
- The execution fields are described in [per-thread model](per-thread-model.md).
