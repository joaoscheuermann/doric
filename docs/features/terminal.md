# Feature: Terminal

- Status: `implemented`

## Problem

The agent needs a shell in its Project's sandbox to run builds, tests and scripts, and it needs the result in a form it can read. A long command must not hold up the agent, and its result must still reach the Thread that started it. The reader needs to see the commands the agent runs while they run, stop them, and open a shell of their own in the same sandbox.

## Decisions

- `terminal/v1.watchProject` is a stream. It sends one snapshot of the Project's sessions on every subscribe, then `updated` and `removed` items, and `output` items only after the snapshot. Output is never buffered for a subscriber: a reader that reconnects reads the terminal's bounded snapshot instead.
- `create` and `snapshot` take positional arguments (`create(threadId, size)`, `snapshot(terminalId, after)`). `stop` answers whether a session existed.
- `terminal/v1` has two references to the one id `terminal/v1`: `TerminalV1`, typed with `run` only, and `TerminalServiceV1`, the full 1.2.0 service. Both are exported from the bundle's contracts module.
- The registry redacts the terminal stream chunk by chunk with the last list `secrets/v1.watchRedactions` delivered, and reads `secrets/v1.redactions()` again right before each terminal starts.
- `run` throws `Thread is inactive.` when the call's scope has no `threadId` or no `promptId`, when `runtime.workspace/v1.withThread` does not answer `ready`, or when the Thread or its Project is closing. A background command's result goes to `runtime.threads/v1.enqueueTerminalResult`; when the result or its delivery rejects, the provider calls `runtime.threads/v1.failTerminalResult`.
- The runtime delivers a background result as a prompt of the input source `terminal`, with its text redacted. A failed delivery logs `Terminal result delivery failed` with the `threadId` and closes the Thread with `terminal_result_failed`. For a Thread the host does not hold live, `enqueueTerminalResult` does nothing and `failTerminalResult` only logs.
- The `onThreadsClosingHook` handler of the `terminal` bundle logs `Terminal cleanup failed` with `{ projectId }` and never rejects. The runtime runs the hook and awaits it where Threads close (`close`), where a host stops (`suspend`) and where a Project drains (`drainProject`); a failing handler never fails the close, and the hook does not fire for an empty list of Threads.
- The `terminal` tool runs every command through the bundle's own `terminal/v1`, in the calling prompt's scope. It has no other way to run a command.
- The desktop reaches every `terminal/v1` method except `run`.
- The host part reaches `runtime.workspace/v1`, `runtime.threads/v1` and `runtime.hooks/v1` through local structural copies, each narrowed to what the bundle calls.
- The client part reaches `files.refresh/v1` through a local structural copy, narrowed to `request`. It builds `ChatViewsV1` from the id `chat.views/v1` and imports the chat's contracts module for types only, since the [`chat`](../../bundles/desktop/chat/README.md) bundle is optional.
- The "New terminal" button has the order 10 in its region.
- The sidebar's terminal rows follow each Thread's Project the first time they count that Thread's rows, and sit one level deeper than their Thread, counted through `parentThreadId`.
- A row's click navigates to `/projects/<projectId>/threads/<threadId>`, when the window's records hold the Thread, before it opens the tab `terminal:<id>`.
- A change of a Project's terminal activity (id, state, command, working directory) calls `files.refresh/v1.request(projectId)`.

## Current behavior and contracts

### The bundle

- The `terminal` bundle, version 1.2.1, provides `terminal/v1@1.2.0` ([manifest.json](../../bundles/features/terminal/manifest.json)). It has a host part, which holds the session registry, the `terminal/v1` provider and the `terminal` tool, and a client part, which draws the terminals in the window ([src/host/index.ts](../../bundles/features/terminal/src/host/index.ts), [src/client/index.ts](../../bundles/features/terminal/src/client/index.ts)). The bundle's interface, data and limits are in its [README](../../bundles/features/terminal/README.md).
- `chat.views/v1` and `files.refresh/v1` are optional. Without `chat.views/v1` the bundle draws nothing in the conversation; without `files.refresh/v1` a terminal change asks for no file refresh ([manifest.json](../../bundles/features/terminal/manifest.json), [src/client/index.ts](../../bundles/features/terminal/src/client/index.ts)).

### Sessions

- The host holds every terminal session in process memory, in one registry. A session belongs to one Thread and runs in that Thread's Project sandbox. Sessions are not stored, so none survives a host restart ([src/host/registry.ts](../../bundles/features/terminal/src/host/registry.ts)).
- Only the `terminal` tool and manual shells create sessions. The filesystem and Git probes of the [`files`](../../bundles/features/files/README.md) bundle run through the sandbox's `exec` and never appear as terminals, and the [`git`](../../bundles/features/git/README.md) bundle only lists the sessions ([bundles/features/files/src/host/reads.ts](../../bundles/features/files/src/host/reads.ts), [bundles/features/files/src/host/tools/find.ts](../../bundles/features/files/src/host/tools/find.ts), [bundles/features/files/src/host/tools/grep.ts](../../bundles/features/files/src/host/tools/grep.ts), [bundles/features/files/src/host/tools/visible-files.ts](../../bundles/features/files/src/host/tools/visible-files.ts), [bundles/features/git/src/host/index.ts](../../bundles/features/git/src/host/index.ts)).
- A session belongs to one Thread and has an id, an origin (`agent` for the tool's commands, `user` for a manual shell), its command, its working directory, its start time, its timeout, a state and an optional name; its full shape, `TerminalSession`, is in the [README's types](../../bundles/features/terminal/README.md#types) ([src/contracts/index.ts](../../bundles/features/terminal/src/contracts/index.ts)).
- An agent command runs as a shell command (`sh -lc`), and its session is removed as soon as the command ends, so the registry keeps no finished agent terminal. A manual shell is an interactive bash in a PTY whose current command the registry reads from markers the shell prints, never from keystrokes; when its process exits it stays, in the state `exited`, until it is stopped. Each session keeps a bounded tail of its output, and a snapshot after an offset older than that tail is marked `truncated`. How sessions start, report their output and end is in the [README's sessions](../../bundles/features/terminal/README.md#sessions) ([src/host/registry.ts](../../bundles/features/terminal/src/host/registry.ts)).
- The registry replaces each secret on the `secrets/v1` redaction list with `[REDACTED]` in the session's command, in its live output and in its retained output, so every snapshot and stream item is redacted. It holds back the end of a chunk that could begin a secret until the next chunk arrives. It redacts only that list: a Git token the runtime applies to a sandbox is redacted in the terminal only while the secret store holds it. The `stdout` and `stderr` of a foreground `run` result are the process's own output, not redacted by the registry ([src/host/registry.ts](../../bundles/features/terminal/src/host/registry.ts), [src/host/redactions.ts](../../bundles/features/terminal/src/host/redactions.ts)).
- When Threads close, the bundle's `runtime.hooks/v1.onThreadsClosingHook` handler stops the sessions of those Threads only. The runtime fires the hook when it terminates Threads or their Project, when the host stops, and when a Project drains from the host ([src/host/index.ts](../../bundles/features/terminal/src/host/index.ts), [bundles/runtime/runtime/src/host/domain/runner.ts](../../bundles/runtime/runtime/src/host/domain/runner.ts), [bundles/runtime/runtime/src/host/domain/service.ts](../../bundles/runtime/runtime/src/host/domain/service.ts)).
- The host part writes no terminal command or output to the log. It logs only `Terminal cleanup failed` with the Project's id and `Terminal result delivery failed` with the Thread's id ([src/host/index.ts](../../bundles/features/terminal/src/host/index.ts), [src/host/provider.ts](../../bundles/features/terminal/src/host/provider.ts)).

### The `terminal/v1` contract

`terminal/v1` 1.2.0 serves `run`, the agent's command on the calling prompt's Thread; the desktop cannot call it. Its other methods serve the sessions of every Project, and the desktop can reach them: `list`, `create`, `snapshot`, `input`, `resize`, `stop`, `rename`, and the stream `watchProject`, which sends a snapshot on every subscribe and output only after it. Its types and methods are in the [README's contract](../../bundles/features/terminal/README.md#the-terminalv1-contract) ([src/contracts/index.ts](../../bundles/features/terminal/src/contracts/index.ts), [src/host/provider.ts](../../bundles/features/terminal/src/host/provider.ts)).

- A foreground `run` takes its prompt's abort signal, so the command is cancelled with the prompt. A background `run` does not, so its command outlives the prompt and stays owned by its Thread ([src/host/provider.ts](../../bundles/features/terminal/src/host/provider.ts)).
- One failing stream listener never reaches the registry or another listener ([src/host/watch.ts](../../bundles/features/terminal/src/host/watch.ts)).
- The window reaches `terminal/v1` only through the Electron preload's `window.doric.desktop`. The main process's dispatcher forwards each call to the host over the main process's own Socket.IO connection on `/doric/bridge`, and the window's packaged content security policy is `connect-src 'none'`, and no window policy allows a connection to the host, so the window opens no HTTP or Socket.IO connection to the host of its own ([app/desktop/doric/src/app/api/preload.ts](../../app/desktop/doric/src/app/api/preload.ts), [app/desktop/doric/src/platform/bridge/dispatcher.ts](../../app/desktop/doric/src/platform/bridge/dispatcher.ts), [app/desktop/doric/src/platform/bridge/host-bridge.ts](../../app/desktop/doric/src/platform/bridge/host-bridge.ts), [app/desktop/doric/src/platform/protocol/csp.ts](../../app/desktop/doric/src/platform/protocol/csp.ts)).
- Separately, the host's REST routes and its `/projects` Socket.IO namespace, which the [`transport`](../../bundles/foundation/transport/README.md) bundle serves and which are not the window's path, read and drive the same sessions through `terminal/v1` ([bundles/foundation/transport/src/host/routes/terminals.ts](../../bundles/foundation/transport/src/host/routes/terminals.ts), [bundles/foundation/transport/src/host/sockets/terminal-feed.ts](../../bundles/foundation/transport/src/host/sockets/terminal-feed.ts)).

### The `terminal` tool

- The bundle registers the tool `terminal` as always available, at the model-visible order 500 ([src/host/index.ts](../../bundles/features/terminal/src/host/index.ts)).
- The tool takes a command, an optional working directory resolved against the Thread's, a timeout (2 minutes by default, 10 minutes at most, 0 for none), `background` and `pty`. In the foreground it waits and answers compact output: the exit status, the head and tail of each long stream, and the lines it recognizes as errors, warnings or failed tests. Its input and its answer, the record `terminal.compact.v1`, are in the [README's tool](../../bundles/features/terminal/README.md#the-terminal-tool) ([src/host/tool.ts](../../bundles/features/terminal/src/host/tool.ts)).
- With `background: true` the tool answers `{ terminal_id, background: true }` at once and the agent keeps working ([src/host/tool.ts](../../bundles/features/terminal/src/host/tool.ts)).
- With `pty: true` the command runs in a PTY, with stdout and stderr combined ([src/host/tool.ts](../../bundles/features/terminal/src/host/tool.ts)).
- A foreground command answers only its tool result; nothing is queued for it. Interrupting the prompt cancels its foreground command ([src/host/provider.ts](../../bundles/features/terminal/src/host/provider.ts)).

### Background results

- When a background command ends, the provider sends its result to the Thread through `runtime.threads/v1.enqueueTerminalResult`, once. The text is a Markdown prompt headed `# Background terminal result`, naming the terminal, the originating prompt, the command, the exit code, the reason and the duration, followed by the last 12,000 characters of stdout and of stderr; its exact format is in the [README's background results](../../bundles/features/terminal/README.md#background-results) ([src/host/provider.ts](../../bundles/features/terminal/src/host/provider.ts)).
- The runtime redacts the text and delivers it as a prompt of the source `terminal`, as its [README](../../bundles/runtime/runtime/README.md#threads) describes. A Thread that runs a prompt takes it in as a steer at its next safe point; an idle Thread takes it from its first-in, first-out input queue; a Thread that is stopping or paused queues it. Nothing is delivered to a closing or finished Thread, and none is reopened ([bundles/runtime/runtime/src/host/domain/runner.ts](../../bundles/runtime/runtime/src/host/domain/runner.ts), [bundles/runtime/runtime/src/host/domain/service.ts](../../bundles/runtime/runtime/src/host/domain/service.ts)).
- The conversation keeps the tool results and the background results; it keeps no terminal session ([src/host/registry.ts](../../bundles/features/terminal/src/host/registry.ts), [bundles/runtime/runtime/src/host/domain/runner.ts](../../bundles/runtime/runtime/src/host/domain/runner.ts)).
- What the conversation stores is redacted by the runtime with its own list: the secrets on the `secrets/v1` list and the Git token it applied to the Project's sandbox. That covers the background result's text and every recorded event and history part, tool results included ([bundles/runtime/runtime/src/host/domain/runner.ts](../../bundles/runtime/runtime/src/host/domain/runner.ts), [bundles/runtime/runtime/src/host/domain/session.ts](../../bundles/runtime/runtime/src/host/domain/session.ts), [bundles/runtime/runtime/src/host/domain/redactor.ts](../../bundles/runtime/runtime/src/host/domain/redactor.ts), [bundles/runtime/runtime/src/host/domain/service.ts](../../bundles/runtime/runtime/src/host/domain/service.ts)).
- A manual shell never sends anything to its Thread: only `run` with `background` delivers a result ([src/host/provider.ts](../../bundles/features/terminal/src/host/provider.ts)).

### In the window

- The window keeps one terminal store, which follows each Project's terminals through `watchProject` ([src/client/store.ts](../../bundles/features/terminal/src/client/store.ts)).
- The "New terminal" button sits in the header region `shell.header.actions`. It is disabled until a Thread is selected; a click opens a manual shell in that Thread's working directory and opens it as a tab of the workspace, beside the conversation, where files and diffs open ([src/client/index.ts](../../bundles/features/terminal/src/client/index.ts), [src/client/elements.tsx](../../bundles/features/terminal/src/client/elements.tsx), [src/client/store.ts](../../bundles/features/terminal/src/client/store.ts)).
- The sidebar lists a Thread's terminals under it, through `workspace.sidebar/v1`. An agent row reads `<command> · mm:ss (<timeout>)`, its elapsed time updated each second and its timeout written as `no limit`, `<1 sec` or minutes and seconds; a manual row reads the shell's current command, or `bash` while it is idle. A name, when set, replaces the command ([src/client/index.ts](../../bundles/features/terminal/src/client/index.ts), [src/client/domain/terminals.ts](../../bundles/features/terminal/src/client/domain/terminals.ts), [src/client/rows/terminal-rows.tsx](../../bundles/features/terminal/src/client/rows/terminal-rows.tsx)).
- An agent terminal that has not exited keeps its Thread marked busy in the sidebar; a manual one never does ([src/client/index.ts](../../bundles/features/terminal/src/client/index.ts), [src/client/domain/terminals.ts](../../bundles/features/terminal/src/client/domain/terminals.ts)).
- A row's click selects its Thread, when the window's records hold it, and opens the terminal's tab, or shows it when open. The row of the terminal whose tab is selected is marked (`aria-current="true"`) ([src/client/index.ts](../../bundles/features/terminal/src/client/index.ts), [src/client/elements.tsx](../../bundles/features/terminal/src/client/elements.tsx)).
- Each row has a stop button, labelled "Stop terminal" for an agent terminal and "Discard terminal" for a manual one; both stop the session. Its context menu holds Rename, Copy command and Kill terminal. Rename turns the row into a name field: Enter sends the trimmed text (empty clears the name), Escape or leaving the field cancels; the field closes whatever the answer, and a failed call keeps the old name and shows a toast ([src/client/rows/terminal-rows.tsx](../../bundles/features/terminal/src/client/rows/terminal-rows.tsx), [src/client/store.ts](../../bundles/features/terminal/src/client/store.ts)).
- A terminal's tab is titled by its name, else its command, else "Terminal", and follows every rename and command change. Its icon is the element `terminal-tab-icon`, and its context menu holds Kill terminal, which stops the session. Closing the tab only closes the tab: the process keeps running and its row reopens it ([src/client/tab.ts](../../bundles/features/terminal/src/client/tab.ts), [src/client/store.ts](../../bundles/features/terminal/src/client/store.ts)).
- When a session leaves its Project's list, its tab closes. A finished agent command therefore leaves both the sidebar and the open tabs ([src/client/store.ts](../../bundles/features/terminal/src/client/store.ts), [src/host/registry.ts](../../bundles/features/terminal/src/host/registry.ts)).
- The tab draws the element `terminal-view`, an xterm emulator with 10,000 lines of scrollback that follows the color scheme. An agent terminal's view has a header with its command; a manual shell's has none. A manual shell whose process exited stays open in its tab and takes no input; its tab and row carry no mark of the exit. The workspace, drawn by the [`layout`](../../bundles/desktop/layout/README.md) bundle, keeps an open tab's element mounted while another tab is shown, so switching tabs keeps the emulator ([src/client/view/terminal-view.tsx](../../bundles/features/terminal/src/client/view/terminal-view.tsx), [src/client/tab.ts](../../bundles/features/terminal/src/client/tab.ts), [bundles/desktop/layout/src/client/components/organisms/workspace-tabs.tsx](../../bundles/desktop/layout/src/client/components/organisms/workspace-tabs.tsx)).
- The view sends the PTY a resize only when its columns or rows change ([src/client/view/terminal-view.tsx](../../bundles/features/terminal/src/client/view/terminal-view.tsx)).
- Output reaches a view through the snapshot and the stream. A watch first reads the terminal's snapshot to learn its Project; when that read fails it reports `The terminal is no longer available.` On every subscribe the view reads the snapshot again; output that arrives meanwhile is buffered, and when the buffer passes 2,097,152 characters the snapshot is read again instead. Only the unseen part of the output is drawn, so a reconnect neither repeats nor loses output. A view whose snapshot is truncated writes `[Earlier output is no longer available]` first. All the watchers of one terminal share one stream, which closes when the last one stops ([src/client/output-watch.ts](../../bundles/features/terminal/src/client/output-watch.ts), [src/client/view/terminal-view.tsx](../../bundles/features/terminal/src/client/view/terminal-view.tsx)).
- A dropped connection or a lost host generation reports nothing and subscribes again once connected, or after one second; any other end of the stream reports `The terminal connection failed.` ([src/client/output-watch.ts](../../bundles/features/terminal/src/client/output-watch.ts)).

### In the conversation

- While `chat.views/v1` is served, the bundle registers the element `terminal-tool-call` for the `terminal` tool and the element `terminal-result` for the input source `terminal`, each in a registration of its own ([src/client/index.ts](../../bundles/features/terminal/src/client/index.ts)).
- `terminal-tool-call` draws each `terminal` call. While its terminal runs it shows the live output, the last 32,000 characters drawn at most every 50 ms, and a Stop action, which stops the terminal and disappears at once ([src/client/chat/terminal-call.tsx](../../bundles/features/terminal/src/client/chat/terminal-call.tsx), [src/client/chat/live-output.ts](../../bundles/features/terminal/src/client/chat/live-output.ts), [src/client/domain/live-terminal.ts](../../bundles/features/terminal/src/client/domain/live-terminal.ts)).
- `terminal-result` draws a background result as a block named "Background terminal", or "Background terminal failed" when the command did not exit with code 0 and the reason `exited`; a failed result's block is open, any other is folded. A prompt of the source `terminal` without the host's frame is a block labelled "Terminal" holding its text as read-only Markdown ([src/client/chat/terminal-result.tsx](../../bundles/features/terminal/src/client/chat/terminal-result.tsx), [src/client/domain/terminal-result.ts](../../bundles/features/terminal/src/client/domain/terminal-result.ts)).
