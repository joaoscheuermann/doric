## Problem

The desktop UI differs from the Figma file the user approved in its palette, its window structure and a set of missing features ([concept, Problem](../features/ui-redesign.md#problem)). This spec settles, phase by phase, the files to change, the contracts and their versions, the persisted data, the host operations, the docs each phase rewrites and the tests that prove each phase.

## Goals and non-goals

Goals:

- The concept's G1–G4 ([Goals](../features/ui-redesign.md#goals-and-success-measures)): 1:1 with the design as [1:1 verification](#11-verification) defines it; no behavior lost; the new features end to end; phased delivery.
- Every design decision of the change is made here, so the plan, tests and implementation of each phase need no further product decision.
- Each phase, and each feature of phase 4, lands with the code building and every test passing ([Phases](#phases)).

Non-goals:

- The concept's [Non-goals](../features/ui-redesign.md#non-goals): the Artifacts page, Sidebar/ProjectSwitcher and the global-footer variants, an app icon, the preview frames' generic theme, host configuration, a real account, a Settings menu item, new contrast requirements beyond [S4](#design-decisions), model icons.
- Archive (UR9); Reveal in Finder (P17); the Project "Copy path" (UR13); a Discord link (UR14); any network request from the splash (UR18); setting the release number (UR16); a recoverable Discard (UR21).
- InsetHeader (`82:41663`) and a React wordmark or glyph component: no surface of this change draws them. The cloud-fill and cloud-off-fill glyphs (`179:32`, `179:45`) ship inside the `resources` bundle, not as shared components (UR24, [2.7](#27-account-status-ur7-ur24)).
- The `xs` NewTerminalButton (`166:157`): its one call site, the `layout.header` item (`bundles/features/terminal/src/client/index.ts:43-49`), already uses `icon-sm`, Figma's `Size=sm` (`40:28978`, 28×28).

## Design

### Design decisions

Each phase section applies them.

- **S1 — Token values.** The token module takes the color values of [the token table](#11-tokens) exactly; no value is rounded or converted. Values Figma states with alpha are written as 8-digit hex.
- **S2 — Shadows.** Both themes take the shadow values the dark theme has today (black, `hsl(0 0% 0% / α)`, `packages/desktop/src/tokens/tokens.ts:196-209`); the light theme's grey shadows (`hsl(240 4% 60% / α)`, `:116-129`) go. `--paper-shadow-control` keeps today's value in each theme, since Figma states no variable for it (UR10, Q1).
- **S3 — Fixed Dark in phases 1–3.** Main sets `nativeTheme.themeSource` from one function, `resolveThemeSource`, in a new module `app/desktop/doric/src/platform/appearance.ts`. In phases 1–3 it returns `'dark'`, except in an unpackaged build where `DORIC_THEME` is `light`, `dark` or `system`, which it returns instead. A packaged build ignores `DORIC_THEME`. Phase 4 adds the preference file to the same function ([4.1](#41-appearance)).
- **S4 — Filled button hover (UR12, UR20).** The base colors stay Figma's. Today the default button hovers to `color-mix(in oklch, var(--primary), var(--foreground) 12%)` (`packages/desktop/src/components/button.tsx:11`), which measures 1.021:1 against rest in light and 1.003:1 in dark: the hover cannot be seen. The hover becomes `color-mix(in oklch, var(--primary), var(--foreground) 60%)` in light and `color-mix(in oklch, var(--primary), var(--primary-foreground) 8%)` in dark. Target: hovered against rest at least 1.10:1, hovered text at least 4.5:1. Measured with the WCAG ratio on the oklch mix: light 1.105:1 against rest and 11.39:1 for text; dark 1.193:1 and 11.53:1 (rest text 10.30:1 light, 13.76:1 dark). The contrast test computes the hover as that oklch mix and asserts both thresholds ([T-1.3](#phase-1-tests)); its old assertion "hovering does not cost contrast", which blended in linear sRGB with the weights reversed (`packages/desktop/tests/palette-contrast.test.ts:157-178`), is removed.
- **S5 — Withdrawn** (brand components; see Non-goals).
- **S6 — The reader's identity** moves to `packages/desktop/src/identity/` exported as `desktop/ui/identity`: `reader-avatar.tsx`, `identity-mark.ts` and `READER_NAME` (P11). The chat bundle imports them from there; `bundles/desktop/chat/src/contracts/index.ts:181` re-exports `READER_NAME` from `desktop/ui/identity` so its public contract does not change.
- **S7 — One app version source.** `WindowDescription` (`packages/desktop/src/client/protocol.ts:54-70`) gains the required field `app: { readonly version: string }`, and `windowDescriptionSchema` (`:72-83`, `.strict()`) gains `app: z.object({ version: z.string() }).strict()`. The dispatcher imports no Electron, so `DispatcherDeps` (`app/desktop/doric/src/platform/bridge/dispatcher.ts:70-105`) gains `readonly appVersion: string`, which `DesktopPlatform` passes as `app.getVersion()` where it builds the dispatcher (`app/desktop/doric/src/platform/app.ts:342-376`); the dispatcher writes `app: { version: this.#deps.appVersion }` into the window's description (`dispatcher.ts:387-398`) and the splash's (`:251-261`). The field is required because main always has the value; every fixture that builds a description adds `app: { version: '0.0.1' }`: `bundles/desktop/chat/tests/client/support/window.ts:520-527`, `bundles/foundation/core/tests/client/support/window.ts:338-345`, `bundles/desktop/settings/tests/client/support/window.ts`, `bundles/features/threads/tests/client/support/window.ts`, `packages/desktop/tests/client/support/fixtures.ts` and `packages/desktop/tests/client/bootstrap.test.ts`; `app/desktop/doric/tests/dispatcher.test.ts` passes `appVersion: '0.0.1'` to its `Dispatcher` (`:330-369`) and expects `app` in the description it compares (`:394`). (`app/desktop/doric/tests/preload-desktop.test.ts` only sends `describeWindow`, `:62`, `:81`, and needs no change.) A new client platform contract `doric.about/v1@1.0.0` answers it: `packages/bundle/src/contracts/platform.ts` adds `export interface DoricAbout { get(): Promise<{ readonly version: string }> }` and `DoricAboutV1 = ref<DoricAbout>('doric.about/v1')` beside `DoricTokensV1` (`:900`), and `platformContracts['doric.about/v1'] = { environments: ['client'], methods: { get: { input: noInput, output: z.object({ version: z.string() }).strict() } } }` beside `'doric.tokens/v1'` (`:1099-1104`); `packages/bundle/tests/values.test.ts`, which compares every platform contract's methods with an expected table (`:120-252`), adds `'doric.about/v1': { get: 'crosses' }` after `'doric.browser/v1'` (`:227`). `packages/desktop/src/client/platform.ts` registers it as it registers `doric.tokens/v1` (`:97-108`), answering `{ version: description.app.version }`. The layout's story host answers it with `{ version: '0.0.1' }` (`bundles/desktop/layout/stories/support/fake-host.ts`), since that host throws for a contract it does not provide (`:448-452`). The license text "MIT License" is fixed in the UI (UR11). The build writes `"version": "0.0.1"` into `dist/app/desktop/doric/package.json`, which `app.getVersion()` reads (UR16).
- **S8 — `layout.account.status`** is the new region beside the avatar (P19). Items are `{ id, tag, order }`. The account status is a 20×24 box (`267:21908`: the avatar 20×20, centered in the 24 px trigger height); the layout draws the region's items in a 14×14 slot at left 10 px, top 12 px of that box, over the avatar's bottom-right corner, as siblings of the avatar button (the cutout `266:21653`).
- **S9 — `layout.panel.footer`** is the new Files column footer region (P16), items `{ id, tag, order }`, drawn left to right in one row of the Files column's footer band ([2.6](#26-files-column)).
- **S10 — `layout.global-footer` is removed** in phase 2; `WorkspaceGlobalFooter` is deleted (P15).
- **S11 — Back/Forward state (P6).** Each history entry the core writes carries the state `{ doric: { index, max } }`, and nothing else; the core also keeps the current `index` and `max` in memory. Nothing is written to `sessionStorage`, `localStorage` or a file: the entries' state lives in the window's own session history, which a reload keeps and an app restart does not (P6).
  - **Start.** When the navigation module first listens, it reads the current entry: with a `doric` state it takes `index` and `max` from it; without one (the window's first entry, which no code has written) it takes `index = 0`, `max = 0` and writes that state with `replaceState`, keeping the URL.
  - **Push.** The new entry gets `index + 1` and `max = index + 1`.
  - **Replace.** The entry keeps its `index` and `max`.
  - **`popstate`.** The core reads the landed entry's `index`, sets `max = Math.max(max, entry.max, index)` and writes the result into that entry with `replaceState`, so the current entry always holds the current list length.
  - **Only the core writes history.** `navigation.ts:166-168` are the only `pushState`/`replaceState` calls in product code, and the app has no fragment navigation (outside tests there is no `href="#…"` link, no write to `location.hash` and no `hashchange` listener; `navigation.ts:158` only reads `location.hash` to compare paths), so every entry a window reaches carries `doric` state. A `popstate` to an entry without it (only tests that push `null` state make one) counts as `index = 0` and leaves `max` unchanged.
  - `canGoBack = index > 0`; `canGoForward = index < max`.
- **S12 — Stale history entries.** Back or Forward to an entry whose Thread was deleted lands on it and shows what a direct route to that Thread shows today: the route restore finds no Thread and selects its Project instead (`selectMissingThreadProject`, `bundles/desktop/layout/src/client/hooks/use-workspace.ts:257`, through `bundles/desktop/layout/src/client/stores/route-selection.ts:247-253`). There is no separate not-found view, and entries are not skipped.
- **S13 — ⌘F binding.** The Project sidebar mounts a `keydown` listener on `document` that acts only when `(event.metaKey || event.ctrlKey) && !event.altKey && !event.shiftKey && event.key.toLowerCase() === 'f'`, `event.defaultPrevented` is false and the target is not inside `.monaco-editor` or `.xterm` (`target instanceof Element && target.closest('.monaco-editor, .xterm') !== null` skips it). It then calls `preventDefault`, focuses the search field and selects its text.
  - Not `menus/v1.addKeybinding` (`packages/bundle/src/contracts/basic/menus.ts:19-23`): the window's keybinding listener calls `preventDefault` on every match in the capture phase whatever the target (`packages/desktop/src/client/keybindings.ts:129-141`), so it would take ⌘F from Monaco's find widget and the terminal; and `when` matches a context only by equality (`app/desktop/doric/src/platform/menus/native-menus.ts:55`).
  - The Dashboard's listener (`bundles/desktop/layout/src/client/components/organisms/dashboard.tsx:198-212`) has no such filter: it acts on any ⌘F or Ctrl+F whatever the target, and on ⌘N or Ctrl+N when it is not showing all Projects (`!all`, `dashboard.tsx:205`). It stays unchanged: the Dashboard renders no Monaco editor or terminal, and it and the Project view are alternative renders of `workspace-view.tsx` (`:179-195` renders the Dashboard on `/` and `/projects` only), so the two listeners are never mounted together.
- **S14 — ◆ write paths.** File creation goes through `files/v1@1.2.0`; Discard through `git.commands/v1@1.1.0`; terminal Rename through `terminal/v1@1.2.0` ([4.4](#44--actions)). The user approved file creation and Discard under HC-007 (UR15).
- **S15 — Viewer tab menus and titles.** `layout.tabs/v1@1.2.0` adds three things. (1) An optional `menu` on `TabRequest`: `readonly { id: string; label: string; destructive?: boolean; run: () => void }[]`, validated in `tabRequestSchema` (`bundles/desktop/layout/src/contracts/index.ts:67-77`) with `run` as `z.custom<() => void>((value) => typeof value === 'function')`, as chat's contract validates a function (`bundles/desktop/chat/src/contracts/index.ts:621`). (2) `retitle(input: { id: string; title: string; threadId?: string }): Promise<void>`, input `z.object({ id: z.string().min(1), title: z.string(), threadId: z.string().optional() }).strict()`, output `z.void()`: it sets the title of the tab with that id among that owner's tabs (the active owner without `threadId`, as `close` resolves it) through a new `retitle(threadId, id, title)` action of `bundles/desktop/layout/src/client/stores/workspace-tabs.ts` (beside `select`, `:45`); without such a tab it does nothing. It exists because `open` with an existing id only selects the tab (`bundles/desktop/layout/src/client/services/layout-tabs.ts:72-75`). (3) Every viewer tab gets a context menu: the tab's `menu` items, a separator when there are any, then "Close tab"; a tab without `menu` shows only "Close tab" ([4.4](#44--actions)). Because the schema is `.strict()`, a layout older than 1.2.0 rejects an `open` carrying `menu`, so the `files`, `git` and `terminal` manifests raise their requirement to `layout.tabs/v1@^1.2.0` in 4.4 (today `^1.1.0`: `bundles/features/files/manifest.json:24`, `bundles/features/git/manifest.json:24`, `bundles/features/terminal/manifest.json:20`); the composition then refuses the skew instead of failing at the first `open`.
- **S16 — Reveal in Files is internal to the `files` bundle.** The File tab's menu entry is a closure the `files` bundle builds when it opens the tab (`bundles/features/files/src/client/commands.ts:28-42`); no command or contract is added. It shows the Files panel (`layout.panel/v1.show('files')`) and expands the file's ancestor directories through a new `expand(scope, paths)` action of `bundles/features/files/src/client/stores/expansion.ts` (beside `toggle`, `:11-25`). The tree already selects the current tab's file (`bundles/features/files/src/client/tree/files-tree.tsx:86-90`).
- **S17 — Withdrawn** with the Project "Copy path" (UR13).
- **S18 — Discard confirmation.** The `git` bundle composes `desktop/ui/alert-dialog` directly in a new `bundles/features/git/src/client/changes/discard-dialog.tsx`, as the `mcp` bundle composes its confirmation (`bundles/features/mcp/src/client/elements.tsx:16-24`). `DeleteDialog` stays where it is.
- **S19 — The splash art shader (UR17, UR19, UR22).** The art is Figma's shader effect "Bitmap orgânico" run live with WebGPU on the photograph S33 picks. It is the file shader `071018be-b00a-4c0a-83da-1729a60fc95b`, version `2d24f46323ce8a35993d022830f285c2421814f6` (manifest `version: 3`, `isAnimated: false`, `renderScaleAware: true`), owned by the user and copied under MIT (UR19). On layer `302:22443` it runs with these parameters (read with `get_design_context` on `302:22439`):
  - `Tamanho: 5` — the dot grid spacing in px (range 4–100);
  - `Densidade: 5` — a tone offset added before the dots are sized (−50–50);
  - `Contraste: 75` — the tone contrast in % (25–250);

#### Code: Discard on the host

In `bundles/features/git/src/host/service.ts`, `discard` runs inside `workspace.withThread(threadId, { exclusive: true }, …)`, the Project mutation lock that `switchBranch` holds (`:179-186`). In order, the first failing step answers and nothing is written:

1. **Stale working directory.** `cwd !== thread.cwd` → `refused`, "The working directory changed. Reopen the Changes view and try again."
2. **Repository.** `repository` has no NUL, does not start with `/` and has no `..` segment (`''` names the sandbox root); it must then be one of the repositories `readProjectChanges(thread.sandbox, scope)` lists, where `scope = workspacePath(thread.cwd)` (`bundles/features/files/src/contracts/reads.ts:17`, the scope the Changes view reads with, `bundles/features/git/src/client/changes/store.ts:82-83`, `:163-167`). Else `refused`, "\<repository> is not a repository of this working directory." The paths are not checked here: step 4 accepts only exact matches of the read's changes, which excludes NUL, absolute paths and `..`.
3. **Running work.** `busyPaths(thread, terminals, call)` (`service.ts:56-72`) lists the working directories with running work in the Project. Each, made sandbox-relative, blocks when it lies inside the repository or contains it (`under(busy, repository) || under(repository, busy)`). `under` is module-private in `changes.ts:116-117`; it becomes `export const under`, and `service.ts` imports it. A blocked call answers `refused`, "Wait for active prompts and terminal commands in this repository to finish before discarding changes." This covers work in the repository, in a repository nested in it, and in a directory above it that can write into it.
4. **Targets.** Without `paths`, every change the read lists for the repository, except the nested repositories below. With `paths`, each must be the `path` of a listed change; else `refused`, "\<path> has no change to discard." So an unchanged file, an ignored file (for example `.env`; `git status` does not list ignored files), a path that never existed, an absolute path, a path with `..` and a path under a symlinked directory (Git lists the symlink, not paths under it) are refused, not touched.
   - **Nested repositories.** A target is another repository when `workspacePathKind(sandbox, join(repository, path, '.git'))` is not `missing` (a `.git` directory, or the `.git` file of a submodule). The read lists such a path as untracked `sub/` (a repository inside another, which `git status --untracked-files=all`, `changes.ts:178-194`, does not enter) or as a modified submodule. Discard never changes another repository: with `paths`, such a target answers `refused`, "\<path> is a separate repository. Discard does not change it."; without `paths`, it is left out of the targets and stays listed.
5. **Conflicts.** Any target with status `conflicted` → `refused`, "\<path> has a merge conflict. Resolve it before discarding."
6. **Discard**, one target at a time, with `sandbox.exec({ cmd: ['git', '-C', root, …] })` at the repository root, as `projectChanges` runs `git status` (`changes.ts:85-89`). The command follows the target's two status letters (`indexStatus`, `worktreeStatus`, `bundles/features/git/src/host/changes.ts:171-172`), not its `status`, which reads `AD` as `deleted` (it tests `D` before `A`, `:160-163`) and a copy `C` as `renamed` (`:150`):
   - `??` (untracked): `clean --force --quiet -- <path>`. After step 4 every untracked target is a file: `--untracked-files=all` lists the files inside untracked directories, and the only directories it lists are nested repositories. Without `-x`, `clean` never removes an ignored file;
   - every other code: `restore --source=HEAD --staged --worktree -- <path>`, plus `<originalPath>` when the change has one (`R`, `C`). Git removes from the index and the working tree a path that `HEAD` does not have, so this one command also discards `A`, `AM` and `AD` (git 2.39: each exits 0 and leaves no change), restores a rename's origin and removes its destination; a copy's origin is unchanged, so restoring it changes nothing.
   - **A repository without a commit.** There `restore --source=HEAD` exits 128 with "fatal: could not resolve HEAD" (git 2.39.5). So before the loop the host runs `rev-parse --verify --quiet HEAD`; when it exits non-zero, every target other than `??` is discarded with `rm --force --quiet -- <path>` instead, which removes it from the index and the working tree (git 2.39.5: `A`, `AM` and `AD` each leave no change). Without `HEAD`, Git reports no rename or copy, so no `<originalPath>` arises; `??` targets still use `clean`.

   A command that exits non-zero stops the loop. Then the host reads the repository's changes again; `discarded` is the targets that read no longer lists, so it never names a path Git left in place.
   - Every command succeeded and no target is still listed → `{ status: 'ready', value: { discarded } }`.
   - A command failed → `{ status: 'failed', message: <its first stderr line>, discarded }`.
   - Every command succeeded but a target is still listed → `{ status: 'failed', message: "\<path> still has changes after Discard." (the first such target), discarded }`.

## 1:1 verification

"1:1" passes when the checks below pass. Each phase section names the nodes and lists its expected differences; an unlisted difference fails the check.

- **Values.** For each Figma node of the check, `get_design_context` gives width, height, padding, gap, radius, border width and side, font size, line height, weight and color. Each is compared with the rendered element's computed style (`getComputedStyle` in its story or in doric-e2e). Padding, gap, radius, border, font size, line height and weight must be equal; a box's width and height may differ by at most 1 px (Figma states fractional sizes); a color must resolve to the token Figma's variable names, or to the same hex where Figma states a literal. The phase's pull request records one row per node and property: Figma value, rendered value, pass.
- **Text.** Labels use the fixture's longest names. A label wider than its Figma box truncates with an ellipsis; it does not wrap or overflow its container (SR5).
- **Pictures.** `get_screenshot` of each node beside the rendered story or capture, light and dark, for what the values do not state (icons, alignment, composition). The user accepts each phase on these images; there is no pixel-diff gate.
- **Component check**: the values, text and pictures of each node, rendered in its story through papercraft's preview.
- **Shell check**: the same on doric-e2e captures through `doric.windows/v1.capture` at 1920×1080.
- **Splash check**: the same on doric-e2e captures of the splash window (`platform.splashWindow.webContents.capturePage()`, the harness exposes it at `app/desktop/doric-e2e/tests/splash.test.ts:20-27`).
- **Tokens**: T-1.1. **Light during phases 1–3**: S30.

- **A static export of the shaded art** (version 1). Rejected by UR17: the shader runs live. The export stays only as the fallback (S32).
- **`Sidebar variant="inset"` with `SidebarInset`'s peer styling** (versions 1–4). Rejected: the styling needs the card as a sibling of a `Sidebar` that is not `collapsible="none"`, which is `fixed` and `h-svh` (S34).
- **Renaming the platform folders with each `PLATFORM_VERSION`** (version 5). Rejected: about 30 places hard-code `1.0.0` in the folder paths and URLs, among them the splash page's stylesheet and the renderer's public path; a separate `PLATFORM_ASSETS_VERSION` keeps them valid (S35).
- **The connection status as a 10×10 dot** (P19, versions 1–5). Replaced by UR24: the prototype's cloud glyphs (2.7).

Rejected: the splash shades an image, not DOM, so `copyExternalImageToTexture` gives the shader its input, and the module's `render` runs unchanged and calls its own `setup` on the first frame ([4.5](#45-splash)).

## Risks

- **SR1 — The hover rule.** S4's thresholds hold for today's palette (1.105:1 and 1.193:1 against rest). A later palette that falls under them fails T-1.3, which is the intent.
- **SR2 — Removing `layout.global-footer`.** A bundle outside this repository that registers into it would draw nothing. Every first-party user moves in phase 2; no external bundles exist (`docs/architecture/bundles/implementation-decisions.md:174`).
- **SR3 — Layout test churn.** Phase 2 rewrites tests that pin the old structure (concept R2); T-2.9 lists the behaviors that must still pass.
- **SR4 — Discard cannot be undone. Accepted (UR21).** Deleting untracked files and resetting edits loses work. The user accepts it because the reader sees the change in the Changes tree before choosing it, the confirmation names the target and says it cannot be undone, the call is refused while work runs in or around the repository, and ignored files, nested repositories and paths outside the change set are never touched ([4.4](#44--actions)).
- **SR5 — Font metrics.** Noto Sans first changes text widths everywhere; the text rule of [1:1 verification](#11-verification) covers truncation.
- **SR6 — Withdrawn** (UR18).
- **SR7 — Collapsed Files column crowding.** With the column collapsed, the tab bar's right end holds `layout.header`, FilesToggle and the account status; a narrow window truncates Project tabs first, as today.
- **SR8 — `app.getVersion()` in development.** It reads the built `dist/app/desktop/doric/package.json` (`0.0.1`); T-2.10 asserts the value equals `app.getVersion()`, not a literal (UR16).
- **SR9 — WebGPU in the splash. Accepted with the live path (UR22).** Electron 44.4.3 (`package.json:51`) ships Chromium's WebGPU, but an adapter can be missing or hang (GPU blocklist, virtual machines, CI runners). Mitigation: the 1000 ms limit, the destroyed late device, the redraw on a device-pixel-ratio change and the shaded export on any failure (S32); T-4.5.5, T-4.5.7.
- **SR10 — Withdrawn** (network request, UR18).
- **SR11 — Withdrawn** (third-party content, UR18).
- **SR12 — WebGPU work at startup. Accepted with the live path (UR22).** The page creates a WebGPU adapter and device, compiles the shader and decodes a 746×1078 photograph while the workspace window boots, and competes with it for CPU and GPU time. Bound: T-4.5.8, the median boot with the shader at most 150 ms above the median boot with the shaded image, measured in one build on the reference Mac; above it, 4.5 does not land until the cause is found.
- **SR13 — Region moves across versions. Accepted.** A manifest requires contracts, not regions (`bundles/features/resources/manifest.json:8-13`), so `resources` 1.1.0 (into `layout.account.status`) or `git` 1.2.0 (into `layout.panel.footer`) composed with a layout older than 1.4.0 registers into a region nothing draws, and the item is missing without an error. Tying the moves to a layout contract minor would add a version that carries no method. Phase 2 ships the three bundles in one change, and T-2.3 and T-2.5 show both items in place.
- **SR14 — Version skew between the app and its bundles.** The bundles come from the host and may be newer or older than the app (UR25). Failure modes and their handling: a chat or layout bundle of phase 1 or later on an app before 1.1.0 is refused (`engines_unsatisfied`) and the splash shows its bundle-failure state with its recovery actions (`app/desktop/doric/src/platform/splash/protocol.ts:17-57`); every other newer bundle loads and hides what the app cannot answer, by phase: the version in the account menu before 1.2.0, Appearance before 1.3.0, Back/Forward before 1.4.0, A5–A11 before 1.5.0; a newer bundle draws the older app's shared components and token values, so the 1:1 checks hold only when the app and the bundles are of one phase; an older core loads on an app of 1.4.0 or later because `forward` and `history` are optional. Mitigation: each degrade path has a test (T-2.15, T-4.1.12, T-4.2.10–T-4.2.12, T-4.4.16), and a gap that would fail a module at link time raises `engines.doric` instead, so no window opens that fails on a missing import or a missing platform contract.
