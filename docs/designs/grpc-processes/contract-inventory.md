## B. The public API: REST and Socket.IO to gRPC

The routes are the host README's [Routes](../../../app/backend/doric-host/README.md#routes) table (`app/backend/doric-host/README.md:1099-1200`) and its [Socket.IO](../../../app/backend/doric-host/README.md#socketio) section (`:1917-2136`); the routers are mounted at `bundles/foundation/transport/src/host/app.ts:19-35`. Each route becomes one RPC of one service of the proto package `doric.api.<resource>.v1`, the package of the contract `api.<resource>/v1` (A60): `api.config/v1`, `api.credentials/v1`, `api.providers/v1`, `api.host/v1`, `api.projects/v1`, `api.threads/v1`, `api.terminals/v1` and `api.status/v1`, each with cardinality `ONE` and environment `HOST`, which `transport` provides from phase 3 ([Public API](../grpc-processes.md#12-public-api)). T1.4 checks every row below against the image. A path parameter becomes a request field of the same name in snake case (`:id` is `project_id`, `thread_id`, `credential_id`, `terminal_id` or `vm_id`, by resource; `:promptId` is `prompt_id`); the JSON body becomes the other request fields with the same names; the JSON answer becomes the response message. An RPC `X` takes `XRequest` and answers `XResponse`, and a `Watch` answers a stream of `WatchResponse` items (A49). Every request and response message keeps today's JSON field names as the `json_name` of its fields, so a request sends today's fields. A body is the JSON of the RPC's `.proto` message (D8), which differs from today's body where the message nests its value: `GET /config` answers `{ "doricConfiguration": { … } }`, and a 202 answer is the `pending` case of the response's `oneof result` (coordinator decision, version 6.7; [section 12](../grpc-processes.md#12-public-api), "Bodies and statuses").

**The streams.** A Socket.IO subscription becomes the request of `Watch`; today's handshake `auth` fields (`app/backend/doric-host-e2e/tests/integration.test.ts:98-107` builds them) become the request fields. Each emitted event becomes one response item, a message with a `oneof event` whose case names the Socket.IO event (`thread:snapshot` is `thread_snapshot`, `agent:event` is `agent_event`, `terminal:output` is `terminal_output`: the twelve events of the README's table, `app/backend/doric-host/README.md:1962-1976`, are `thread:snapshot`, `agent:event`, `thread:updated`, `thread:deleted`, `project:snapshot`, `project:updated`, `project:deleted`, `terminal:snapshot`, `terminal:updated`, `terminal:output`, `terminal:removed` and `workspace:error`; each case is the event's name with `:` replaced by `_`, and `workspace:error` has none: a snapshot read that fails ends the stream with `INTERNAL`, reason `replay_failed`). `api.projects/v1` declares its own `ProjectSnapshot`, which holds the Project's terminal sessions. `ReadFile` streams one `pending` item, or a `head` and then the text in `content` chunks; `ListEvents` answers `nextAfterSequence`. `thread_snapshot` follows the snapshot rule of row 42: its `events` stop before 3 MiB and the rest follow as `agent_event` items. A paged answer (`ListEvents`, `ListThreads`) ends its page before 3 MiB and sets its next cursor. A disconnection the server makes today (for example a failed `/projects` snapshot without `terminal/v1`, `docs/features/host-api.md` "Decisions") ends the stream with the status that maps the same error. `status.v1.StatusService.Watch` sends one item `{ ready: {} }` and stays open; it is the liveness signal `/status` gives today by connecting (`bundles/foundation/transport/src/host/sockets/status.ts:4`).

**Statuses.** A REST refusal `{ error: { code, message } }` (`bundles/foundation/transport/src/host/errors.ts`) becomes a gRPC status whose `google.rpc.ErrorInfo` has `reason` = the same `code` and `domain` = `doric`, with this code:

| HTTP today             | gRPC status code                                                                               |
| ---------------------- | ---------------------------------------------------------------------------------------------- |
| 400, 422               | `INVALID_ARGUMENT`                                                                             |
| 404                    | `NOT_FOUND`                                                                                    |
| 409                    | `FAILED_PRECONDITION`                                                                          |
| 202 with `Retry-After` | `OK`; the response's `oneof result` holds `pending { retryAfterSeconds }` instead of the value |
| 500 `internal_error`   | `INTERNAL`, message `The request could not be completed.`, no cause, as today                  |
| 503                    | `UNAVAILABLE`                                                                                  |
| 410                    | `FAILED_PRECONDITION` (`project_files_expired`, `project_ssh_expired`)                         |
| 502                    | `UNAVAILABLE` (`model_catalog_unreadable`, `compaction_failed`)                                |

Two refusals take the code of the shared table (`packages/bundle/src/contracts/status.ts`), not the row of their HTTP status (coordinator decision Q2 of S60; proto comments in slice S62b3):

- `credential_name_taken`, a 409 today, answers `ALREADY_EXISTS` (`api.credentials/v1`).
- The queued edit's outcome `invalid_prompt`, a 409 today, answers `INVALID_ARGUMENT` (`api.threads/v1`).

Every other HTTP status the routes answer today maps by the table of `google.rpc.Code` ("HTTP Mapping"), and the implementation adds a row here before it uses one. A request that breaks a protovalidate rule answers `INVALID_ARGUMENT` with the reason the route answers today for the same input: the route's reason for a path parameter (`invalid_project_id`) when the violation is on that field, and its reason for the body or query (`invalid_page`, `invalid_prompt`) otherwise. The body-size refusal of the JSON parser (100 KB, `docs/features/host-api.md:34`) stays for Connect JSON requests: the gateway answers a JSON request message over 102,400 bytes with `RESOURCE_EXHAUSTED`, reason `limit_exceeded`, before it transcodes it; a binary message keeps the 4 MiB limit ([section 11](../grpc-processes.md#11-gateway-and-public-listener)).
